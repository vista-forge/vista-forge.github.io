M in ten minutes

For developers who know another language and have just opened HELLO.m. Every construct below is tied to a line you can see in the box, and every claim was run on the box's engine. Read it once; keep the table at the end.

A routine is a file

Section titled “A routine is a file”

src/HELLO.m is a routine named HELLO. The file name, the first word of the file, and the name you call it by are the same. A routine is a list of labels; each label starts a block of lines. Running a routine means starting at its first label:

HELLO is the label. ; starts a comment. write prints. quit ends the block. Run Code in the IDE runs do ^HELLO: do the routine HELLO from its top.

Whitespace is syntax

Section titled “Whitespace is syntax”

A label starts in column one. Every command line is indented (a tab or spaces — this box uses spaces and m fmt keeps them uniform). A command and its arguments are separated by one space; two commands on one line are separated by one space too. That is why an M line reads write "a",! quit and why a stray leading space on a label line is an error. m fmt fixes indentation; m lint tells you about the rest.

Commands, and their one-letter forms

Section titled “Commands, and their one-letter forms”

Standard M has 26 commands. You will use these:

Command Short What it does You will see it as
write w print write "Hello",! — ! is a newline
set s assign set total=total+1
do d call a procedure (no return value) do start^STDASSERT(.pass,.fail)
quit q leave the block; with a value, return it quit 0 · quit "text"
if i condition for the rest of the line if n<0 quit 0
else e the opposite of the last if on the line above
for f loop for i=1:1:n write i,!
new n make a local variable private to this block new pass,fail
kill k delete a variable or a subtree kill ^DEMO
merge m copy a whole subtree merge out=in("rows")

The box's lint profile (modern) wants the full lower-case word; the one-letter forms are what you will see in older M code and in /opt/msl/src, where both are legal.

Values: everything is a string

Section titled “Values: everything is a string”

There are no types. A value is a string; it is used as a number when an operator needs a number, by reading digits from the left:

Strings concatenate with _: "Hello, "_name_"!". Compare strings with = (exact) and ] (follows, i.e. sorts after): "b"]"a" is 1. Compare numbers with < and >. "10">"9" is 1 because both sides read as numbers — see the sixth trap below.

Operators: no precedence

Section titled “Operators: no precedence”

M has no operator precedence. An expression is evaluated strictly left to right, and parentheses are the only way to change that:

Arithmetic: + - * /, \ (integer divide), # (modulo), ** (power): 7/2 is 3.5, 7\2 is 3, 7#2 is 1. Boolean: &, ! (or), ' (not), and ' before a comparison negates it: '= is not-equal, '> is not-greater, which is how you write <=.

Calling things

Section titled “Calling things”

Two kinds of call, one naming scheme:

You want Write Example from the box
a value back (a function) $$label^ROUTINE(args) $$toUpperASCII^STDSTR("world")
the work done (a procedure) do label^ROUTINE(args) do report^STDASSERT(pass,fail)
a label in the same routine drop ^ROUTINE do tour · $$greet(name)
the routine from its top do ^ROUTINE what Run Code does

A label that takes parameters declares them: greet(name). Parameters are passed by value; a leading . passes by reference so the callee can change it: do start^STDASSERT(.pass,.fail) lets STDASSERT count into your pass and fail. A subscripted node cannot be passed by reference — merge it into a plain variable first.

There is no import. The standard library is installed on the engine, so $$…^STDSTR works from the first line of any routine.

Variables, arrays, and the database

Section titled “Variables, arrays, and the database”

A local variable lives for the process: set name="world". Every variable is also a sparse, ordered, multi-level array: set x(1)="one", set x("a","b")=2. Subscripts are strings or numbers and sort in a defined order (numbers first, then strings). new pass,fail makes those names private to the current block so a callee cannot clobber them; a routine that forgets new leaks variables to its callers, which is why every label in the box's code starts with one.

A global is the same thing with a ^ in front, and it lives in the database, shared by every process and persistent until killed:

That is the whole of "M is a database": there is no separate query language; globals are the tables. In this box the database is empty when the container starts and forgotten when it stops, unless you mount a volume (the Install, run, stop page).

The intrinsic functions you meet first

Section titled “The intrinsic functions you meet first”

All start with $; the standard library adds the rest under $$.

Function Does Example
$length(s) length $length("hello") → 5
$piece(s,d,n) the n-th delimited field $piece("a,b,c",",",2) → b
$extract(s,from,to) substring by position (1-based) $extract("hello",2,3) → el
$get(v) the value, or "" if undefined — no error $get(x("missing")) → ""
$data(v) 0 undefined, 1 has a value, 10 has children, 11 both
$order(x(k)) the next subscript after k; "" at the end $order(x("")) → the first
$select(c1:v1,c2:v2,…) the first value whose condition is true $select(n<0:"neg",1:"pos")
$horolog today and now as days,seconds STDDATE turns it into ISO 8601

$order is how you walk any array or global: set k="" for set k=$order(x(k)) quit:k="" write k,!.

Errors

Section titled “Errors”

An error sets $ECODE and unwinds until something handles it. The standard library raises its own codes (U-STD…, all listed in /opt/msl/skill/error-codes.md), and a test asserts that a call raises with raises^STDASSERT. In your own code, set $ecode=",U-MYAPP-BAD-INPUT," raises; $etrap names the code that runs when one happens. You will not need any of this for the first hour; the library and the test helpers handle the common cases.

A test suite, line by line

Section titled “A test suite, line by line”

tests/DEMOTST.m from the hello example, abridged:

A suite is a routine whose name ends in TST; each test is a label named t… with a ;@TEST "…" description; eq, true, raises and the other helpers in STDASSERT do the assertions; report prints the count. m test tests runs every suite in the folder and prints verdict green or the failing assertions. m new NAME writes a suite in this shape with one failing test, which is where you start.

The style this box lints for

Section titled “The style this box lints for”

Lower-case full-word commands (write, not W), lower-case local variables, upper-case routine names, a few commands per line at most, new for every local a label uses. m lint --error-on=error reports departures; m fmt repairs the mechanical ones. The rules are the modern profile in .m-cli.toml, and they are also what the standard library is written in, so reading /opt/msl/src/STDSTR.m shows you the house style on real code.

Six things that cost an hour each

Section titled “Six things that cost an hour each”
  1. <= does not exist. Write '>; >= is '<.
  2. No precedence. 1+2*3 is 9. Parenthesise.
  3. A counted for leaves its variable at the last value, not one past it; use a found flag rather than testing i>n afterwards.
  4. < on two ISO timestamps compares the leading number (the year). Compare strings with ] (follows), or use STDDATE.
  5. A subscripted node cannot be passed by reference. merge it into a plain local first.
  6. A $etrap that stores into a local can be shadowed by a deeper frame's parameter of the same name; give the error variable a distinctive name.
