Start here

Welcome to m-devbox, a complete M/MUMPS development environment. You are looking at a real engine, a real database, a working toolchain, eleven worked examples, the standard library with its documentation, and an AI coding assistant — nothing to install. This page is the map.

M is one of the oldest languages still doing serious work, and its age is a virtue: for forty years it has handled the most life-, health- and money-sensitive transactions there are, running a large share of the world's hospitals and core-banking systems, and it is still doing so today.

Its reputation for difficulty to learn is ill-deserved. The language has only 26 commands — far fewer than today's "modern" languages — and the database is built-in, so there is no additional language or technology to learn for data-based applications. What has been hard is getting the environment - an engine, a database, a toolchain, a library - all set up and agreeing with each other. This image is that environment, ready in a minute.

Use your AI assistant

Section titled “Use your AI assistant”

You already use one. It works here in a few minutes with the credentials you already have, and the box makes it good at M from the first task:

  1. Cline is installed in this IDE — the robot icon in the left bar. Click it, choose your provider, paste your key. It already knows the rules of this box.

  2. Or use the assistant you have on your machine — Claude Code, Codex, Cursor, Copilot, Gemini CLI, Aider. Start the box from your project directory, install a ten-line shim so m runs inside the box from your host, and drop the box's contract file into the project:

  3. Give it the first task — add a greet label to HELLO.m, test-first — and watch it run m test --expect-red, implement, run m test, and lint.

Every step, for every assistant, with what you should see at each one: USE-YOUR-AI.md in this folder (the manual page Use your AI assistant). What the assistant reads: AGENTS.md, beside it.

Four things to try by hand

Section titled “Four things to try by hand”

The terminal is Ctrl+` (or Terminal → New Terminal in the menu).

  1. Run a program. Open examples → hello/src/HELLO.m in the file tree, and press the Run Code button (▷, top right). The output panel shows the routine running on the engine.
  2. Run the tests. In the terminal: m test /opt/examples/hello/tests — a real suite, with assertion counts.
  3. Change something. The examples are read-only teaching copies; to edit one, copy it into your folder first — cp -r /opt/examples/hello /work/hello — then open work/hello/src/HELLO.m, change the greeting, and Run Code again. (Run Code runs the file you have open; m test runs the folder you name.)
  4. Copy the example nearest your problem. examples/README.md lists eleven worked examples — a command-line tool, a CSV report, configuration, an HTTP client, a clinical XML document, tokens, an inventory, and the TDD kata that shows how each was built — every one with a README, working source and a green suite.

When something refuses

Section titled “When something refuses”

The tools here prefer a loud, specific refusal over a silent wrong answer. Read the message — it usually names the fix. The linter behind the editor squiggles is m lint; the test runner is m test; both work identically from the terminal. The engine is single-writer: a command refused with a run-lock message means something else held the engine for a moment — run it again.
