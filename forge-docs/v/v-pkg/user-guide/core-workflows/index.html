Core workflows

Build, preview, install

Section titled “Build, preview, install”

install refuses (exit 4) to clobber an existing national routine or a live component record (a shipped SEND entry purges any existing version; a DELETE-AT-SITE entry removes one) unless you give it --auto-snapshot/--snapshot <out> (the safe path — enables a later restore) or --allow-overwrite (explicit, no pre-image). The pre-image sidecar embeds the overwritten/deleted component records VERBATIM alongside the routine sources, so restore stays a plain install-of-the-pre-image. A component name that is ambiguous on the live engine (multiple same-named records) refuses AMBIGUOUS_COMPONENT rather than guessing. Other useful install flags: --register-package "NAME" (stamp the #9.4 footprint so $$PATCH^XPDUTL is honest), --heal (purge a corrupt half-install first), --verify-checksums (hard checksum gate), --answer NAME=VALUE (pre-answer an install question). A bare install previews and stops (same plan as diff); only --commit actuates.

Back-out

Section titled “Back-out”

The right back-out depends on the build's reversibility class, which uninstall decides from the .KID:

With a pre-image in play, the back-out is partitioned and restore-first: records the pre-image captured (overwritten or deleted at install) are re-filed by the pre-image install, and only the greenfield adds — routines and component records the site never had — are deleted afterwards. The report itemizes restoredComponents / deletedComponents.

--force overrides a refusal (deletes routines anyway, leaving any declared-foreign overwrite in place rather than bricking it) — use it only when you accept that install-time data/side-effects will be orphaned. Even under --force, records the attestation ledger says the install overwrote are NEVER deleted (protectedComponents) — with no pre-image to restore them, deleting would brick what nothing can put back. Symmetrically, an uninstall with a wrong or stale sidecar (one missing a routine or component the ledger/declaration says was overwritten) is refused instead of partitioned.

Delete-at-site

Section titled “Delete-at-site”

Real national patches ship DELETE-AT-SITE entries (#9.68 ACTION 1 — 877 records across the corpus): install deletes the named live record. v-pkg handles the whole arc:

The same closed loop covers overwritten components: the site's original OPTION / template / RPC / bulletin / etc. comes back after uninstall (template-family records byte-identical; XPDIA entry classes content-surface exact — FileMan re-stamps its bookkeeping pieces). Proven end-to-end by make preimage-gate (35/35 on both engines).
