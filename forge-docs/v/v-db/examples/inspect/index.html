integrity

Section titled “integrity”

Executed 2026-08-20 at v0.7.1-122-g522929b against vehu, after the instance-integrity effort landed (VSL*1.0*75 + MSL*0.1*2). This is the bounded form: --to 2 restricts every walk to file numbers ≤ 2, which is a dev/smoke run and not the instance audit. The whole-instance run is ≈ 8.3 min on vehu; this one is seconds.

Exit status 0.

Four things in that output are the contract, and each is a rule the census holds everywhere:

  • Every class carries its own denominator, and a zero is printed. 0 key-duplicate is a measured zero, not an absent measurement — the two must never share a rendering, so the class list prints the zeros rather than omitting them.
  • The unmeasurable share is stated out loud, in the same breath as the coverage. 23 of 115 stored index subtrees (20.0 %) cannot be interpreted from the registers, and the line says so rather than reporting 92 as though it were the whole plane. A quarter of a plane is not a corner case.
  • The excluded pair is named, not silently skipped. The two audit-class files store per-FILE subtrees at the first subscript, so a bare walk would read subtree headers as records; they are excluded from every record walk and counted by name.
  • The note pins the vocabulary. red belongs to the comparison (integrity-compare), never to this census — an absolute count never sets a failing exit, because a stock release build is not self-consistent in any class.

The same run, writing the committed-artifact form:

Exit status 3.

⚠️ The exit differs between the two blocks above, and that is the convention, not an inconsistency. A bounded console view exits 0; a bounded artifact exits 3. The artifact is a durable claim about what was covered, so writing an incomplete one is a gate failure the caller must acknowledge; a console view claims nothing beyond the screen. Verified the same day to be verb-wide and not special to integrity: census --file 2 --one-page exits 0 without --out and 3 with it. The rows that were written are valid either way — the manifest names every reason.

integrity-compare

Section titled “integrity-compare”

Executed 2026-08-20, offline, against the committed baselines of record in baselines/integrity/. The verb speaks exactly four words and each has one meaning; all four are shown here.

clean — row-identical to the named base.

Exit status 0. Note that the expectation's own identity — engine, station, build, timestamp, digest and row count — is printed beside the verdict. A verdict without the identity of what it was measured against is not a verdict.

attention — one-sided excess against the shipped-state ledger, never red.

Exit status 0 — deliberately. The ledger is the intersection of two release builds, so it is a floor on what ships that way, never a target. An instance's own standing damage is excess against it, and reporting that as a regression would make the first baseline swallow it forever.

stopped — no verdict, because the input could not be certified against.

Exit status 3. stopped is a distinct word from clean because a run that ran out of scope is not a run that found nothing — collapsing the two is how a bounded smoke run gets mistaken for a passing audit.

delta — any row difference against the named base. The audit's only red. It is not reproducible from committed inputs alone (both baselines are, by construction, identical to themselves), so it is demonstrated by the red-proof harness, which plants one changed byte in a copy of a real baseline and reseals the manifest so the checksum door stays armed:

"Fired alone" is the assertion that matters. A vocabulary of four words is only worth having if each one excludes the others — P1 checks that a delta reds without dragging attention with it, and P3 checks that the typed code is STOPPED and not DELTA.

integrity-report

Section titled “integrity-report”

Executed 2026-08-20 against the committed vehu baseline. The census says which source files hold dangling pointers; this says what is wrong with the thing they point at.

Summary of the run (the full output lists every target):
targets reported 106
header-divergent (the mechanism class) 34
healthy targets — the worth-eyes class 64
roots that resolve to no file 8

The largest single finding, verbatim from the target's own record:

That is the whole argument for the verb in one record. Twenty-one distinct source files hold 425,874 dangling references into ^ICPT(. Reported per source, that is twenty-one findings and a reader with no idea where to start. Reported per target, it is one fact — the file's own header claims 26,877 records where 2,351 were walked — and the sources become evidence for it rather than defects of their own.

Three properties of the report worth naming:

  • The root→file resolution is asked of the LIVE engine, one dispatch per distinct root, memoized — so unclaimed and ambiguous roots are carried as named states rather than guessed from the artifact.
  • The same-place door. The live engine must declare the same instance the artifact measured, or the report refuses: joining one site's artifact to another site's dictionary would silently answer a different question.
  • An empty target explains its own inbound mass too. A target holding no records at all (claim=0, walked 0) is in the mechanism class for the same reason a header-divergent one is — which is why the class has more than one arm, and why the arms were added only after a live run produced a target the first rule mis-filed.

bundle

Section titled “bundle”

Executed 2026-08-23 at v0.7.1-150-g675a065 against vehu, through v db bundle — the run-set orchestrator that replaced scripts/dd-bundle.sh when VD-D95 retired it, with per-component certification (VD-D121, the S2 increment) and drift certified against the previous day's bundle via --base. The earlier transcript here drove that script; it was replaced rather than kept, because an example that tells a reader to run a deleted file is a dangling artifact.

A bundle is an assembly of existing artifacts, not one bigger file (VD-D84). What it exports is a run set: a committed TOML declaration, one entry per component, each a verb plus its argv with a group and a sentence saying why it is in the bundle.

Ask it what it exports first. This reaches no engine and writes nothing, and it is where a misspelled flag is caught — resolution runs against the tool's own generated contract before any engine work:

Then the run. It holds the engine run-lock for the sum of its components, so a busy lock refuses before the first sweep:

Started 2026-08-24T02:56:40Z, finished 03:33:31Z. export and refs dominate the cost — the components after them are seconds each, certification included.

certified is VD-D121 running as each component lands — never as a final sweep. Five layers in order, first red stops: an independent re-read and re-hash (the certifier's own file handle, hash and line count — nothing shared with the writer); every record's keys against the schema generated from the tool's own serialising types, shipped in the bundle as schema.json; the manifest's complete claim re-derived plus the page evidence's own arithmetic; per-key density recorded as counts over denominators; and drift against the bundle --base names — this run measured every component against the previous day's, zero collapses, zero drops. The full five-layer record rides beside each component as certification.json; a run without --base records drift as unmeasured, by name.

Had any layer refused, the run would have stopped at that component: nothing after it dispatched (stopped.notDispatched names them), every component already on disk marked refused (refused.json), exit 3 COMPONENT_REFUSED naming the component and the check.

Each component lands in its own directory with the manifest that verb writes on its own. Beside them, bundle.json records per component its argv, exit, duration, projection tier, both digests, its declared instance and its certification verdict:

— and set.toml, the set that produced the bundle, byte-identical and digested, so a bundle read a year later can be checked against what asked for it rather than against a file that stayed behind:

The bundle checks itself against its own set, in both directions (VD-D94), and publishes the result whether or not it found anything — an empty finding list is a measurement:

missing is a declared component that landed no complete artifact; unasked is a directory no component asked for — the direction nothing used to check, which catches a leftover from an earlier, larger set reading as part of this one; more than one entry in instances is a bundle assembled from two places. Any of them, or any failed component, exits 3 BUNDLE_INCOMPLETE.

What a replica should and should not match. The SHAPE reproduces exactly: 32 components, the tier pins, notRun: [fields-profile], complete: true, an empty reconciliation. The NUMBERS should not — timings move with the machine, and every digest changes the moment the dictionary or the data does. On another instance the record counts differ outright, which is what the manifests exist to say.

To export something the set excludes, add a component naming it — e.g. verb = "fields-profile", args = ["2"]. To take one plane instead of all of it, --group interop (repeatable); everything left out is named in notRun with its reason.
