v db indexes
Group Inspect
Engine access read
Mutates data no
Reversibility not applicable (does not mutate)
Exit classes 2 (usage error)

Synopsis

Section titled “Synopsis”

Arguments

Section titled “Arguments”
Argument Type Required Description
file float no FileMan file number, e.g. 44 for HOSPITAL LOCATION. Omit it and pass --all to sweep every file.

Flags

Section titled “Flags”
Flag Type Default Env Description
--engine string vehu V_ENGINE VistA engine profile to reach (vehu = YDB, foia = IRIS, local = in-image YDB).
--lock-wait duration 30s — How long to wait for the engine run-lock before refusing (0 = skip immediately when busy).
--timeout DURATION duration — — Host wall-clock bound on ONE engine visit; a hung page is aborted engine-side, not just abandoned. Unset = the verb's derived default (180s; a whole-instance sweep verb pins a slower one); negative = no bound (still reapable by hand).
--all bool — — Inventory EVERY top-level file in ONE engine-side pass (needs VSL1.061). Measured on vehu: 9,739 cross-references across 2,915 files in about two seconds — the per-file form costs 489 engine round trips for #2 alone. The key column is NOT measured at this scale and every row says so.
--kind string — — List only cross-references of this kind (the classifier's own word — regular, mumps, trigger, dangling, compound, record-level, and whatever else this instance carries). On one file this runs BEFORE the per-cross-reference probes, so a narrow list is a cheap one; under --all the engine has already measured every row, so it narrows the listing only.
--walkable bool — — List only the cross-references a seek accepts. The others are still readable — see 'find --raw' — they just cannot be positioned by key.
--key-sample N string — — How many stored entries to read per seekable cross-reference when measuring whether its key IS the indexed field's value (default 20; one file at a time only). 0 skips the measurement and every key cell says so. A larger sample raises the chance of catching a transform, and the length signals beside it catch the truncation a mismatch sample cannot.
--sample int — — --all only: stored entries sampled per cross-reference (engine default 20). The sweep's cost dial.
--page-size int — — --all only: rows per engine page (engine default 2000).
--token string — — --all only: resume a prior sweep from its opaque token, verbatim.
--one-page bool — — --all only: fetch one bounded page and stop (prints the resume token). Recorded as a NAMED incompleteness in a written artifact.
--pace duration — — --all only: politeness gap between the sweep's engine visits (e.g. 500ms) — host-side spacing for background runs.
--out string — — Write every row to this directory as indexes.jsonl + a manifest (consumer contract: docs/guides/indexes-jsonl-contract.md). On ONE file this is how --key-sample measurements are landed for --explain --indexes; under --all it lands the instance sweep.
--bytes string — — One file only: emission budget per probe page in envelope bytes (engine default 786432).
--examined string — — One file only: candidates-examined budget per probe page (engine default 75000).
--elapsed string — — One file only: engine-time budget per probe page in ms (engine default 10000).

Notes

Section titled “Notes”

Hand-written in the owning repository; the facts above are generated.

Which of this file's indexes can I actually look things up with? schema lists a file's cross-references. This measures them.

The gap between the two is not a detail. On vehu:

Five of #44's cross-references are registered only in FileMan's new-style INDEX file (#.11), which schema does not read. On #2 PATIENT the same gap is 384 → 485.

The columns

Section titled “The columns”
column what it measures
source which register declared the name — dd-ix (a traditional ^DD definition), index-file (a #.11 registration), or both
kind the shared classifier's word, the same one find dispatches on. The vocabulary is open: a kind this catalog has no rules for rides through by name, is counted, and nothing is derived from it (kwic on #8925.1 is the measured example)
Seek whether a seek is admitted. unmeasured is a real state — see below
Cond whether the registration carries a SET CONDITION. A conditional index holds a subset of the file
Stored whether a subtree named after it exists under this file's data root, on this instance
Shape the sampled subscript depth, then which positions hold a record number
Key whether the stored key is the indexed column's value, and the measured key length ceiling

walkable and stored differ

Section titled “walkable and stored differ”

A seek needs a mechanically-maintained cross-reference. Storing entries needs nothing but a site routine that writes them. On #2 PATIENT, 446 of 485 cross-references store nothing on vehu, and most of the ones that do refuse a seek — those subtrees are how this database is actually navigated. Stored: present with Seek: no is the signal to reach for find … --raw; Stored: absent is a measurement about this instance, not an error.

The record id is not last

Section titled “The record id is not last”

Shape reads 4 · id@3 (not the last) on #100 AR — the patient-orders path. Four subscripts, the order number at position 3, and a trailing sequence number that a walk assuming "last subscript = record id" would have read as a record number. id@ lists every position that addressed a live record in every sampled entry; id@none means none did, which is also an answer.

Key, and the byte figure

Section titled “Key, and the byte figure”

FileMan's stock B cross-reference stores $E(X,1,30) — the first 30 characters. Nothing in a mismatch sample can see that if every sampled value is shorter than 30:

300 entries agreed with the field's value, and every key stopped at exactly 30 bytes. The agreement proves nothing; the ceiling is the tell. So:

  • identity (n=K) is unfalsified, never proven — a sample can only fail to refute one.
  • transformed is proof, and names the record it was proven at — or says (declared) when the #.11 registration declares a TRANSFORM FOR STORAGE, which is proof from the dictionary with no sampling at all.
  • unmeasured says why: not seekable, keyed on more than one field, the column is computed or word-processing, or the index stores nothing here.

The seek license table below the listing turns that into the sentence you can act on. Only prefix seeks are ever proposed over a sampled identity, and only up to the longest key the sample measured — an unfalsified identity means no sampled value was cut, so whatever length the index truncates at, it is at least that long, and a prefix inside it survives the cut. (Until Q4.1 this said minimum, which measures something else entirely — how short the shortest indexed value happens to be. On #44 B that is 2 bytes, against a real ceiling of 30.) Equality and range seeks are listed as sample-supported, residual under-return risk, because a seek over a truncating index positions past the stored bucket, visits zero candidates, and a kept predicate never runs on what the seek never reached.

A second risk rides beside that one and is reported separately: whether the index holds every record. A #.11 registration declaring no SET CONDITION provably does; a traditional ^DD definition declares no condition field at all, so whether its logic files every record is site M v db never evaluates — and that is 5,394 of vehu's 5,665 seekable regular cross-references, including every stock B. The licence says POPULATION UNPROVEN there. The positioning is exact either way; what needs checking is the population, which is what --explain states, and what its equivalence check settles (§8.8).

Two more things it reports

Section titled “Two more things it reports”

Defined here, stored elsewhere. #.11 indexes registrations two ways — by the file an index is defined on and by the file at whose root its entries live. Membership here is the second, because that is what the engine resolves a name through. On vehu #2 the two differ by ten: AX/AY → #2.98, G202501–G202504 → #2.025, and so on. They are reported by name with their root file rather than listed as #2's indexes, because find 2 AX has never heard of AX.

What it cost. One dictionary read, two #.11 seeks, one registration read, then one stored-entry probe per listed cross-reference and one key sample per seekable single-field one. indexes 2 is 489 round trips; indexes 2 --walkable --key-sample 10 is 61 and takes seven seconds. --kind and --walkable filter before any probe runs, and the listing always carries the full denominator so a filtered answer never reads as the whole file.

--all: one engine-side pass

Section titled “--all: one engine-side pass”

The per-file form probes once per cross-reference. --all does not repeat that loop 8,300 times: the sweep is computed engine-side (ixcensus^VSLDD, VSL*1.0*61) and paged back.

9,739 cross-references across 2,879 files in about four seconds (foia: 9,699 across 2,826). The cost is not a trick — roughly 90% of declared cross-references store nothing, so their enumerability is a single $DATA, and the rest cost a bounded 20-node walk.

Without --out it prints the same table the per-file listing does, with a File column in front — filter it, or it is 9,739 rows:

Three things to know before consuming it:

  • key is unmeasured on every row, and says so. Deciding whether a stored key IS the indexed column's value costs a record read per sampled entry per cross-reference. That question belongs to one file at a time — the header block points at --key-sample, and the row never leaves the cell blank.
  • files represented is not the number of files swept. It counts the files the rows came from; a file declaring no cross-reference emits no row. Sub-files are outside the sweep entirely (the enumerability half needs a data root) — ask one by number instead.
  • The two scopes are one column set. A sweep row renders through the same cells as a per-file row, and the counts agree: #2 answers 485 and #44 answers 19 either way.

The dials are --sample N (stored entries read per cross-reference, default 20), --page-size N (rows per engine page, default 2000), --pace D (a politeness gap between pages for a background run — the artifact is pacing-invariant, same sha256), and --one-page/--token to walk it by hand. --all refuses beside a file number, and each single-file flag refuses beside --all, rather than being silently ignored.

--out DIR writes indexes.jsonl + manifest.json under the index-sweep input contract. A --kind/ --walkable run is a deliberate subset: it stays complete: true, records the filter in request, and carries the denominator it was cut from in details.declared. --one-page is a named incompleteness and exits non-zero.

Measured properties

Section titled “Measured properties”

Synopsis, arguments and flags: generated from the contract (dist/v-contract.json, command indexes) and rendered on the documentation site.

The cross-reference inventory — the measurements that say what may be looked up by key and what may not. Per row: name, field(s), source (which register declared it — dd-ix, index-file, or both), kind (open vocabulary — regular, mumps, trigger, compound, record-level, kwic, soundex…), seek (does a positioned lookup admit it), condition presence, stored (does a subtree by this name exist under the file's root on this instance — absent is a measurement, not an error), shape (sampled subscript depth and the measured position(s) of the record id — which is not reliably the last subscript), and key — whether the stored key IS the indexed field's value, measured by sampling --key-sample entries. The key verdict is epistemically careful: identity n=K is unfalsified, never proven, and the byte ceiling beside it is what catches truncation (vehu #44 B stores exactly 30 bytes). The per-license rendering spells out what each row admits: prefix seeks up to the measured ceiling; equality/range sample-supported only; conditional or condition-unproven populations named. --out works on both scopes: on one file it lands the --key-sample measurements as the indexes.jsonl that rows --explain --indexes cites; under --all it lands the instance sweep. --all inventories every top-level file in one engine-side pass (vehu: 9,739 cross-references across 2,879 files in ~2 s; the key column is not measured at that scale and every row says so). Executed: example (#44: 19 cross-references, 6 of them seek-refusing MUMPS-kind; the sweep header with its open-vocabulary tally — kwic 45, soundex 3, unlisted 1).
