v db fields-profile
Group Data
Engine access read
Mutates data no
Reversibility not applicable (does not mutate)

Synopsis

Section titled “Synopsis”

Arguments

Section titled “Arguments”
Argument Type Required Description
file float yes FileMan file number, e.g. 63.04.

Flags

Section titled “Flags”
Flag Type Default Env Description
--engine string vehu V_ENGINE VistA engine profile to reach (vehu = YDB, foia = IRIS, local = in-image YDB).
--transport local | docker | remote — — Driver transport: local | docker | remote. Overrides the profile's transport; unset = the profile's own.
--lock-wait duration 30s — How long to wait for the engine run-lock before refusing (0 = skip immediately when busy).
--timeout DURATION duration — — Host wall-clock bound on ONE engine visit; a hung page is aborted engine-side, not just abandoned. Unset = the verb's derived default (180s; a whole-instance sweep verb pins a slower one); negative = no bound (still reapable by hand).
--parent string — — Scope a SUB-file profile to ONE multiple instance: the parent-record IENS with its trailing comma. Without it, a sub-file is profiled across EVERY parent's instance (the whole depth walk).
--top int 20 — How many fields the human face lists (0 lists them all). The machine face always carries every field.
--empty bool — — List the fields holding NO data instead of the ones that do — the other half of the same answer, and usually the one a wide file is asked about.
--token string — — Resume a prior walk from its opaque token, verbatim.
--one-page bool — — Fetch one bounded page and stop (prints the resume token; the tallies are that page's alone).
--out string — — Write every field's row to this directory as JSONL + a manifest, paired with the dictionary it describes.
--pace duration — — Politeness gap between the walk's engine visits (e.g. 500ms).
--examined string — — Candidates-examined budget per page (engine default 75000).
--elapsed string — — Engine-time budget per page in ms (engine default 10000).
--bytes string — — Emission budget per page in envelope bytes (engine default and ceiling 786432). The row set is the DICTIONARY, so a file too wide for the budget refuses BEFORE the walk rather than dropping fields to fit.

Example

Notes

Section titled “Notes”

Hand-written in the owning repository; the facts above are generated.

How many records hold a stored value in each field of a file — the whole dictionary tallied in one walk.

This is the instrument this database's sparsity demands. VistA sites extend a file by adding fields: #63.04 (the chemistry/haematology results multiple) carries 965 of them, because each site's lab tests arrive as columns. So the first question any extract asks — which of these columns actually hold data here? — used to cost one full walk of the file per column, 965 of them. It now costs one:

--empty flips the listing to the other half of the same answer — the columns holding nothing — which on a wide file is usually the half you came for. --top 0 lists them all; the machine face always carries every field.

What "bound" means. A scalar is bound when its ^-piece of its storage node is non-empty. A multiple is bound when its sub-file 0-node is set — "this record has sub-entries", answered without enumerating them. Both are the same notion the bound predicate reads (§7.4 and --where "<field> bound"), and deliberately so: this verb tells you which columns are worth predicating on, so it must agree with the predicate about what stored means. It does, by construction — one shared decision in the engine — and the accuracy sweep checks it in both directions.

What cannot be measured is declared, never zeroed. A computed field, a field the dictionary gives no storage node, and a field stored at an extract location rather than a readable piece each get a row carrying their reason instead of a tally:

A zero there would be indistinguishable from the answer you are looking for. They are counted apart on both faces: measured + skipped = fields, and populated + empty = measured.

It reports field NUMBERS, not names. The dictionary serves a field's name one engine visit at a time, so decorating 965 rows would cost the 965 visits this verb exists to avoid. Join them from v db schema <file> — and when you write the profile to disk, the --out manifest carries that dictionary's fingerprint, so the pairing is verifiable rather than remembered (§8.8 has the same pairing on data extracts).

Sub-files. Without --parent, a sub-file is profiled across every parent's instance (the whole depth walk) — which is what makes the #63.04 answer above a statement about the instance rather than about one patient. With --parent <IENS>, it is scoped to one multiple instance.

Paging. Every page carries every field, and the pager merges by summation. That is why a zero is a real zero rather than something you infer from a dictionary you also had to fetch: a field that appears at 0 on every page is empty here. An empty population still reports the whole dictionary at zero and says so, rather than rendering a blank:

Budgets. The row set is the dictionary, whose size is known before the walk starts — so a file too wide for --bytes refuses before doing any work, rather than dropping fields to fit. That is the opposite of distribution, which defers mid-walk; deferral is only honest when the thing being bounded genuinely grows as the walk proceeds.

Engine floor: VSL*1.0*57. An older engine does not have the verb.

Measured properties

Section titled “Measured properties”

Synopsis, arguments and flags: generated from the contract (dist/v-contract.json, command fields-profile) and rendered on the documentation site.

How many records hold a stored value in each field of a file — the whole dictionary tallied in ONE walk (the alternative was one distribution per field: 965 walks on #63.04). Every page emits every field, so a bound: 0 is a real measured zero and pages merge by summation; what the node/piece map cannot read (computed, storage-less) is declared, not zeroed. --empty lists the other half — the columns holding nothing, usually the question a wide sparse file is asked. Field names are deliberately not joined (one DD round-trip per name would re-price the verb); join from schema. A file too wide for the byte budget refuses TOOWIDE before the walk rather than dropping fields to fit. Executed: example (#4: 29 of 42 columns hold data; both halves shown).
