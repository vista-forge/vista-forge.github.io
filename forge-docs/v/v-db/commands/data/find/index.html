v db find
Group Data
Engine access read
Mutates data no
Reversibility not applicable (does not mutate)
Exit classes 2 (usage error)

Synopsis

Section titled “Synopsis”

Arguments

Section titled “Arguments”
Argument Type Required Description
file float yes FileMan file number, e.g. 200 for NEW PERSON.
index string yes The index name, e.g. B (a regular single-key whole-file index; MUMPS/computed-style refuse).

Flags

Section titled “Flags”
Flag Type Default Env Description
--engine string vehu V_ENGINE VistA engine profile to reach (vehu = YDB, foia = IRIS, local = in-image YDB).
--transport local | docker | remote — — Driver transport: local | docker | remote. Overrides the profile's transport; unset = the profile's own.
--lock-wait duration 30s — How long to wait for the engine run-lock before refusing (0 = skip immediately when busy).
--timeout DURATION duration — — Host wall-clock bound on ONE engine visit; a hung page is aborted engine-side, not just abandoned. Unset = the verb's derived default (180s; a whole-instance sweep verb pins a slower one); negative = no bound (still reapable by hand).
--from string — — Inclusive lower key bound, in STORED key space.
--to string — — Inclusive upper key bound, in stored key space (subscript collation).
--prefix string — — Byte-prefix key constraint, in stored key space; does not combine with --from/--to.
--fields string — — Projection: ';'-separated field numbers, or '*' (engine default: all top-level). Under --raw a projection is OPT-IN: unset means the stored subscript paths alone.
--tier external | internal | raw — — Projection tier for the record behind each entry (engine default external). Distinct from --raw, which chooses the POPULATION.
--where list (no splitting) — — Row filter ' ' on the candidate RECORD (repeatable = AND). Ops: = '= > < >= <= contains starts bound 'bound. Stored fields only, INTERNAL values; the seek still positions for free, every in-range candidate is charged.
--ids bool — — Attach a reference map to every row: for each pointer (foreign key) field, the file and record it names, plus a 'ref' that 'get --ref' reads back. A variable pointer resolves PER RECORD from its stored global root; a root the dictionary does not declare is resolved by asking which file owns it (marked resolvedBy:root), and named unresolved — never guessed — when no file claims it. Free on --tier internal (the values are already record numbers); on the default external tier it costs ONE extra internal projection of the reference fields per page.
--explain bool — — Report what this read WOULD do and exit, without reading a data page: its population, which predicate each index can position, the cost class, and the command to run instead. Two bounded dictionary reads of this file; never a sweep.
--census FILE string — — --explain only: a census artifact (census.jsonl) to read this file's record count from. The count is never estimated — it comes from a named artifact or it is reported unmeasured.
--indexes FILE string — — --explain only: an index artifact (indexes.jsonl from 'v db indexes --key-sample N --out DIR') to read the KEY measurements from. Without it every index is order-only, because whether a key IS the field's value is the one fact a dictionary read cannot supply.
--profile FILE string — — --explain only: a fields-profile artifact (fields-profile.jsonl) — a predicate on a column measured at zero bound records is a guaranteed-empty walk, said before the walk.
--token string — — Opaque continuation token from the prior page, passed back verbatim.
--raw bool — — Read the cross-reference's STORED entries instead of seeking it — the only way to reach the ones a seek refuses (MUMPS-type, compound, and the ones whose definition is gone). Emits the whole subscript path per entry; the record-number position is MEASURED and declared.
--at list (no splitting) — — Constrain a LEADING subscript to this exact value, one --at per level, in STORED key space (repeatable, in order). Measured: 'this patient' on #100 AR is the composite '100000;DPT(' — a record id with its global root appended — not the bare id. Needs --raw.
--ien-at string — — PIN the subscript position that holds the record number, 1-based. Unset MEASURES it from a bounded sample and declares the verdict. Needs --raw.
--out string — — Write EVERY entry to this directory as JSONL + a manifest, walking the index population to exhaustion instead of returning one page. The manifest carries each page's completeness block — population included — so a truncated artifact says so.
--max-pages int — — Safety bound on the --out walk (0 = unbounded). Hitting it is recorded as a NAMED incompleteness, never a silent stop.
--pace duration — — Politeness gap between the --out walk's engine visits (e.g. 500ms) — host-side spacing for background extracts against a live instance; every page stays bounded regardless.
--max string — — Rows budget (page size; engine default 4000).
--bytes string — — Page payload byte budget (engine default 786432).
--examined string — — Candidates-visited budget for the page (engine default 75000).
--elapsed string — — Engine-time budget for the page in ms (0 is legal; engine default 10000).

Notes

Section titled “Notes”

Hand-written in the owning repository; the facts above are generated.

Lookup over a named index — a declared index walk in emission order. This is the verb to use when you want to seek rather than scan, because the key bounds are pushed down to the index:

Read this carefully — the differences from rows are the point:

  • population index:B — the answer set is the index's, not the file's. That is stated, never assumed. If the index is incomplete, this is the field that tells you the answer might be too.
  • emitted vs distinct are reported separately and an index walk is never silently de-duplicated. A record indexed twice is emitted twice, and you can see it.
  • Entries are in emission order and are never re-sorted host-side. Sorting by IEN would clobber duplicate emissions, which is exactly the signal you need.
  • Key bounds are in STORED key space — the collated subscript, not the external value. --prefix is a byte-prefix constraint and does not combine with --from/--to.
  • The cursor is (key, ien) — note the base64 key inside the token.

A key range — inclusive on both ends, in stored key space:

--where on find filters the candidate record after the index has positioned. It does not affect the seek — which is exactly what the completeness block shows: the seek narrowed 1,496 records to 16 candidates, and the filter then rejected all 16.

An unknown index is a typed refusal, not an empty list — which is the exact DDR behaviour (a typo'd index yields an empty result with no error) that this verb exists to not reproduce:

Index types that cannot be walked safely are refused rather than approximated — MUMPS-type, trigger, compound-key, record-level, computed-style and dangling (a directory row whose definition is gone) all raise U-VSL-ROW-IXTYPE, because site-authored index logic is never evaluated. The kind column in schema's xref table is the same classification find dispatches on — one shared classifier, so what schema calls regular is exactly what find will walk, and a refused kind names itself in the refusal message.

--out: the population as artifact

Section titled “--out: the population as artifact”

rows --out walks a file to exhaustion into JSONL plus a manifest. find --out does the same over an index population, on the same contract — so an index-driven extract is one invocation rather than a paging loop you write yourself:

Two things make the artifact readable months later by someone who cannot go back and check it:

  • The manifest names the population. details.population is the engine's own index:B, lifted to the top of the evidence — so a reader knows this is a slice of the file chosen by a key range, not the file. Every page's completeness block rides underneath it verbatim, never summed by the host.
  • complete means what it says. The walk has exactly one clean exit — the engine hands back no continuation token. Every other stop (a failed page, the --max-pages bound) appends a named reason to incomplete, and the command exits non-zero. A truncated artifact that looks whole is the single worst thing this verb could produce.

It also carries the same dictionary pairing rows --out does: a fingerprint of the DD the values were decoded against, so --tier internal data and its dictionary travel as a pair you can verify rather than a discipline you have to remember.

--raw: the stored-entry walk

Section titled “--raw: the stored-entry walk”

Look at that list again. On #200, one cross-reference is regular and the rest are mumps — and find refuses every one of the mumps ones, because the logic that maintains them is site-authored M this tool will never evaluate. Measured across the database the ratio is worse and more interesting: 354 of #2 PATIENT's 386 cross-references are mumps, and those subtrees are how VistA is actually navigated. #100 ORDER's AR is the patient-orders path.

--raw is the door to them. It does not seek and it does not interpret: it walks the cross-reference's own subtree and emits one row per stored node, with the whole subscript path.

Four things in that output are the whole design, and each of them exists because the obvious alternative is wrong.

--at takes the key AS STORED, which is not the key you expect. "This patient" on #100 AR is 100000;DPT( — a record id with its global root appended, the variable-pointer spelling — not the bare 100000. Every first attempt that passes the bare id returns nothing, correctly and uselessly. --at repeats, one per subscript level, and the levels must be contiguous from the first. Its value is taken byte for byte: a stored key containing a comma (SMITH,JOHN) is one level, never two.

The record id is read from a MEASURED position, never from the last subscript. Look at the path above: (patient key, inverse date, ORDER id, sequence). The record number is at position 3 of 4. A walk that assumed the terminal subscript would have read the trailing sequence number as an order number — silently, on the most valuable path in the database. So every page samples up to 20 entries, tallies how often each position resolves to a live record of this file, and reports the verdict with its evidence:

verdict what it means
elected one position out-resolves every other; that is the one used
pinned you supplied --ien-at N; the measurement is still reported, so a pin that disagrees with it is visible
ambiguous two or more positions resolve equally often — nothing is claimed, entries come back with paths and no candidate
none no position resolved; the entries are real, but they are not subscripted by this file's records
unsampled there was nothing to sample

ambiguous is common and it is a measurement, not a failure. #19 AD stores (item, OPTION id, sub-id), and its key is a small integer that collides with live record numbers, so positions 1 and 2 both resolve 20 out of 20 on both gold engines. Guessing between them would report a menu item as an option. Pin it once you know which it is:

Asking for a projection (--fields or --tier) when nothing was elected refuses rather than handing back every row unprojected. Without either flag there is no projection at all: the walk's product is the path, and no record is read.

A candidate that is not a live record is NAMED, never skipped. The row comes back flagged dangling with the subscript still reported, because that is a finding about the cross-reference — three stock cross-references were measured with live entries whose definition is gone, and this is the only instrument that can reach them. An entry with fewer subscripts than the elected position is flagged short, which is a different fact and says so.

A declared cross-reference that stores nothing here refuses (U-VSL-ROW-NOSUBTREE) instead of returning an empty page — 70% of the non-walkable ones store nothing on a given instance, and "this instance files nothing here" is a different answer from "your --at matched nothing", which is an empty page. A name the dictionary does not declare refuses U-VSL-ROW-NOINDEX: --raw reads declared cross-references, never an arbitrary subtree.

--ids works here too, and needs no --fields. The reference map is asked for by name, so the walk fetches the reference fields itself — which turns a page of subscript paths into a page of places to go:

That is this patient's orders, each entry carrying the ordering provider, the dialog and the location as addresses rather than as renderings. See 8.7 for the rules and the cost.

Flag notes. --from/--to/--prefix and --where refuse under --raw — a seek positions a walkable index over a key range and this walk positions with --at, so accepting either and ignoring it would answer a wider question under exit 0. And --raw is not --tier raw: --raw chooses the population (stored entries), --tier raw chooses the projection grain (a record's data nodes). They compose.

That second one is a genuine name collision, and it comes from the accepted design rather than from an oversight — so the tool signposts it instead of relying on you to have read this paragraph. Whenever find, count --index or distribution --index refuses a cross-reference as unseekable, the refusal now carries the way out:

--tier raw is the word most people reach for first when they want "the raw thing", and it lands on exactly this refusal — which used to be a dead end. A correct refusal that leaves you with nowhere to go is how a capable tool reads as an incapable one.

--out lands the whole walk as JSONL plus a manifest, on find --out's contract. The manifest lifts the population, the elected position and its verdict to the top of its evidence, and keeps every page's declaration block — because a file of subscript paths whose record-id position is not recorded with them is a set of subscripts nobody downstream can resolve.

Measured properties

Section titled “Measured properties”

Synopsis, arguments and flags: generated from the contract (dist/v-contract.json, command find) and rendered on the documentation site.

Lookup over a named cross-reference, in emission (key-collation) order — a declared index walk where seeks position and never degrade into scans. emitted vs distinct stays visible because an index walk never de-duplicates. Key bounds are in stored key space (what the index holds, not what the field renders). A seek admits only a mechanically-maintained cross-reference; the rest refuse U-VSL-ROW-IXTYPE naming their measured kind — and that refusal signposts the other face:

--raw reads a cross-reference's stored entries instead of seeking it — the only way into MUMPS-type, compound, and definition-less cross-references, which are the majority of the database's real access paths (354 of #2's 386). It emits each entry's whole subscript path; the record-id position is measured from a bounded sample and declared with its per-position evidence (a strict argmax that refuses on a tie — ambiguous is a measurement, not a missing answer), or pinned with --ien-at. --at constrains leading subscripts level by level, in stored key space — measured reality: "this patient" on #100 AR is the composite 100000;DPT(, a record id with its global root appended, not the bare id. A projection under --raw is opt-in; the coverage sentence on every page states what the walk is OF (the cross-reference's stored entries, not the file's records — the walk reads subscripts, it never interprets them). A declared cross-reference with no subtree refuses NOSUBTREE (a finding); an --at matching nothing is an empty page — different nothings, different shapes. --raw is not --tier raw (population vs projection). Executed: example (#200 B prefix seek; the #44 AC typed refusal with its signpost; the raw walk of #44 AC with elected id-position and evidence line).
