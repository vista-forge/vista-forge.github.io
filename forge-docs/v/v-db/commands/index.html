Commands — v db

Analyze

Section titled “Analyze”

Sizing the database as it is — measured counts and sampled record sizes.

Command What it does
v db estimate Estimate export size for a set of files (record count × sampled record size) and fit it against a cap (exit 3 over cap).

Inspect

Section titled “Inspect”

Dictionary and catalog reads: schema, the walked census, explain.

Command What it does
v db export Write the data dictionary to disk as JSONL plus a manifest, for analysis away from the engine. The manifest records WHICH instance it came from, at what FileMan version, what was requested, and what was requested and not written.
v db census The WALKED catalog of every file (table): honest record (row) counts with the stored header claim beside as an integrity signal, and sampled record sizes.
v db refs The reference map (foreign keys) around one file: what it points at, and what points at it — with --verify auditing FileMan's pointed-to-by catalog against the fields themselves.
v db indexes Inventory one file's cross-references (indexes): both registers they are declared in, what each one stores, where the record id sits inside an entry, and whether its key IS the indexed column's value — the measurements that say what may be looked up by key and what may not.
v db schema Describe one file (table): its fields (columns) and types, pointers (foreign keys) and cross-references (indexes) — the data dictionary, which is this database's schema catalog.
v db integrity The instance-integrity census: the whole-instance sweeps — header claims vs walked truth, pointer resolution, declared-type grammar, the declaration-driven index audit (register + feed), hollow sub-records, the DD census, key uniqueness, and the full-depth sub-file descent — as counts with denominators per file (class, file, count, content-fold rows), never a pass/fail verdict.
v db integrity-compare Compare an integrity artifact against a named expectation, OFFLINE: a prior committed run of the same instance (any row difference is the red delta outcome) and/or the shipped-state ledger (one-sided excess is the attention outcome, never red). Speaks four pinned outcome words: clean, delta, attention, stopped.
v db integrity-report Explain one integrity artifact's pointer findings by TARGET (VD-D109): dangling mass joined to each target file's own header-ledger row — a header-divergent target is ONE finding with its mechanism shown, a healthy target is the class worth eyes, with the source list attached either way — plus the malformed split (type-history vs live-resolving), which has no target to attribute.
v db bundle Run a RUN SET — the committed declaration of the components a bundle is made of — writing each component to its own directory with its own manifest, and embedding the set that produced it. --explain reports what it WOULD export without reaching an engine.
v db selection The SELECTION object: which tables to extract, at any depth, with a projection and filter per table — compiled into the run set 'v db bundle' runs. Saved, diffable and re-runnable; not a query language.
v db selection compile Compile a selection into the run set 'v db bundle' runs: each table entry becomes one 'rows' invocation with its projection and filter, each passthrough entry is carried unchanged, and the compiled set records which selection (and which catalog build, under which rule) produced it. Every entry is resolved against the generated command contract; a problem refuses and writes nothing.
v db selection size Size a selection BEFORE it is extracted (VD-D119/VD-D120): each table's N from the committed catalog build at zero engine cost, its mean row bytes from one spread probe at the component's own projection, tier and filter, widened until the sample-dispersion band is inside ±10 % or 5 visits are spent — an interval per component and for the whole, never a point; a selection with an unsizable component refuses before any engine visit and never holds a verdict.
v db selection explain Report what a selection WOULD compile to — every entry, its kind, the verb and arguments it becomes, and the lineage the compile step would attach — without writing anything. If the selection has problems, all of them rather than the first.
v db catalog The VistA data catalog: build it without touching an engine, from a certified bundle plus an integrity capture (one entry per table — structure, volume and condition planes, derived package attribution with its rule, search index embedded), then browse and search the artifact without an engine.
v db catalog build Build the catalog artifact OFFLINE from a certified bundle and an integrity capture of the same instance: one entry per table with structure, volume and condition planes, the derived package attribution with its rule, and the search index built in — then certify the derivation by both-direction reconciliation against the components (refused is not published).
v db catalog browse List the catalog's tables from the artifact — attribution-first by default (owner, then the contested set, then unmatched); size is never the default. Every row states its volume as a count or a named non-fact.
v db catalog search Rank tables and fields by name and description over the artifact's embedded index, under the ranking rule the artifact ships as data. A negative answer carries the corpus denominator and the build age.
v db packet The DELIVERY PACKET: the per-component manifest, the producer certification, the channel evidence stated verbatim, the selection's lineage with every declared exclusion, the sized run, and the condition of the data — the same-session integrity audit's rows scoped to exactly what was extracted, read against the shipped-state floor. Counts over denominators; the packet never scores or judges.

Data

Section titled “Data”

The data plane: bounded, resumable reads with a completeness block on every page.

Command What it does
v db rows One bounded page of a file's records (rows) walked in row-id order — the population is the walk, never a stored list, so nothing is missed because an index was stale (completeness block on every page).
v db get One record (row) by its IEN (row id), byte-exact — .5 is a real IEN, not a typo.
v db count Honest record (row) count of one file (table) — counted by walking the rows, resumable, with a completeness block. The count the file header stores is a CLAIM; this is a measurement.
v db find Lookup over a named cross-reference (index) — a declared index walk in emission order. Emitted vs distinct stays visible because an index walk never de-duplicates; seeks position, never scans. --raw instead READS a cross-reference's stored entries, which is the only way to reach the ones a seek refuses (most of them: 354 of #2's 386 are site-authored).
v db distribution Bounded distinct-value/top-N distribution of ONE field (column), or the depth of a multiple (nested table) — what values are actually in this column, and how many of each.
v db fields-profile How many records hold a stored value in EACH field (column) of a file (table) — the whole dictionary tallied in ONE walk, so a wide sparse file says which of its columns actually carry data here.

Authorize

Section titled “Authorize”

The instance's declared authorization surface (enforced engine-side at every verb door).

Command What it does
v db policy Show or declare the instance's authorization surface (class, per-file policy, read enablement) — enforcement is engine-side at every data verb's door.

Write

Section titled “Write”

Validated, audited mutations behind the engine-side @mutates gate.

Command What it does
v db put Create a record (row), or a sub-record in a multiple (nested table) — external values by default, validated whole-request.
v db edit Write values into an existing record (row) — one invalid value refuses the whole request; '@' clears a field (column), which is distinct from deleting the row.
v db delete Delete a record (row) — DRY-RUN by default (reports what would go); --commit --yes actuates.
v db reindex Rebuild one record's cross-references (its index entries). ADDS any entry that is missing; it does NOT remove one that is wrong — an index entry for a value the record no longer holds SURVIVES a reindex (measured, both engines). Whole-file reindex is deliberately not a verb.
v db text Write or read ONE word-processing field (a text blob) — replace/append/--clear; --show reads the field back, which the older interface could only write.

Completeness fields

Section titled “Completeness fields”
field type meaning
population string file, index:<name>, sub:<file>, ien-list(<n>), dic, or dic:<file>
examined int candidates visited, charged per candidate including filter-only projection
filtered int candidates rejected by a predicate
emitted int rows in this page
distinct int distinct IENs in this page — below emitted when a population can repeat one (index:<name>, ien-list)
stopped enum end | rows | bytes | examined | elapsed | chunk (ien-list only: the transport ran out of chunk, not the population)

Emission order is a property of the population, derivable from that one field — there is no order field to read and none to keep in step: file ⇒ row-id order · index:<name> ⇒ that key's collation · sub:<file> ⇒ parent-major depth order · ien-list(n) ⇒ the order you supplied.

On an ien-list page one more block rides beside these: misses, the requested IENs with no record, each with the list position that asked for it — present and empty when nothing was missing.

Beside it, page:

field meaning
more is there data behind this page
next the opaque continuation token, present only when more is true

Recurring flag families

Section titled “Recurring flag families”

Named once here; the summary table marks membership.

  • Budgets (B): --max (rows) · --bytes · --examined · --elapsed — §2.4, defaults §6.6.
  • Cursor (C): --token · --one-page · --pace (on the fold verbs, --pace spaces the fold's own pages).
  • Artifact (A): --out DIR (JSONL + manifest) · --max-pages (named-incompleteness bound) · --pace (politeness gap between the walk's engine visits). On rows/find the two walk dials belong to --out and refuse without it (BAD_OUT_DIAL) — a bound or a pace on a single-page read would be accepted and silently inert.
  • Projection (P): --fields '<n>;<n>;…'|'*' · --tier external|internal|raw.
  • Filter (W): --where '<field> <op> <value>', repeatable = AND; §6.4.
  • Seek (K): --from · --to · --prefix (stored key space; --prefix excludes --from/--to).
  • Plan (X): --explain (+ artifact citations --census · --indexes · --profile). The citations are plan inputs: naming one without --explain refuses (BAD_EXPLAIN) rather than running the read with the artifact silently ignored.
  • Reference map (I): --ids (and get --ref).
  • Confirmation (Y): --yes, required by every mutation, client- and engine-side.

Projection tiers

Section titled “Projection tiers”
tier value shown property
external (default) FileMan's rendered form (via FileMan's own retriever) human-faithful; instance-specific — the portability warning on every page is real
internal the stored value (a pointer is an IEN, a date is FileMan internal) portable across instances; what --where evaluates against; makes --ids free
raw the record's data nodes byte truth; excludes --fields and --ids by construction

Filter operators

Section titled “Filter operators”

The closed table — no client M is ever XECUTEd:

op meaning
= equal
'= not equal
> < >= <= ordered comparison, in the engine's own collation
contains M [ containment
starts byte-prefix test
bound the field has a stored value node at all — takes no value
'bound it does not — the negation of the above

Two constraints:

  • Stored fields only. A computed field is refused, because filtering on it would execute site DD M once per candidate.
  • Predicates run against the INTERNAL value, not the external one. A filter on a pointer field takes an IEN, not a name; a filter on a date takes FileMan internal date form. This is deliberate — the external value is the retriever's product, and requiring it per candidate would price every filter at the projection rate.

bound is the one predicate that reads storage rather than a value. An absent node, a stored empty string and FileMan's @ are three different states that every other operator sees identically, and bound names exactly one of them: is there a node here at all. Two consequences worth knowing:

  • It is the only operator admissible on a multiple — a multiple is bound iff its 0 node is set, which answers "does this record have any sub-entries?" without enumerating them. Every other operator on a multiple refuses U-VSL-ROW-FLTFIELD.
  • It is a two-token clause — --where '9.3 bound'. Supplying a value (--where '9.3 bound X') is a typed refusal, never an ignored argument.

Every verb that takes --where takes the same table: rows, find, count and distribution. There is one grammar, so a predicate you can express in one you can express in all of them.

A clause is ONE shell argument, taken byte-for-byte. VistA values carry commas (SMITH,JOHN is one name), and every --where treats a comma as data, never as a list separator — repeat the flag for AND: --where '.01 = SMITH,JOHN' --where '9.3 bound' is two predicates; --where '.01 = SMITH,JOHN' is one.

Default bounds

Section titled “Default bounds”

Engine defaults, overridable per invocation:

verb rows bytes examined elapsed
rows / find 4000 786432 75000 10000 ms
count — — 300000 / page 10000 ms / page
census — engine default engine default 10000 ms / page
distribution — engine default engine default 10000 ms / page
text --show — 786432 — —

bytes is derived from the smaller of the two engines' maximum string lengths (YottaDB 1,048,576 against IRIS 3,641,144), which is why there is no engine branch anywhere in the byte accounting.

What each exit class means here

Section titled “What each exit class means here”

The platform ladder, identical across every v domain:

code meaning typical v db causes
0 ok
1 runtime error a genuine engine fault (verb X faulted), an engine-class refusal (site-M/substrate failure), IO, parse
2 usage error bad flag/argument — including usage-shaped engine refusals (no such file/record/field/index, bad operator, bad token — since VSL*1.0*64 these exit 2, not 1)
3 check/gate failed estimate over --cap · an INCOMPLETE artifact · a capability floor
4 refused / substrate unavailable no engine resolved · run-lock timeout · missing --yes · a policy/instance/audit denial or record-lock timeout (since VSL*1.0*64)

Typed refusals, explained

Section titled “Typed refusals, explained”

Engine-side refusals are typed, and (since VSL*1.0*64, the typed-refusal-class patch) they render as refusals: the message is the module's own reason alone — file 99999 has no data dictionary — at a classified exit (usage-shaped → 2 · policy/instance/audit/lock → 4 · site-M/substrate failures → 1). The classification is per-code, default usage, carried in the generated dist/errors.json (class field) with the runtime truth in $$classOf^VSLAPI. Only a genuine engine fault — a real crash — wears the trap prose verb <label>^VSL… faulted: at exit 1; that wrapper now means what it says. Branch on the typed error.code, never the prose. The ones you will actually meet:

code meaning
U-VSL-ROW-NOFILE no such file number, no DD, or no data root on this instance
U-VSL-ROW-NOTFOUND no record at that IEN
U-VSL-ROW-BADFIELD not a field number, or the file has no such field
U-VSL-ROW-FLTFIELD filter target is computed, a multiple, or has no storage location
U-VSL-ROW-FILTER malformed filter, or an operator outside the closed table
U-VSL-ROW-VALUE a control byte in a value
U-VSL-ROW-IENS malformed IENS, or the wrong shape for the verb (put creates, edit files)
U-VSL-ROW-DINUM the file forces its own record numbers — put refuses it
U-VSL-ROW-LAYGO a lookup node in the IENS without --laygo
U-VSL-ROW-NOINDEX no such index on that file
U-VSL-ROW-IXTYPE the index cannot be walked safely — the refusal names its measured kind (mumps, trigger, dangling, compound, record-level, computed-key, foreign-root), the same vocabulary schema reports. The kind vocabulary is OPEN — see below. The refusal also signposts find … --raw, which reads the stored entries of exactly these
U-VSL-ROW-NOSUBTREE the name is declared but stores nothing under this file's data root on this instance (measured: 70% of non-walkable cross-references) — a finding, refused loudly rather than served as an empty page
U-VSL-ROW-FOREIGN a new-style FOREIGN-ROOT registration: its entries live at another file's root, and which file its subscripts number is unmeasured
U-VSL-ROW-AT find --raw --at was given something other than a contiguous 1..k list of leading subscripts
U-VSL-ROW-IENPOS a pinned record-id position is not a positive integer, or a projection was asked for where no position measurably holds a record number
U-VSL-ROW-TOOWIDE fields-profile: the dictionary needs more envelope bytes than the budget allows — refused before the walk, because a per-field tally cannot drop fields without lying
U-VSL-ROW-IENLIST the supplied IEN set is defective: a non-IEN entry, a gap in the chunk keys, an empty list, a chunk overrunning its declared total, a chunked list with no whole-list hash, or an IEN set combined with a parent scope or a sub-file
U-VSL-ROW-CHUNK the supplied chunk does not carry the list position the cursor needs — the refusal names both; send the chunk that covers it
U-VSL-ROW-PARENT the parent scope is defective: given for a top-level file, wrong arity for the sub-file's depth, a non-IEN piece, a missing trailing comma, or an unresolvable DD chain
U-VSL-ROW-DEPTH a ** field spec (sub-file depth) was requested
U-VSL-ROW-HDRLESS the multiple's node;0 header is missing and filters were requested — filter evaluation runs through FileMan's retriever, which measurably cannot address a headerless multiple (DIERR 401). Without filters the page serves, each unprojectable sub-row a typed in-stream fault
U-VSL-ROW-NRFIELD a nested-root branch projection asked for a field the location decode cannot serve (computed, storage-less, extract-location, or a multiple)
U-VSL-ROW-WFIELD the file is a word-processing sub-file — its records are lines; read them with text --show
U-VSL-ROW-TIER unknown projection tier
U-VSL-ROW-INSTANCE / U-VSL-ROW-AUDIT the instance gate refused (class undeclared or unrecognized, a real-data instance, the Kernel PROD tripwire), or the real-data read-audit write failed and the read fails closed with it
U-VSL-ROW-NESTEDROOT the file is in the measured nested-root table (#1.1, #.6): its top-level IENs are file numbers, so a top-level read would render wrong-level values
U-VSL-ROW-TREESIZE a record's subtree exceeded the bytes budget under --with-multiples — the row is a typed stub naming the record, the multiple and the paged alternative; distinct from U-VSL-ROW-TOOBIG (one oversize value)
U-VSL-ROW-SUBFILE the sub-file's parent chain does not resolve — over 20 levels, or a cycle in the dictionary. Nesting depth alone no longer refuses: a sub-file at any depth walks file-wide (§8.8)
U-VSL-ROW-RAWFIELDS --fields combined with --tier raw — raw returns the record's data nodes, which a fields spec cannot select
U-VSL-ROW-PROJFAULT the retriever hard-faulted mid-projection (typically a computed field's site M against malformed data) — typed, never a bare M fault
U-VSL-ROW-SEEK malformed key bound, or --prefix combined with --from/--to
U-VSL-ROW-TOKEN malformed token
U-VSL-ROW-STALE the token's binding fingerprint does not match this request shape
U-VSL-ROW-BOUNDS a bound is out of range
U-VSL-ROW-TOOBIG a single value exceeds what the envelope can carry
U-VSL-ROW-DIERR FileMan itself refused — its text is projected verbatim
U-VSL-ROW-POLICY the declared policy denies this verb on this file
U-VSL-POL-ARG / U-VSL-POL-KEY a malformed policy declaration
U-VSL-API-CONFIRM / U-VSL-API-ATTRIB the @mutates gate: missing confirmation or attribution
U-VSL-ROW-ARG a malformed argument to a text write: a bad mode, an empty line set outside --clear, lines supplied with --clear, or a non-numeric line key
U-VSL-ROW-LOCKTIMEOUT the record's bounded LOCK timed out — another process holds it (multi-process contention; retry)
U-VSL-DD-NOTFOUND the dictionary read (schema, export, the --ids companion) found no data dictionary for that file number
U-VSL-DD-INSTANCE / U-VSL-DD-AUDIT the raw dictionary read's instance gate refused — the same M6 door and rungs as U-VSL-ROW-INSTANCE/-AUDIT, in the dictionary module's namespace (the raw ^DD register serves stored bytes, so it is gated where the interpreted schema reads are not; no v db verb reaches it today — it serves the read-fidelity harness)
U-VSL-DD-POLICY the declared policy denies the raw dictionary read on that file's top-level ancestor — the DD-plane twin of U-VSL-ROW-POLICY
U-VSL-POL-WRITE a policy --declare/--revoke could not be filed — the underlying VSLFS write failed
U-VSL-INTEG-INSTANCE / U-VSL-INTEG-AUDIT the instance-integrity sweeps' instance gate refused, or their real-data read-audit write failed and the sweep fails closed with it — the same M6 door and rungs as U-VSL-ROW-INSTANCE/-AUDIT, in the integrity module's (VSLINTEG) namespace
U-VSL-INTEG-ADMIT an audit-class file's first-level subtree headers no longer claim its own number — the pinned A4/D108 file-subscripted-storage contract failed on-engine, and every sweep refuses rather than walking a population it can no longer exclude
U-VSL-INTEG-KEY two KEY register entries share one (file, name) identity on this instance — the keys sweep's per-key emission identity would collide, so it fails closed rather than silently overwriting a row (a register defect, shipped at VSL*1.0*75; the host face consuming the sweep is part 3 of the 3x-b expansion)
U-VSL-INTEG-ARG a defective indexb population feed: no population, both the explicit and naive populations at once, an explicit feed combined with a walk bound, or a malformed / out-of-vocabulary / duplicate / inadmissible population row
U-VSL-ROW-PROFFIELD distribution's field is computed, has no storage location, or was supplied together with --index — a field and an index are two different distributions

Host-side codes — the complete catalog, grouped by exit class so a script can branch on error.exit first and error.code second. Completeness here is mechanical, not a promise: make error-gate reds when a code is raised in source and missing from this section, documented under the wrong exit, or left behind after a rename — and dist/error-catalog.json is the generated registry for a consumer that would rather read JSON than this prose. It carries three layers: host (raised in v-db), lowerLayer (raised by the org packages v-db links — v-base and clikit — derived from its own imports, with the raising file and line), and engineClasses (the U-VSL-* half, classed by v-stdlib). Every entry carries documented, which says whether this section names it: the host and engine halves are total by gate, and the lower layer is inventoried rather than documented — the codes below are the ones a v db user is most likely to meet, and the registry is where you look up one that isn't here. Every one carries code, exit, message and (where a one-flag fix exists) hint in the JSON envelope. In JSON mode every envelope rides stdout — ok and error alike, one stream to read (since clikit v0.11.3, ruled 2026-08-15); a refusal after an engine visit additionally carries data.instance. Text mode keeps the human Error: line on stderr. Exactly one ok:false envelope per failing invocation.

Usage — exit 2 (a flaw in the request; raised before any engine visit, naming the flag rather than the engine):

UNKNOWN_ENGINE --engine names no registered profile (the standing ones are vehu and foia)
BAD_MAX non-positive --max — the engine would silently remap it to the default page size

Every problem is reported, not the first, and nothing is written — a refused compile leaves no half-valid run set on disk. The message names which

Check — exit 3 (a verdict or a floor, for scripts to branch on):

code meaning
AGG_SINCE this engine's VSL build predates --where/--index on count/distribution (needs VSL*1.0*55; distribution --index needs VSL*1.0*56 — see below). Refused here rather than sent because an older engine does not refuse the flag — it never binds it and answers the wider question with ok:true
IENS_SINCE the same floor for --iens (needs VSL*1.0*54) — below it the engine reads the WHOLE file instead
OVER_CAP estimate — the selection exceeds --cap; selection size — the whole sizing interval is above --cap
CAP_UNDECIDED selection size — the --cap falls inside the sizing interval, so the measurement does not decide it: raise or lower the cap past the interval, or narrow the selection
UNSIZED selection size — the selection holds a component that cannot be sized from the committed artifacts, so there is no size and no verdict (VD-D119); every such component is named in data.sizing.unsized[] with a per-component code — NO_PRIOR_RUN (a sweep with no --prior run, or a prior pass with different arguments), NO_COUNT (no committed count: uncovered), NOT_IN_CATALOG, NO_CEILING (no header-ledger row-id ceiling for a top-level file), WP_UNSIZED (a word-processing sub-file; demand-triggered, VD-D119 rev 5) — which is a field of the report, not an error.code. Decided offline, before any engine visit
PACKET_STALE_AUDIT packet: the audit was written BEFORE the extraction began, so it describes the instance as of an earlier moment — the stale slice VD-D122 forbids, and the one that would look right, because a gold instance is byte-stable within a day. Run v db integrity --out after the extraction and assemble against that
PACKET_SESSION packet: the audit was written outside the extraction's session window (--session-window, default 1h, always stated in the packet). The condition rows must be measured in the same session as the data they describe — re-run the audit, or state a wider window if the ordering was legitimate
PACKET_REFERENT packet: a referent does not hash, or is ABSENT — the set that traveled inside the bundle against bundle.json's digest, a component manifest against the pass row's, a missing manifest.json or certification.json, or a stream digest its three independent writers (the manifest, the bundle record, the certifier's own re-read) spell differently. Absent reds like wrong does: a check that skips a missing artifact goes green over a part with nothing behind it
PACKET_UNDECLARED packet: a component the run set declares is neither run nor named as not-run, or the bundle's own reconciliation carries a missing/unasked entry. An excluded component is DECLARED, never discovered later as an absence (VD-D122) — give the set an [[excluded]] entry with its reason, or re-run so the component lands
PACKET_STOPPED packet formed no condition: the extraction did not complete (a stopped or failed bundle), or the audit is incomplete/scope-bounded. The packet still reports, with its condition outcome the fourth pinned word stopped rather than a silence — recapture without the bound
PACKET_WRONG_INSTANCE packet: the audit measured a different engine or station than the extraction read. Two instances' condition is not one packet's
PACKET_PIN_MOVED packet: the extraction ran under one source pin and the audit measured under another, so the rows do not describe the bytes in hand. Re-run the audit under the pin the extraction ran on
PACKET_GRAIN packet: an audit row carries a class whose file grain is not declared, so the packet cannot say which table it is about. It refuses rather than dropping the row — a slice that silently drops what it cannot read reports a cleaner instance than the audit measured. Declare the grain in internal/packet, beside the contract-guide row it comes from
INCOMPLETE a verb finished without covering everything it was asked to cover, with no more specific cause: an artifact-writing verb whose manifest is not complete (every reason named in manifest.incomplete; the records written are still valid), or estimate withholding its verdict because the selection holds a skipped or unsized file (VD-D85 — the measured files are still reported)
SOURCE_PIN the engine's installed VSL sources could not be verified: its build is below the source-pin floor (VSL*1.0*68), it did not answer for a routine, its answer was malformed, or its engine family has no measured fold semantics. Raised before the first dispatch, so nothing was read
SOURCE_DRIFT they were verified and they differ: a routine is absent from the engine, or its installed source folds to a value other than the build this host was generated against — a stale routine, a partial install, or an unregistered load (a container restart reverts those). The refusal names the routine and both folds
DELTA integrity-compare's red — the ONLY red the integrity audit has (VD-D106a): one or more rows differ from the named base, reported per (class, file, sub, value) row with the expectation's identity beside the verdict, never as an aggregate count. A sanctioned install legitimately moves rows: re-baseline, then re-compare
STOPPED integrity-compare formed no verdict (VD-D106c): the subject or base artifact is incomplete or scope-bounded (--to), and certifying against a partial audit would launder it — recapture without the bound
BUNDLE_INCOMPLETE bundle: the run finished and the bundle is not whole. Findings that survive to the end of a run, each named in bundle.json — a declared component with no complete artifact; an artifact no component asked for (the direction nothing used to check: a directory left by an earlier, larger set reads as part of this bundle); or components measuring more than one instance, which nothing downstream can untangle
COMPONENT_REFUSED bundle: the run stopped at a component (VD-D121) — the component itself failed, or its certification refused at a named layer (integrity, shape, completeness, density, drift). The refusal names the component and the check that fired; that component's certification.json carries the five-layer result, every component already written is marked refused (refused.json), and the components after it were never dispatched (bundle.json's stopped.notDispatched). Fix the cause and re-run — a green run re-certifies and clears the marks
CATALOG_REFUSED the join failed its own certification (VD-D126) — a dropped plane, an entry fact that traces to no component row, a density collapse against the named previous build, a dangling or missing index document, a ranking fixture that does not replay — and the artifact is marked refused.json; a reader (catalog browse/search) raises the same code on a directory so marked or lacking a certified certification.json
BAD_DEFAULT_ORDER the artifact's manifest declares a class-absent default browse order other than attribution-first — size especially — and no reader opens it (VD-D116 rev 4)
CATALOG_DENOMINATOR catalog search was about to emit an answer with no corpus denominator or no build age — a negative answer without its denominator is a claim about the instance, not about the search (VD-D117) — and refused instead
CATALOG_RANKING catalog search found the artifact's ranking.json or index.jsonl missing or unreadable; a reader never ranks by a rule the artifact does not carry
COMPARE_CHECKSUM an input's data file does not match its manifest's sha256 — a base or subject that is not the artifact its manifest describes, or a ledger that drifted from its derivation. A deliberately edited expectation is passed with --assert, which labels it an assertion instead

Refused — exit 4 (the substrate, not the request): ENGINE_UNRESOLVED (profile resolves, driver or container does not), plus v-base's own codes — NEEDS_CONFIRM (a mutation without --yes) and the run-lock/transport refusals.

Runtime — exit 1 (a broken contract between host and engine — each one names what the engine actually sent; meeting one usually means the engine's VSL build is not the one this host was built against): NO_COMPLETENESS / BAD_COMPLETENESS · BAD_ROW / BAD_ORDINAL / BAD_FOLD · NO_MISSES / BAD_MISSES · WRONG_POPULATION (the engine answered a different population than asked — refused rather than relabelled) · NO_PROFILE / BAD_PROFILE · NO_RAWINDEX / BAD_RAWINDEX · SHORT_PAGE · BAD_LINE (a text line outside the value contract) · IDS_NO_DICTIONARY / BAD_IDS · INTEGRITY_FAIL (the envelope failed its delivery digest — the engine's stamp and this host's recomputation disagree, so bytes were lost or changed in between; the refusal prints both folds and both entry counts) / INTEGRITY_MISSING (the engine answered with no delivery digest at all, at a build that owes one) · OUT (the artifact could not be written — a local disk problem, not the engine) · SIZING_INVALID (selection size produced a row its own validator refuses — a defect in v-db, not in the selection or the engine). Two exit-1 codes are findings about the data, not defects: OVERFLOW (distribution past its distinct cap — the verdict rides the envelope with the measured lower bound) and any engine-typed U-VSL-* refusal relayed from the tables above.

Four of those codes are raised by a lower layer, and they are about the ENGINE'S IDENTITY rather than your request. SOURCE_PIN / SOURCE_DRIFT (exit 3) and INTEGRITY_FAIL / INTEGRITY_MISSING (exit 1) come from v-base, the shared client — not from this repo and not from the engine's own refusal table. Every v db invocation verifies the installed source bytes of the whole VSL build before its first dispatch, and every success envelope carries a digest stamped by the engine that the host recomputes from the decoded values before any consumer sees it. Both fail closed. The reason they exist: on 2026-08-18 an engine ran one routine older than the build this host was generated against, and every gate the producer had passed while 7,166 tables silently lost their field descriptions. A build-version floor did not catch it — an exact source check does, and a digest catches the bytes that go missing after the engine is done being right. If you meet one, the engine and the host are not the pair they think they are: converge the build (v pkg install) and re-run rather than reading the answer.

The kind vocabulary is open

Section titled “The kind vocabulary is open”

U-VSL-ROW-IXTYPE above names seven kinds, and indexes reports them as a column — but the set is not closed, and treating it as closed is how a consumer ends up silently mis-handling a kind nobody anticipated. The classifier emits whatever the dictionary declares. Measured instance-wide on vehu (9,739 cross-references), three kinds fall outside the documented set:

kind vehu what it is
kwic 45 keyword-in-context — one entry per word of the indexed value
soundex 3 a phonetic key, so the stored key is deliberately not the value
unlisted 1 declared with no classifiable type, usually on a sub-file

The rule everywhere they appear: an unknown kind rides through by name and is counted — indexes publishes it, the sweep's kinds histogram tallies it, and kindDocumented:false marks it. Every derivation from kind (walkable / enumerable / seek licensing) default-refuses a kind it does not know rather than guessing a safe-looking answer. A sub-file-heavy instance probably holds more than these three; that is the point of the design, not a gap in it.
