$$add^VSLCFG(entity, param, instance, value, out, plan)

Section titled “$$add^VSLCFG(entity, param, instance, value, out, plan)”

ADD a row that is not on file; refuses one that is. Lock, re-read, write, read back.

THE GATE (cprs-config-automation PP-D2): after every check about the request itself has passed, and before the lock - and only when something would actually be written (a request for the value a row already holds asks nobody, since *90) - Kernel is asked whether the AMBIENT user may run an option that guards this setting at this level - the rows of the reviewed table VSLCFGT ($$guards) - else the general parameter editor. Nobody is exempt: not user 1, not a programmer. On the driver path nobody signed on, so the user is whoever the caller stated; Kernel verifies a person only on the Broker path, and the change record says which of the two it was. THE RECORD (PP-D6): inside the lock, BEFORE the write, a change record is filed (who, when, what, from, to, which plan, through which option) as NOT CONFIRMED; it is marked APPLIED only after the read-back. No record, no change.

Parameters

  • entity (string) — the entity (the $$read forms)
  • param (string) — the parameter NAME (exact), or `ien
  • instance (string) — the instance (the $$read forms)
  • value (string) — the value (the $$check forms)
  • out (array) — (by ref) before ("" - the row was absent), after (the internal value read back), changed (1), option (the guarding option Kernel allowed the person through), user, record (the IENS of the change record filed), plus the $$read map
  • plan (string) — (optional) what the caller calls the plan this write belongs to; filed on the change record, never interpreted

Returns string — the internal value read back after the write

Raises

  • U-VSL-CFG-EXISTS — the row is already on file (checked INSIDE the lock; ADD^XPAR is the second line)
  • U-VSL-CFG-PKGLEVEL — the package level is read-only to this module
  • U-VSL-CFG-PROHIBITED — the definition is flagged PROHIBIT EDITING
  • U-VSL-CFG-ENTITY — the definition does not allow this entity kind (the interface does NOT check), or the entity is a domain that is not this system's
  • U-VSL-CFG-VALUE — an empty value, @, a value outside the set, a relative date, or one the validator refuses
  • U-VSL-CFG-NOTFOUND — no such parameter, entity, instance or pointed-to record
  • U-VSL-CFG-AMBIGUOUS — a name more than one record carries
  • U-VSL-CFG-TYPE — a word-processing, M-code or constant parameter
  • U-VSL-CFG-LOCK — the row's lock could not be taken in 3 seconds (another run holds it)
  • U-VSL-CFG-WRITE — the interface refused or faulted, or the read-back differs from what was filed
  • U-VSL-CFG-NOACCESS — Kernel does not allow this person: the option is in no menu tree they own, is locked by a key they lack (the detail names it) or barred by one they hold, they have no primary menu, or they are not on file, terminated or without an access code - the sentence carries Kernel's own reason (BC-D2: the one code for a refusal that is Kernel's decision)
  • U-VSL-CFG-NOGATE — Kernel could not be asked: nobody is signed on, this engine has no Kernel, the guarding option is not on file, or Kernel's test faulted
  • U-VSL-CFG-RECORD — the change record could not be filed, so the change was NOT made

Since VSL1.087.

$$avail^VSLCFG()

Section titled “$$avail^VSLCFG()”

1 iff the XPAR parameter store is reachable on this engine (a live VistA), else 0.

A capability probe: a consumer gates the live XPAR path with $$avail^VSLCFG() instead of $text-probing a Kernel routine itself, so the L4 reference (and its ICR) stays here, where XPAR is bound (waterline no-duplication). Bare-safe ($text never faults).

Returns bool — 1 iff $$GET^XPAR is present (Kernel Toolkit installed); 0 on a bare engine

Example

Since VSL1.026.

$$change^VSLCFG(entity, param, instance, expect, value, out, plan)

Section titled “$$change^VSLCFG(entity, param, instance, expect, value, out, plan)”

CHANGE a row ONLY IF it still holds expect. Lock, re-read, compare, write, read back.

CHG^XPAR is NOT a compare-and-set - it refuses only an absent row and never looks at the old value - and nothing in XPAR locks. So the comparison is made here, under this module's own lock on the row. The lock excludes other runs of THIS module only (XPAR's own editors do not honour it): the window against a hand edit is the few milliseconds between re-read and write, not zero.

Parameters

  • entity (string) — the entity (the $$read forms)
  • param (string) — the parameter NAME (exact), or `ien
  • instance (string) — the instance (the $$read forms)
  • expect (string) — the INTERNAL value the caller last read - the from-value of its plan
  • value (string) — the new value (the $$check forms)
  • out (array) — (by ref) before (the pre-image, captured INSIDE the lock), after, changed (0 when the row already held the new value), option, user, record (the change record's IENS; "" when nothing was written), plus the $$read map
  • plan (string) — (optional) what the caller calls the plan this write belongs to; filed on the change record, never interpreted

Returns string — the internal value read back after the write

Raises

  • U-VSL-CFG-ABSENT — the row is not on file
  • U-VSL-CFG-MOVED — the row no longer holds expect (the detail reports what it holds)
  • U-VSL-CFG-UNRESTORABLE — the row's CURRENT value would not be taken back by the interface, so an undo could not restore it; $$remove stays available
  • U-VSL-CFG-PKGLEVEL — the package level is read-only to this module
  • U-VSL-CFG-PROHIBITED — the definition is flagged PROHIBIT EDITING
  • U-VSL-CFG-ENTITY — entity kind not allowed by the definition, or an orphaned domain
  • U-VSL-CFG-VALUE — see $$add
  • U-VSL-CFG-NOTFOUND — see $$add
  • U-VSL-CFG-AMBIGUOUS — see $$add
  • U-VSL-CFG-TYPE — see $$add
  • U-VSL-CFG-LOCK — see $$add
  • U-VSL-CFG-WRITE — see $$add
  • U-VSL-CFG-NOACCESS — the gate - see $$add (Kernel does not allow this person)
  • U-VSL-CFG-NOGATE — the gate - see $$add (Kernel could not be asked)
  • U-VSL-CFG-RECORD — see $$add

Since VSL1.087.

$$changes^VSLCFG(param, out)

Section titled “$$changes^VSLCFG(param, out)”

The CHANGE RECORDS on file for parameter param - every write this module applied to it, oldest first.

The record is this module's own (VSL AUDIT #999001, written through VSLLOG): VistA's parameter file keeps no history. It names WHO made a change on purpose - that is what a change record is for - which is a different thing from the people a parameter's personal values belong to, whom $$list counts and never names.

Parameters

  • param (string) — the parameter NAME (exact), or `ien
  • out (array) — (by ref) out(n)=<JSON: record (IENS), event (parameter add | change | remove | set | delete), when (FileMan date/time), user (#200 IEN), userName, signon (1 = Kernel signed the person on, 0 = the caller stated the user), scope, item, from, to, plan, authority (the option Kernel let the person through), outcome (1 = applied and read back, 0 = not confirmed)>

Returns numeric — the number of records

Raises

  • U-VSL-CFG-NOTFOUND — no such parameter
  • U-VSL-CFG-AMBIGUOUS — a parameter name carried by more than one definition

Example

Since VSL1.089.

$$check^VSLCFG(entity, param, instance, value, out)

Section titled “$$check^VSLCFG(entity, param, instance, value, out)”

Would this write be accepted? Read-only: resolves, checks and validates exactly as a write would, and files NOTHING.

NEVER raises a U-VSL-CFG refusal: a plan wants every verdict, refused rows included. The validator behind it is VALID^XPARDD, which files nothing; it is reached only after every name is resolved and every empty value refused HERE.

Parameters

  • entity (string) — the entity (the $$read forms)
  • param (string) — the parameter NAME (exact), or `ien
  • instance (string) — the instance (the $$read forms)
  • value (string) — the value: a name/text/number in external form, a set code, 1/0 for yes/no, a FileMan date, or `ien for a pointer
  • out (array) — (by ref) the $$read map for the row as it stands, plus: action (add | change | none - what a write would be), internal (the value the interface would store), refusal (the U-VSL-CFG-* code a write would raise, "" when accepted), detail, option (the guarding option Kernel allowed the person through; "" when refused or never asked), user (the person Kernel was asked about)

Returns bool — 1 iff the write would be accepted (or is already in place); 0 with out("refusal") when it would not

Since VSL1.087.

do delete^VSLCFG(key)

Section titled “do delete^VSLCFG(key)”

Clear the SYS-level instance of parameter key; raise on a failed delete.

Clears the SYS instance via DEL^XPAR (which files the FileMan "@" delete sentinel). A deleted parameter then reads exactly like a never-set one ($$get returns the default). NOTE: DEL^XPAR is NOT idempotent — deleting a non-existent SYS instance raises U-VSL-CFG-DEL; guard with $$get if you need an idempotent clear.

Parameters

  • key (string) — XPAR parameter name (#8989.51)

Raises

  • U-VSL-CFG-DEL — the XPAR delete failed (detail in $$lastError)
  • U-VSL-CFG-NOACCESS — Kernel does not let this person run an option that guards the setting (see $$add)
  • U-VSL-CFG-NOGATE — Kernel could not be asked (see $$add)

Since VSL1.021.

$$get^VSLCFG(key, default)

Section titled “$$get^VSLCFG(key, default)”

Read parameter key at the SYS entity; return default when unset.

Parameters

  • key (string) — XPAR parameter name (PARAMETER DEFINITION #8989.51)
  • default (string) — value returned when the parameter is unset (optional; empty when omitted)

Returns string — the SYS-level value, or default when unset

Example

Since VSL1.021.

$$getEffective^VSLCFG(key, default)

Section titled “$$getEffective^VSLCFG(key, default)”

Read the effective value across the parameter's entity precedence; else default.

The "ALL" entity tells XPAR to walk the precedence multiple defined on the parameter (#8989.51) and return the first level that has a value — what the value would actually resolve to in context. Contrast $$get, which reads only SYS.

Parameters

  • key (string) — XPAR parameter name (PARAMETER DEFINITION #8989.51)
  • default (string) — value returned when the parameter is unset at every level (optional; empty when omitted)

Returns string — the first value found in the parameter's precedence chain, or default

Example

Since VSL1.021.

$$guards^VSLCFG(param, out)

Section titled “$$guards^VSLCFG(param, out)”

Which menu options GUARD parameter param - the options a person would otherwise have used to change it - from the reviewed table VSLCFGT.

THE GATE: a write verb asks Kernel ($$mayRun^VSLSEC) whether the person may run ONE of these options - scoped to the level being written - and, when none guards the parameter at that level, the general editor, which a coordinator is normally refused. The rows are VSLCFGT's (BC-D1, 2026-09-21): a table generated ONCE from a reference system by tools/guards/VSLCFGGEN.m - three rules, each accepting only an option that lets the person CHOOSE the level - then reviewed by a person and committed. Nothing is read from the option file or from other packages' source at run time; a reviewer reads the table. A site that wraps a setting in an option of its own adds a row. Whether the table still matches a live system is tests/VSLCFGGENTST.m, the live check.

Parameters

  • param (string) — the parameter NAME (exact), or `ien
  • out (array) — (by ref) out(n)=<JSON: option, how (entry-action | template | routine), scope ("" = any level the definition allows, else the ONE entity file the option edits at)>; out("fallback")=the general parameter editor's option, set only when NO row names the parameter

Returns numeric — the number of guarding options

Raises

  • U-VSL-CFG-NOTFOUND — no such parameter
  • U-VSL-CFG-AMBIGUOUS — a parameter name carried by more than one definition

Example

Since VSL1.089.

$$lastError^VSLCFG()

Section titled “$$lastError^VSLCFG()”

The last VSLCFG error message (the composed XPAR failure detail).

Returns string — ^TMP($job,"vslcfg","err"), or "" if none

Since VSL1.021.

$$list^VSLCFG(entity, param, personal, max, token, out)

Section titled “$$list^VSLCFG(entity, param, personal, max, token, out)”

List a parameter's rows - one entity's, or every entity's - each as a JSON object; paged.

Parameters

  • entity (string) — one entity (the $$read forms), or "" for EVERY entity holding a row
  • param (string) — the parameter NAME (exact), or `ien
  • personal (bool) — 1 = include rows stored under a USER entity; 0 (default) = count them in out("personal") and list none
  • max (numeric) — page size (0 = all)
  • token (string) — continuation token from the prior page ("" = first page)
  • out (array) — (by ref) out(n)=<row JSON: entity, kind, entityName, orphaned, allowed, instance, instanceName, value, valueName, restorable, why>; out("personal")=<count of user rows not listed, first page only>; plus the __page convention. The population is the #8989.5 "AC" index - the reading GETLST^XPAR and ENVAL^XPAR make - because ENVAL drops every empty-valued row (measured 2026-09-21: 296 parameter/entity pairs on vehu are invisible to it)

Returns numeric — the number of rows in this page

Raises

  • U-VSL-CFG-NOTFOUND — no such parameter or entity
  • U-VSL-CFG-AMBIGUOUS — an entity name carried by more than one record
  • U-VSL-CFG-TYPE — a word-processing, M-code or constant parameter

Since VSL1.087.

$$read^VSLCFG(entity, param, instance, out)

Section titled “$$read^VSLCFG(entity, param, instance, out)”

Read ONE parameter row, entity- and instance-qualified; "" when the row is not on file.

Parameters

  • entity (string) — the entity: SYS (this system's domain), PREFIX.name, PREFIX.`ien, or ien;GLOBAL( - a bare prefix other than SYS names no entity
  • param (string) — the parameter NAME (#8989.51 .01, exact), or `ien
  • instance (string) — the instance: a name/value in external form, or `ien for a pointer instance; "" or 1 for a single-valued parameter
  • out (array) — (by ref) a flat map: entity, kind, entityName, orphaned, allowed, editable, param, paramIen, instance, instanceName, value, valueName, present (1/0 - an absent row and an empty-valued row are different facts), restorable (1/0 - would the interface take the current value back), why (when it would not), institution

Returns string — the row's INTERNAL value; "" when the row is absent (out("present")=0) or empty-valued

Raises

  • U-VSL-CFG-NOTFOUND — no such parameter, entity or instance (the detail names which)
  • U-VSL-CFG-AMBIGUOUS — a name carried by more than one record - refused HERE so the parameter interface is never asked (it would prompt, and the prompt kills the engine process)
  • U-VSL-CFG-TYPE — a word-processing, M-code or constant parameter - outside this module's slice
  • U-VSL-CFG-VALUE — an instance given for a single-valued parameter, or none for a multi-valued one

Since VSL1.087.

$$remove^VSLCFG(entity, param, instance, expect, out, plan)

Section titled “$$remove^VSLCFG(entity, param, instance, expect, out, plan)”

DELETE a row ONLY IF it still holds expect. Its own entry point: @ is never a value.

Allowed where add and change are not - on a row under a disallowed entity kind or an orphaned domain, and on an un-restorable row - because deleting is how those are cleaned up. It is IRREVERSIBLE for an un-restorable row: the value reported in out("before") could not be added back.

Parameters

  • entity (string) — the entity (the $$read forms)
  • param (string) — the parameter NAME (exact), or `ien
  • instance (string) — the instance (the $$read forms)
  • expect (string) — the INTERNAL value the caller last read
  • out (array) — (by ref) before (the value deleted - the pre-image an undo needs), after (""), changed (1), option, user, record, plus the $$read map
  • plan (string) — (optional) what the caller calls the plan this write belongs to; filed on the change record, never interpreted

Returns string — "" (the row is gone)

Raises

do set^VSLCFG(key, value)

Section titled “do set^VSLCFG(key, value)”

Set parameter key to value at the SYS entity; raise on a failed write.

An ADD-OR-CHANGE at the system level, instance 1: it never compares the old value. A caller that must not overwrite a value that moved uses $$add / $$change. "@" is REFUSED as a value (since VSL1.087): XPAR treats it as the FileMan delete sentinel and would silently clear the instance. Delete is its own entry point.

Parameters

  • key (string) — XPAR parameter name (#8989.51)
  • value (string) — value to store at the SYS level

Raises

  • U-VSL-CFG-SET — the XPAR write failed (detail in $$lastError)
  • U-VSL-CFG-VALUE — @ or an empty value, or one outside the parameter's set - refused before XPAR sees it
  • U-VSL-CFG-NOTFOUND — a pointer value naming no record
  • U-VSL-CFG-AMBIGUOUS — a pointer value naming more than one record (XPAR would prompt, and the prompt kills the engine process)
  • U-VSL-CFG-NOACCESS — Kernel does not let this person run an option that guards the setting (see $$add)
  • U-VSL-CFG-NOGATE — Kernel could not be asked (see $$add)

Since VSL1.021.
