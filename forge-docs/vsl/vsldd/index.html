$$ddcount^VSLDD(scope, max, token, out)

Section titled “$$ddcount^VSLDD(scope, max, token, out)”

Per-file record counts + a sampled avg-bytes/record, paginated — the Planner's size input.

Parameters

  • scope (numeric) — a single top-level file to count, or <1 (0/"") to sweep ALL top-level files
  • max (numeric) — page size over the swept files (default: all remaining; ignored when scope>0)
  • token (string) — opaque continuation token from the prior page ("" = first page)
  • out (array) — (by ref) out(file#)=a small JSON object {recordCount,sampledAvgBytes,sampledN} per top-level file in the page, plus the __page convention (out("__page","more")/,"next")) — same projection as $$files. recordCount is one of THREE things and recordCountSource says which (VD-D79): header-claim = the FileMan-maintained entry count in the data global 0-node, O(1) and only as fresh as the filer left it; walked = an exact live $order count of top-level IENs; capped = a live count that hit $$countCap, so the number is a FLOOR ("at least N"), never the total; no-data-global = a subfile or a file with no data root, where 0 is the absence of a global rather than a count of zero. A bare integer cannot be told apart from the other two readings — this key is what makes it legible. sampledAvgBytes is the mean byte size of up to sampledN (<=20) sampled records; a subfile (or a file with no data global) reports 0/0/0. The payload is PURELY NUMERIC — no raw-DD string reaches the wire, so it needs no frame sanitization.

Returns numeric — the number of files in this page

Raises

  • U-VSL-DD-NOTFOUND — a scope>0 file has no data dictionary

Since VSL1.025.

$$field^VSLDD(file, field)

Section titled “$$field^VSLDD(file, field)”

Read one field's dictionary attributes as the rich DD-model JSON string.

emission floor: payload keys landed through *58 dinum / *59 variableTargets / *65 storageLocation+inputTransform / *66 description+screen / *84 technicalDescription+helpPrompt+title.

Parameters

  • file (numeric) — the file number
  • field (numeric) — the field number within the file

Returns string — JSON {number,name,typeSpec,dataType,pointerTarget,dinum,audit, wordProcessing,setOfCodes,storageLocation,inputTransform,computed,subfileLink, variableTargets}. variableTargets (VSL1.059) is a VARIABLE pointer's declared target-file SET, in the DD's own order — empty for every other data type, and empty-but-real for a variable pointer that declares none. typeSpec is the raw ^DD field-0-node piece 2 (the host's authoritative decode input); dataType is the coarse decode. dinum (VSL1.058) is the one edge attribute typeSpec cannot carry — measured off the field's stored input transform, marking an identity extension rather than a reference. storageLocation (VSL1.065) is the 0-node's piece 4 — the node;piece physical decode map; inputTransform (VSL1.065) is the piece-5 TAIL (the transform is M code and carries "^" freely — a single-piece read truncates at the first routine call). Both are EMPTY on a computed field, a fact not an absence: a computed 0-node's pieces 4.. are the computed algorithm, not a storage location. description (VSL1.066) is the field's ,21 word-processing lines joined with newlines — the NUMERIC subscripts only, since ,21,0 is FileMan's WP header node, not text. screen (VSL1.066) is the ,12 human message a user sees when a pointer's screen rejects a value, with screenCode carrying the 12.1 executable DIC("S") half beside it. technicalDescription / helpPrompt / title (VSL1.084) are the REST of FileMan's field prose, and they are not synonyms of description: DESCRIPTION (,21) is what a user sees on "??", TECHNICAL DESCRIPTION (,23, word-processing, header node skipped like ,21) is "for internal documentation only" per the FileMan User Manual, HELP-PROMPT (,3) is the one-line prompt shown on "?", and TITLE (,.1) is the field's alternate label. Measured by walking ^DD(file,field,*) whole-dictionary — 77 distinct subscripts, four of them prose: ,21 on 59,661 fields, ,3 on 52,906, ,23 on 7,105, ,.1 on 5,941. A SUB-FILE has no prose of its own (^DIC is top-level only), so its text is its CREATING FIELD's — completing this set completes the sub-file set with it.

Raises

  • U-VSL-DD-NOTFOUND — the file or the field has no data dictionary

Since VSL1.025.

$$file^VSLDD(file)

Section titled “$$file^VSLDD(file)”

Read one file's dictionary attributes as the rich DD-model JSON string.

emission floor: payload gained the measured dinum key at *58, the file description at *83, the identifiers at *86.

Parameters

  • file (numeric) — the file (or subfile) number to describe

Returns string — JSON {number,name,nameHeader,globalRoot,parent,dinum,recordCount, sampledAvgBytes,access{read,write,delete,laygo},deleteRestricted,packagePrefix,description, pointerIn,pointerInFiles:[...],xrefs:[{name,field,kind,walkable,triggerTargetGlobal}]}. walkable (A4) is the shared classifier's admit bit: true exactly when find will accept the name on this file number (file-level refusals fold in — VD-D55, WP sub-files; the sub-file door lifted, VD-D125). nameHeader is the directory header name (^DIC(f,0) piece 1, else ^DD(f,0) piece 1 for a subfile) — distinct from name (the ^DD NM node); pointerIn/pointerInFiles surface FileMan's own pointed-to-by index (^DD(f,0,"PT") first-level subscripts, as strings). recordCount/sampledAvgBytes are 0 placeholders in P0 (populated by the E-5 count verb); packagePrefix is a host/measured-derived placeholder — the KEY is pinned so the host binding is stable. dinum is MEASURED since VSL1.058: the file's .01 input transform sets FileMan's DINUM, i.e. its records extend the pointed-at record by IEN identity. description (VSL1.083) is the FILE's own ^DIC(f,"%D",) word-processing lines joined with newlines — the numeric subscripts only, since ^DIC(f,"%D",0) is FileMan's WP header node, not text. It is VERBATIM, banners included: a file whose description opens with a DBIA or ownership notice says so because its owner wrote that, and lifting the "real" sentence out of it is a consumer's job, never this read's. ^DIC is TOP-LEVEL ONLY, so a sub-file's description is EMPTY by construction — the key is present and blank, never absent and never the parent's text. Measured before building: 2,750 of 2,917 vehu files carry one (94.3%), 2,715 of 2,863 on foia. identifiers (VSL1.086) are the file's IDENTIFIER fields — what FileMan shows a person to recognise a record, ^DD(f,0,"ID",field) — as an array of field numbers in $ORDER; present and empty where none is declared, never absent. writeIdentifiers (VSL1.0*86) are the node's NON-numeric subscripts — WRITE-type identifiers keyed by name ("WRITE", or a label such as "AFJX NETWORK ID") whose value is M code that prints — carried as names only.

Raises

  • U-VSL-DD-NOTFOUND — the file has no data dictionary

Since VSL1.025.

$$filedump^VSLDD(file, max, token, out)

Section titled “$$filedump^VSLDD(file, max, token, out)”

Dump one file's COMPLETE DD model in a single round-trip — the rich file header PLUS a page of its fields' rich JSON.

emission floor: emits the exact $$file/$$field strings, so it widens whenever THEY do (last: *86, the file identifiers).

Parameters

  • file (numeric) — the file (or subfile) number to dump
  • max (numeric) — page size over the FIELDS (default: all remaining)
  • token (string) — opaque continuation token from the prior page ("" = first page)
  • out (array) — (by ref) the flat page — out("file")=the rich file-header JSON (the exact string $$file emits; FIRST page only, token="") and out(<field#>)=that field's rich JSON (the exact string $$field emits), plus the __page convention (out("__page","more")/, "next")). Fields are walked in $ORDER over ^DD(file,fld) with the same scalar filter and "k:<last field#>" resume token as $$fields. Loop to more=0 for the whole file — the common narrow file completes in ONE round-trip, so a full DD crawl is ~1 call/file (the A4/P1b fix).

Returns numeric — the number of FIELDS in this page (the header is not counted)

Raises

  • U-VSL-DD-NOTFOUND — the file has no data dictionary

Since VSL1.025.

$$files^VSLDD(max, token, out)

Section titled “$$files^VSLDD(max, token, out)”

List DD files/subfiles, paginated — one page of file# -> name per call.

Parameters

  • max (numeric) — page size (default: all remaining)
  • token (string) — opaque continuation token from the prior page ("" = first page)
  • out (array) — (by ref) out(file#)=<file name> for the page, plus the __page convention: out("__page","more")=0/1 and out("__page","next")=token — the dispatcher projects __page into the envelope page{more,next} block (vista-sysadmin-base §4 pagination). The token is a best-effort $order resume key ("k:<last file#>"); loop to more=0 for a lossless sweep.

$$ixcensus^VSLDD(scope, sample, max, token, out)

Section titled “$$ixcensus^VSLDD(scope, sample, max, token, out)”

The instance-wide cross-reference inventory, paginated — one row per file per named index.

Parameters

  • scope (numeric) — a single file to inventory, or <1 (0/"") to sweep every TOP-LEVEL file. Sub-files are outside the sweep by construction: the enumerability half needs a data root, and a sub-file has none — ask one directly by scope instead, where its subtree columns come back honestly unmeasured
  • sample (numeric) — stored-entry sample ceiling per cross-reference (default 20). This is the sweep's cost dial: it is a SAMPLE, never a walk, and every row carries the n it was measured at
  • max (numeric) — page size in ROWS (default 2000). Not "all remaining": a page is bounded by the envelope, and an instance has ~58,000 cross-references. A SCOPED census pages on the same cursor — #2 alone declares 485 cross-references, so a scope that answered more:0 after max rows would report a truncation as a completion
  • token (string) — opaque continuation token from the prior page ("" = first page)
  • out (array) — (by ref) out(<emission ordinal>)=<row JSON>, plus the __page convention. The row is Q3.1's column set: file, name, fields[] (the register's own KEY order), root, source (dd-ix|index-file|both), kind, walkable, condition (present|none|unmeasured — a traditional definition carries no SET CONDITION field at all, and none there would be a claim about site M this never evaluates), declaredTransform, declaredMaxLength (absent when none is declared), subtree, foreignRoot, arity[], sampled, resolved, ienPositions[], terminalIen, refutedAt, and key

Returns numeric — the number of rows in this page

Raises

  • U-VSL-DD-NOTFOUND — a scope>0 file has no data dictionary

Since VSL1.061.

$$raw^VSLDD(file, field, max, token, out)

Section titled “$$raw^VSLDD(file, field, max, token, out)”

Read one ^DD(file[,field]) subtree RAW, paginated — one byte-exact row per first-level subscript (read-fidelity step 5).

Parameters

  • file (numeric) — the file (or subfile) number whose ^DD subtree to read
  • field (numeric) — a single field number to scope to (0/"" = the whole file subtree). 0 is the wire's absent — an omitted numeric and a JSON 0 bind alike — and is legible here because field 0 cannot exist: ^DD(f,0) is the header, which the FILE scope walks as an ordinary first-level subtree
  • max (numeric) — page size in ROWS (default: all remaining; the byte budget bounds the page regardless)
  • token (string) — opaque continuation token from the prior page ("" = first page)
  • out (array) — (by ref) out(<ordinal>)=<row JSON> plus the __page convention. One row per FIRST-LEVEL subscript of the scope root: {"sub":...,"value":...,"nodes": [{"path":[...],"value":...},...]} — sub is the subscript, value the subtree root's own value (absent when none), nodes every $query descendant with its subscript path relative to the subtree root, in $query order. Field scope returns exactly ONE row (that field's whole subtree). Every subscript and value is BYTE-EXACT: an element carrying a unit >= 0x80 moves to the lossless {"b64":...} object form (the M1 value contract) — the interpreted verbs' $$clean "?" substitution never applies here, which is the point: this is the raw register the read-fidelity DD oracle folds against. Pages are byte-charged POST-ESCAPE against a 786,432-byte budget (the m7 FRAME_JSON lesson); a row that cannot ride — past the page budget alone, or its encode faulting over the engine's string frame — is emitted as the typed in-stream stub {"sub":...,"error":{"code":"U-VSL-DD-TOOBIG",...}} (U-VSL-DD-PROJFAULT for an under-frame encode failure) with the cursor advancing — the progress guarantee; the #9.4@26 silent-loss class is closed at birth here, never an empty emission. The token is the last emitted subscript, base64-guarded ("k:<b64>") — the same best-effort $order resume contract as $$files. Measured basis (vehu, whole ^DD, 2026-08-19): the largest first-level subtree is 105,121 bytes (^DD(2100,"B")) — a 7.5x margin under the budget — so the stubs are a defensive door, red-proved by a planted fat subtree.

Returns numeric — the number of rows in this page

Raises

  • U-VSL-DD-NOTFOUND — the file has no ^DD subtree, or the field is not a subscript of it
  • U-VSL-DD-INSTANCE — the instance gate refused (class undeclared/unrecognized, real-data instance, or the Kernel PROD tripwire - VD-D26/D48)
  • U-VSL-DD-POLICY — the declared per-file policy refused this read (VD-D25)
  • U-VSL-DD-AUDIT — the real-data read-audit write failed - the read refuses (fail-closed)

Since VSL1.071.
