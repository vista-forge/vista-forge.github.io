the ONE shared cross-reference classifier (schema's kind = find's admit).

$$dinum^VSLDDK(file, field)

Section titled “$$dinum^VSLDDK(file, field)”

1 iff the FIELD's input transform sets FileMan's DINUM — the stored identity fact.

Parameters

  • file (numeric) — the file (or sub-file) number
  • field (numeric) — the field number within that file (positive; ^DD(f,0) is the header)

Returns numeric — 1/0 — $$dinumTx of this field's own input transform. A FILE's DINUM fact is this predicate asked of its .01: $$dinum(file,.01), which is exactly what schema's file header emits and what put's door refuses on.

Since VSL1.058.

$$dinumTx^VSLDDK(t)

Section titled “$$dinumTx^VSLDDK(t)”

1 iff an input-transform TEXT sets DINUM (the record-number-is-the-value marker).

Parameters

  • t (string) — a field 0-node's input transform — pieces 5.. of ^DD(file,field,0). NOT piece 5: the transform is M code and carries "^" freely (^DIC calls, global refs), so a single-piece read truncates it at the first routine call.

Returns numeric — 1/0 — DINUM appearing OUTSIDE a quoted literal, which admits every assignment shape VistA actually uses (S DINUM=X · S:$D(X) DINUM=X · S (X,DINUM)=1 · S X=DINUM · passed .DINUM by reference) without parsing M

Example

Since VSL1.058.

$$enum^VSLDDK(file, name, max)

Section titled “$$enum^VSLDDK(file, name, max)”

Measure whether a named cross-reference's stored entries can be ENUMERATED.

Parameters

  • file (numeric) — the file number the name is asked of
  • name (string) — the cross-reference name
  • max (numeric) — (optional) sample ceiling, default 20 — this is a SAMPLE, never a walk: the probe stops at max entries however large the subtree

Returns string — JSON {file,name,kind,walkable,root,subtree,foreignRoot,depth, sampled,resolved,terminalIen,refutedAt,ienPositions,example,detail}. subtree is the closed vocabulary present|absent|foreign (foreign = a new-style foreign-root registration whose named subtree MEASURABLY exists at the other file's root). terminalIen is unfalsified|refuted|unmeasured — a sample can refute identity with one witness (refutedAt) but can NEVER prove it, so the positive verdict says unfalsified and carries its n. ienPositions are the below-name subscript positions that resolved to a live record in EVERY sample (an intersection — one coincidence never elects a position). kind/walkable are $$name's, verbatim: this arm re-derives no classification.

Since VSL1.044.

do enumMeasure^VSLDDK(file, name, max, m)

Section titled “do enumMeasure^VSLDDK(file, name, max, m)”

The enumerability MEASUREMENT itself, by reference — one decision, two consumers.

Parameters

  • file (numeric) — the file number the name is asked of
  • name (string) — the cross-reference name
  • max (numeric) — (optional) sample ceiling, default 20 — a SAMPLE, never a walk
  • m (array) — (by ref, cleared) kind, walkable (0/1), root, subtree, foreignRoot, depth (comma list of observed arities), sampled, resolved, terminalIen, refutedAt, ienPositions (comma list), example, detail — see $$enum for what each one means

Since VSL1.061.

$$fileOf^VSLDDK(root)

Section titled “$$fileOf^VSLDDK(root)”

Resolve a STORED global root to the file that owns it (Q2.1a).

Parameters

  • root (string) — a data global root, in EITHER form: as a variable pointer's value stores it ("ORD(101,") or as ^DIC holds it ("^ORD(101,")

Returns string — "<file>|<verdict>|<detail>" — verdict is resolved (file is the owning file number), badroot (not a global reference), unclaimed (well-formed, but no file's ^DIC entry names it) or ambiguous (two files claim it). The file number is EMPTY on every refusal — never a plausible guess

Example

Since VSL1.062.

$$ienAt^VSLDDK(gl, sub)

Section titled “$$ienAt^VSLDDK(gl, sub)”

1 iff a record subtree exists at <data root>(sub) — the IEN test.

Parameters

  • gl (string) — the file's data root as ^DIC(file,0,"GL") holds it (trailing comma)
  • sub (string) — the subscript to test as a record number

Returns numeric — 1/0 — $data at that subscript, so a HOLLOW record (no 0-node, other nodes present) still counts as live: the question is whether the subscript addresses a record subtree, not whether that record is well-formed

Since VSL1.044.

$$inside^VSLDDK(q, root, base)

Section titled “$$inside^VSLDDK(q, root, base)”

1 iff reference q lies inside the root subtree - the $QUERY containment test.

Parameters

  • q (string) — a global reference as $query returned it
  • root (string) — the CLOSED subtree root reference q must lie inside
  • base (numeric) — $qlength(root) - passed rather than recomputed, because the caller tests it once per walked node

Returns numeric — 1/0 - the global name and subscripts 0..base of q equal root's

Example

Since VSL1.060.

$$ixcond^VSLDDK(cond, code)

Does a new-style registration carry a SET CONDITION — present|none, from the two texts.

Parameters

  • cond (string) — SET CONDITION (#.11 field 1.3) — what a person typed
  • code (string) — SET CONDITION CODE (#.11 field 1.4) — what FileMan compiled

Returns string — "present" | "none"

Example

$$ixreg^VSLDDK(file, name, d)

Section titled “$$ixreg^VSLDDK(file, name, d)”

One #.11 registration's own declared facts, by reference.

Parameters

  • file (numeric) — the file number the name is asked of
  • name (string) — the cross-reference name
  • d (array) — (by ref, cleared) ien, rootFile, condition (present|none), transform (0/1 — a declared TRANSFORM FOR STORAGE, which is key-is-not-value PROVEN from the dictionary with no sampling at all), maxlen ("" when none is declared), and fields = the indexed field numbers "^"-joined in ORDER NUMBER order (the KEY order: a set would lose it and a sorted list would silently re-key the index)

Returns numeric — 1 when a registration rooted here carries this name, else 0

Since VSL1.061.

$$ixregs^VSLDDK(file, list)

Section titled “$$ixregs^VSLDDK(file, list)”

Every #.11 registration rooted at this file: list(<name>)=<ien>.

Parameters

  • file (numeric) — the file number whose ROOT holds the entries
  • list (array) — (by ref, cleared) list(<cross-reference name>)=<#.11 ien>

Returns numeric — how many registrations were found

Since VSL1.061.

$$name^VSLDDK(file, name)

Section titled “$$name^VSLDDK(file, name)”

Classify one addressable index name the way find dispatches it.

Parameters

  • file (numeric) — the file (or sub-file) number the name is asked of
  • name (string) — the cross-reference name as schema/find receive it

Returns string — "<kind>|<walkable 0/1>|<detail>" — kind from the closed vocabulary above (always the INDEX's own fact); walkable=1 exactly when find's walk admits the name ON THIS FILE NUMBER — the file-level DD facts find refuses at the door (nested-root VD-D55, word-processing sub-file) fold in here so discovery cannot contradict lookup (A4); a regular LOCAL index on a non-WP sub-file IS walkable — find walks it file-wide through the depth odometer (VD-D125 lifted the sub-file door); detail is the human reason (rides refusal messages)

Since VSL1.041.

$$nested^VSLDDK(file)

Section titled “$$nested^VSLDDK(file)”

1 iff file is in the enumerated nested-root table (VD-D55).

Parameters

  • file (numeric) — a file number

Returns numeric — 1/0 — membership in the MEASURED table {1.1, .6}: files whose top-level IENs are FILE NUMBERS (P13-rootcheck, bimodal 4-5/5 vs 0-1/5), so a top-level read renders wrong-level values; #1 excluded by name (self-referential test)

Example

Since VSL1.041.

$$qsub^VSLDDK(s)

Section titled “$$qsub^VSLDDK(s)”

one subscript as an M literal: canonic number bare, anything else QUOTED.

Parameters

  • s (string) — a subscript value

Returns string — the literal to splice into a reference: a canonic number bare, anything else double-quoted with every embedded quote doubled - so a subscript can never close the reference it is spliced into and open code (the M-MOD-036 safety property every caller that builds a reference around REQUEST data depends on)

Example

Since VSL1.060.

$$rowKind^VSLDDK(def0)

Section titled “$$rowKind^VSLDDK(def0)”

The row-level kind of ONE traditional definition node (its type piece).

Parameters

  • def0 (string) — the ^DD(file,field,1,n,0) node value

Returns string — "regular" for an empty type piece, else the type lowercased with spaces as dashes ("trigger", "mumps", "bulletin-message", ...)

Example

Since VSL1.041.

$$vtargets^VSLDDK(file, field)

Section titled “$$vtargets^VSLDDK(file, field)”

The target files DECLARED in a field's variable-pointer nodes, "^"-delimited.

Parameters

  • file (numeric) — the file (or sub-file) number
  • field (numeric) — the field number within that file

Returns string — "19^60^101.41" — piece 1 of each ^DD(file,field,"V",n,0) for NUMERIC n, in the DD's own declared order (the subscript IS the order), skipping the empty ,"V",0 node and the B/M/O/P directory subscripts; "" when none is declared

Since VSL1.059.

$$wpsub^VSLDDK(subfile)

Section titled “$$wpsub^VSLDDK(subfile)”

1 iff the sub-file's own .01 is word-processing (the measured WP rule).

Parameters

  • subfile (numeric) — a sub-file number (a multiple's piece-2 leading number)

Returns numeric — 1/0 — the projection discriminator measured at 214/214 (sweep F4): a multiple projects as a line array iff this is 1

Since VSL1.041.
