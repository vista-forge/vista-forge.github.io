$$bindInto^VSLDDB(file, sink, stats)

Section titled “$$bindInto^VSLDDB(file, sink, stats)”

Walk one LOCAL file's binding rows into sink. Returns the lines appended.

Parameters

  • file (numeric) — a file on the closed list whose class is local (#60 or #50)
  • sink (string) — the sink NAME (default: ^TMP($job,"vslddb","ln")); APPENDED to
  • stats (array) — (by ref) accumulated into, never killed — so $$m2 can compose it. Seeds and maintains rows, bound, bindings, columns, coded, resolved, binds. The vocabulary is file-agnostic: bound = rows carrying the primary binding (#60's DATA NAME, #50's NDF match), coded = rows reaching the national vocabulary (#60's NLT, #50's VA PRODUCT), resolved = rows reaching a VUID-bearing national term. bindings and columns are the two distinct-value censuses F0 published for #60.

Returns numeric — the number of lines appended (0 for an empty file)

Raises

  • U-VSL-DDB-NOTINSLICE — the file is absent from the closed list, or is national
  • U-VSL-DDB-NOROOT — the file has no ^DIC(F,0,"GL") data root on this instance

Since VSL1.026.

$$bindOf^VSLDDB(dataName)

Section titled “$$bindOf^VSLDDB(dataName)”

Decompose a file-60 DATA NAME into location, 63.04 column and data piece.

Parameters

  • dataName (string) — the raw LOCATION (DATA NAME) value, e.g. "CH;500071;1"

Returns string — "<loc>^<col>^<piece>" — ALWAYS three ^-pieces, so a malformed or absent binding is still parseable rather than something a consumer has to guess at. The parts stay strings: a column is a subscript-like token, and F0 measured that it does not identify the analyte across instances in either direction.

Example

Since VSL1.026.

$$entryOf^VSLDDB(root, ien, vs, ms, sn, out)

Section titled “$$entryOf^VSLDDB(root, ien, vs, ms, sn, out)”

Project ONE terminology entry through its per-file storage facts (MX-D2).

Parameters

  • root (string) — a glvn NAME — the file's data root (reads happen ONLY under it)
  • ien (string) — the entry's IEN
  • vs (string) — the VUID storage fact, "<node>;<piece>" (e.g. "VUID;1"; #201 "0;3")
  • ms (string) — the master-flag storage fact, or "" when the file has none
  • sn (string) — the term-status multiple's node (e.g. "TERMSTATUS"), or ""
  • out (array) — (by ref) killed, then populated: name, vuid, master, status, effective, statusN. status/effective are the term-status entry with the HIGHEST effective date — ties and undated entries resolve to the LATER row, so the selection is deterministic and hub-reproducible; statusN counts the history rows (the multiple's 0 HEADER node is not a row).

Returns string — the entry's $$rowV chain-row bytes for exactly what was read

Since VSL1.028.

$$files^VSLDDB(list)

Section titled “$$files^VSLDDB(list)”

The CLOSED, enumerated M2 file list (A-8). Returns the file count.

Parameters

  • list (array) — (by ref) killed, then populated: list(<file>)="local"|"national"|"concept" and list(<file>,"name")=<the VA file name>; concept rows also carry their MEASURED storage facts (MX-D2): list(<file>,"vuid")="<node>;<piece>", list(<file>,"master")=<node;piece or "">, list(<file>,"status")=<term-status multiple node or "">. A file absent from the array is outside the slice, and asking for it refuses.

Returns numeric — the number of files on the list

Example

Since VSL1.026.

$$m2^VSLDDB(sink, stats, drain)

Section titled “$$m2^VSLDDB(sink, stats, drain)”

Walk the WHOLE M2 slice into sink as JSONL. Returns the line count.

Parameters

  • sink (string) — a glvn NAME to write lines under, e.g. "^TMP(123,""m2"")" (default: ^TMP($job,"vslddb","ln")). Lines land at @sink@(1..n), one JSON object each. The sink is KILLED first — this verb owns it.
  • stats (array) — (by ref) killed, then populated: rows, bound, bindings, columns, coded, resolved, binds, concepts (concept files walked), vuidents (concept rows), refs (ALL ref records — one per concept file plus one per national file), n (lines), bytes, maxLine, nonAscii.
  • drain (string) — OPTIONAL entryref called as drain(sink,.stats) after each line lands; it may consume and kill @sink@(stats("n")). The P0.4 streaming seam VSLDDP uses to assemble parts without staging the tier (the VSLDDX header carries the full contract).

Returns numeric — the number of JSONL lines emitted (scope record included)

Since VSL1.026.

$$refInto^VSLDDB(sink, stats)

Section titled “$$refInto^VSLDDB(sink, stats)”

Emit the verify-take-one record for EVERY national file. Returns the lines appended.

Parameters

  • sink (string) — the sink NAME (default: ^TMP($job,"vslddb","ln")); APPENDED to
  • stats (array) — (by ref) accumulated into, never killed. Seeds and maintains refs.

Returns numeric — the number of lines appended — always the national file count, populated or not: an omitted record would make "this site has no CPT vocabulary" indistinguishable from "the walk never looked".

Since VSL1.026.

$$refRec^VSLDDB(file)

Section titled “$$refRec^VSLDDB(file)”

One national reference file's verify-take-one record — count and content hash only.

Parameters

  • file (numeric) — a file on the closed list whose class is national

Returns string — JSON {t:"ref",file,name,root,rows,vuid,hash}. rows is the numeric-IEN count, vuid the count carrying a VUID (field 99.99 at the VUID node), and hash the chained rollup described in the header. An empty file yields rows 0 and an empty hash — a fact, never a skipped record.

Raises

  • U-VSL-DDB-NOTINSLICE — the file is absent from the closed list, or is local
  • U-VSL-DDB-NOROOT — the file has no ^DIC(F,0,"GL") data root on this instance

Example

Since VSL1.026.

$$rowC^VSLDDB(ien, name, vuid)

Section titled “$$rowC^VSLDDB(ien, name, vuid)”

The canonical verify-take-one row bytes the reference rollup hashes.

Parameters

  • ien (string) — the row's internal entry number, verbatim
  • name (string) — the row's .01 value
  • vuid (string) — the row's VUID, or "" when it carries none

Returns string — ["<ien>","<name>","<vuid>"] — a three-element JSON string array under the pinned A-12 byte policy (pure ASCII; every byte >= 0x7F escapes as a lowercase Latin-1 \u00xx). Always three elements, absent rendered as "".

Example

Since VSL1.026.

$$rowV^VSLDDB(ien, name, vuid, master, status, effective, statusN)

Section titled “$$rowV^VSLDDB(ien, name, vuid, master, status, effective, statusN)”

The canonical CONCEPT chain-row bytes — the FULL record (CA-21).

Parameters

  • ien (string) — the entry's IEN, verbatim
  • name (string) — the entry's .01 value
  • vuid (string) — the entry's VUID, or "" when it carries none
  • master (string) — the master flag verbatim, "" when the file has none
  • status (string) — the latest term status — stored set-code bytes, verbatim
  • effective (string) — the winning entry's effective date, verbatim
  • statusN (numeric) — the history depth, spelled as its decimal string in the row

Returns string — ["<ien>","<name>","<vuid>","<master>","<status>", "<effective>","<statusN>"] — a seven-element JSON string array under the pinned A-12 byte policy. The concept ref chains sha256 of THESE bytes, so every field the m2/2 extension adds sits inside the integrity control — a torn part-set, a dropped row, or a parse defect in status/master cannot pass silently (CA-21). $$rowC stays the national-class rule; the two row spellings never mix.

Example

Since VSL1.028.

$$scopeRec^VSLDDB()

Section titled “$$scopeRec^VSLDDB()”

The slice's boundary declaration — the CLOSED file list, shipped with the snapshot.

Returns string — JSON {t:"scope",fmt,local:[{file,name}...],national:[...], concept:[...]}. A-8 made the list closed; putting it in the snapshot means a consumer can tell what a site was ASKED for from what it happened to have, without consulting this source.

Example

Since VSL1.026.

$$version^VSLDDB()

Section titled “$$version^VSLDDB()”

The emitted snapshot format id (the hub keys its parser off this).

Returns string — "vslddb-m2/2" — flipped in the SAME commit as the concept walk (spec section 7); the hub dual-accepts m2/1 and m2/2 because a fleet never upgrades atomically (MX-D5).

Example

Since VSL1.026.

$$vuidInto^VSLDDB(file, sink, stats)

Section titled “$$vuidInto^VSLDDB(file, sink, stats)”

Walk one CONCEPT file's rows + its ref into sink. Returns the lines appended.

Parameters

  • file (numeric) — a file on the closed list whose class is concept
  • sink (string) — the sink NAME (default: ^TMP($job,"vslddb","ln")); APPENDED to
  • stats (array) — (by ref) accumulated into, never killed — so $$m2 can compose it. Seeds and maintains concepts, vuidents, refs.

Returns numeric — the number of lines appended — the file's row count PLUS ONE: the trailing ref record is the row-set integrity control (spec section 2.3), emitted for an EMPTY file too (rows 0, empty hash): an omitted record would make "this site has no LOINC" indistinguishable from "the walk never looked".

Raises

  • U-VSL-DDB-NOTINSLICE — the file is absent from the closed list, or is not concept
  • U-VSL-DDB-NOROOT — the file has no ^DIC(F,0,"GL") data root on this instance

Example

Since VSL1.028.

$$vuidRec^VSLDDB(file, ien, name, vuid, master, status, effective, statusN)

Section titled “$$vuidRec^VSLDDB(file, ien, name, vuid, master, status, effective, statusN)”

One vuident record — the pure spelling the hub's parser reproduces.

Parameters

  • file (numeric) — a file on the closed list whose class is concept
  • ien (string) — the entry's IEN, verbatim
  • name (string) — the entry's .01 value
  • vuid (string) — the VUID, or "" when the entry carries none
  • master (string) — the MASTER ENTRY FOR VUID flag verbatim, "" when the file has none
  • status (string) — the LATEST term status — the STORED set-code bytes, verbatim
  • effective (string) — that entry's EFFECTIVE DATE/TIME, verbatim FileMan date
  • statusN (numeric) — the term-status history depth (0 when the file has no multiple)

Returns string — the wire bytes: {"effective","file","ien","master","name", "status","statusN","t","vuid"} — keys in M collation order, every value a JSON string except statusN (a count, a JSON number). Bounded (D-27): measured worst case < 400 bytes, 40x under the 16,368 sink-region ceiling.

Raises

  • U-VSL-DDB-NOTINSLICE — the file is absent from the closed list, or is not concept

Example

Since VSL1.028.
