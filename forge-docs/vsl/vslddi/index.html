$$buildfileInto^VSLDDI(sink, stats)

Section titled “$$buildfileInto^VSLDDI(sink, stats)”

Walk the #9.6/#9.7 FILE multiples — one record per (build, file) pair. Returns the lines appended.

Parameters

  • sink (string) — the sink NAME (default: ^TMP($job,"vslddi","ln")); APPENDED to, never killed
  • stats (array) — (by ref) accumulated into, never killed. Seeds and maintains buildfiles (pairs emitted, both sources).

Returns numeric — the number of lines appended. Both multiples are DINUM'd, so the pair's file number is the subscript, verbatim; the build name is the parent's .01. The transcript multiples (MESSAGES/ROUTINES/checkpoints) stay excluded — the FILE multiple is provenance, a different fact class (MX-D6, spec section 2.6).

Since VSL1.028.

$$buildfileRec^VSLDDI(src, build, file)

Section titled “$$buildfileRec^VSLDDI(src, build, file)”

One build->file provenance pair — the pure spelling the hub reproduces (MX-D6).

Parameters

  • src (string) — which KIDS file carried the pair: "9.6" (BUILD) or "9.7" (INSTALL)
  • build (string) — the build name, verbatim (#9.6/#9.7 .01)
  • file (string) — the file number, verbatim (the DINUM'd FILE-multiple subscript)

Returns string — {"build","file","src","t":"buildfile"} — keys in M collation order, every value a JSON string. Pure: no global is read, so the wire contract is pinned on an engine with no VistA at all (the $$markOf pattern).

Example

Since VSL1.028.

$$censusInto^VSLDDI(sink, stats)

Section titled “$$censusInto^VSLDDI(sink, stats)”

Walk every ^DIC-registered file — one filecensus record each. Returns the lines appended.

Parameters

  • sink (string) — the sink NAME (default: ^TMP($job,"vslddi","ln")); APPENDED to, never killed
  • stats (array) — (by ref) accumulated into, never killed. Seeds and maintains files (census rows).

Returns numeric — the number of lines appended — one per registered top-level file, populated or not: entries/lastien are the data root's HEADER pieces 4/3 verbatim (header-DECLARED, never a gate value — MX-D7), empty when the file has no ^DIC(F,0,"GL") root or no header node on this instance.

Since VSL1.028.

$$censusRec^VSLDDI(file, entries, lastien)

Section titled “$$censusRec^VSLDDI(file, entries, lastien)”

One per-file population record — the pure spelling the hub reproduces (MX-D7).

Parameters

  • file (string) — the file number, verbatim
  • entries (string) — FileMan header piece 4, verbatim — header-DECLARED, never proven
  • lastien (string) — FileMan header piece 3, verbatim

Returns string — {"entries","file","lastien","t":"filecensus"} — keys in M collation order, every value a JSON string; empty facts stay empty strings. Pure: no global is read.

Example

Since VSL1.028.

$$installInto^VSLDDI(sink, stats)

Section titled “$$installInto^VSLDDI(sink, stats)”

Walk INSTALL #9.7 — one record per entry. Returns the lines appended.

Parameters

  • sink (string) — the sink NAME (default: ^TMP($job,"vslddi","ln")); APPENDED to, never killed
  • stats (array) — (by ref) accumulated into, never killed. Seeds and maintains installs and completed (entries carrying an INSTALL COMPLETE TIME).

Returns numeric — the number of lines appended

Since VSL1.026.

$$installMark^VSLDDI()

Section titled “$$installMark^VSLDDI()”

The A-3 stability marker — read before AND after the walk; a mismatch means re-walk.

Returns string — "<installs>^<lastCompletedIen>^<completeTime>". An overnight KIDS install landing mid-walk moves at least one of the three, which is the whole point (A-3): the snapshot either re-walks or ships flagged unstable=1 and the hub excludes it from consensus.

Example

Since VSL1.026.

$$installRec^VSLDDI(ien)

Section titled “$$installRec^VSLDDI(ien)”

One INSTALL #9.7 record — the install event the hub correlates lineage against.

Parameters

  • ien (numeric) — the #9.7 internal entry number

Returns string — JSON {t:"install",ien,name,status,loaded,started,routines, completed,distributed,build,seq}. Times are FileMan date/times carried verbatim as strings; status is the internal set code of #9.7 field .02.

Raises

  • U-VSL-DDI-NOTFOUND — no #9.7 entry at that IEN

Since VSL1.026.

$$m0^VSLDDI(sink, stats, drain)

Section titled “$$m0^VSLDDI(sink, stats, drain)”

Walk the WHOLE M0 slice into sink as JSONL. Returns the line count.

Parameters

  • sink (string) — a glvn NAME to write lines under, e.g. "^TMP(123,""m0"")" (default: ^TMP($job,"vslddi","ln")). Lines land at @sink@(1..n), one JSON object each. The sink is KILLED first — this verb owns it.
  • stats (array) — (by ref) killed, then populated: packages, versions, patches, installs, completed, buildfiles (#9.6/#9.7 FILE-multiple pairs), files (filecensus rows), n (lines), bytes, maxLine, nonAscii.
  • drain (string) — OPTIONAL entryref called as drain(sink,.stats) after each line lands; it may consume and kill @sink@(stats("n")). The P0.4 streaming seam VSLDDP uses to assemble parts without staging the tier (the VSLDDX header carries the full contract).

Returns numeric — the number of JSONL lines emitted (scope and mark records included)

Since VSL1.026.

$$markOf^VSLDDI(installs, ien, at)

Section titled “$$markOf^VSLDDI(installs, ien, at)”

The marker's spelling — pure, so the wire contract is pinned without an engine.

Parameters

  • installs (numeric) — the INSTALL #9.7 entry count
  • ien (string) — the highest IEN carrying a completion time ("" when none)
  • at (string) — that entry's INSTALL COMPLETE TIME ("" when none)

Returns string — the three values joined by "^". Always three pieces: an instance with no completed install yields "0^^", never a short string a consumer would have to guess at.

Example

Since VSL1.026.

$$markRec^VSLDDI()

Section titled “$$markRec^VSLDDI()”

The stability-envelope record — the A-3 marker, expanded.

Returns string — JSON {t:"mark",installs,completed,last,name,at,marker} where marker is exactly $$installMark. The record is for the hub; the compact marker is what the P0.4 manifest carries in install.pre / install.post.

Example

Since VSL1.026.

$$pkgInto^VSLDDI(sink, stats)

Section titled “$$pkgInto^VSLDDI(sink, stats)”

Walk PACKAGE #9.4 — one record per package, version and patch. Returns the lines appended.

Parameters

  • sink (string) — the sink NAME (default: ^TMP($job,"vslddi","ln")); APPENDED to, never killed
  • stats (array) — (by ref) accumulated into, never killed — so $$m0 can compose it. Seeds and maintains packages, versions, patches.

Returns numeric — the number of lines appended

Since VSL1.026.

$$pkgRec^VSLDDI(ien)

Section titled “$$pkgRec^VSLDDI(ien)”

One PACKAGE #9.4 record — prefix, name and current version.

Parameters

  • ien (numeric) — the #9.4 internal entry number

Returns string — JSON {t:"package",ien,prefix,name,version}. The VERSION and PATCH APPLICATION HISTORY multiples ride as their OWN records (D-27), never nested here.

Raises

Since VSL1.026.

$$scopeRec^VSLDDI()

Section titled “$$scopeRec^VSLDDI()”

The slice's boundary declaration — the first line of every M0 snapshot.

Returns string — JSON {t:"scope",fmt,records:[...],excluded:[...]}. records names every record type the slice emits; excluded names what M0 deliberately leaves behind. D-16: a count whose boundary is a comment is not reproducible; a count whose boundary rides the snapshot is.

Example

Since VSL1.026.

$$siteReadable^VSLDDI()

Section titled “$$siteReadable^VSLDDI()”

Is there a VistA here at all — can a site descriptor be read on this engine?

Ask this BEFORE $$siteRec when an empty answer is an ordinary outcome rather than a fault. On an engine with no VistA the descriptor read does not return empty — it RAISES, once per attempt, and MEASURED 2026-08-13 the unwind is engine-dependent: catching it aborted the whole dispatcher suite on a bare IRIS engine after its first case (23 of 24 cases never ran, reported 0/0) while the same code on a bare YottaDB engine merely returned quietly. $TEXT of an absent routine is "" on both engines and raises on neither, which is why the question is portable and the catch is not. The Kernel routine name stays HERE, in the module that declares the integration — a caller that had to name XUPARAM itself would be a second, undeclared integration point.

Returns numeric — 1 when the Kernel entry the descriptor is built from is linkable on this engine, else 0.

Example

Since VSL1.052.

$$siteRec^VSLDDI()

Section titled “$$siteRec^VSLDDI()”

The site identity record — station, institution, domain, and the three versions.

Returns string — JSON {t:"site",station,institution,domain,fileman,kernel,engine}. station is INSTITUTION #4 field 99 for the site's own institution, carried as an opaque STRING (foia's is "050"); kernel is PACKAGE #9.4's CURRENT VERSION for prefix XU; engine is $ZVERSION, so the hub can tell a YottaDB site from an IRIS one.

Example

Since VSL1.026.

$$station^VSLDDI()

Section titled “$$station^VSLDDI()”

This site's STATION NUMBER — the one owner of the identity every key partitions on.

Returns string — INSTITUTION #4 field 99 for the site's own institution, as an opaque STRING: foia's is "050" and vehu's is "500", and a numeric coercion anywhere downstream silently merges "050" with "50" (D-15). Published so the P0.4 pusher keys its S3 prefix off the SAME read the M0 site record ships, never a second one.

Since VSL1.027.

$$version^VSLDDI()

Section titled “$$version^VSLDDI()”

The emitted snapshot format id (the hub keys its parser off this).

Returns string — "vslddi-m0/3" — m0/2 (buildfile) and m0/3 (filecensus) co-shipped in one increment, so the id the wire ever carries jumps m0/1 -> m0/3 and a bare m0/2 never ships; the hub dual-accepts m0/1 and m0/3.

Example

Since VSL1.026.
