Reproduce the stress / load tests

Note

Hand-written, not generated — the words are v-rpc-tap’s, from docs/guides/reproduce-load-tests.md. What this site guarantees about them is coverage, not correctness.

The tap’s load, latency, memory, and limitations were measured in the production-vetting campaign (P0–P5). The full results, methodology, and byte-clean proof are in the production-vetting report — read that for the numbers. This page is the operational how-to: the re-runnable scripts, what each touches, and what to expect.

Every script was live-verified end-to-end on 2026-07-03. Results land under ~/data/v-rpc-tap/vet/ (outside the repo, never committed).

The scripts

Section titled “The scripts”
script phase what it does touches mutating?
scripts/vet-p0.sh P0 cipher round-trip (Go encrypt → live $$DECRYP^XUSRB1) + authenticated signon + a fast-path RPC vehu read-only
scripts/vet-p2.sh P2 the tap-tax measurement: paired disarmed-control vs armed mode 1 vs armed mode 2, authenticated CPRS-oracle replay, 3 reps at conc 20 vehu yes → byte-clean
scripts/vet-p3.sh journal P3 $VIEW proof that the ring global ^XTMP is in a non-journaled region while real data is journaled vehu read-only
scripts/vet-p3.sh soak [secs] P3 armed mode-2, no-drain soak; samples ring depth + container memory; proves the ring is bounded vehu yes → byte-clean
scripts/vet-p4.sh P4 the method-C 5000-logical model on both bare engines; prints the model numbers bare test engines no (no install)

They share scripts/vet-lib.sh (the driver-seam exec wrapper, MAX SIGNON raise/restore, v pkg install/uninstall with the verifyClean:clean / foreignRestore:exact gates, and a pristine preview check).

Preconditions

Section titled “Preconditions”
  • Containers up: vehu, m-test-engine, m-test-iris (docker ps).
  • Credentials loaded (direnv): VISTA_ACCESS / VISTA_VERIFY present in the environment (the repo .envrc source_ups ~/data/vista-forge/auth.env).
  • Host + KIDS built: make go-build, then a per-site KIDS (make kids SPLICE_SRC=<the site's live XWBPRS.m> — see the user guide §4).
  • dist/kids/vslrtap.kids present (the mutating scripts install it; they refuse to run if the engine is not pristine, and they tear down on failure via a shell trap).

Run them

Section titled “Run them”

Each mutating script ends by restoring the pre-image (--restore --verify), clearing the ring, restoring MAX SIGNON to 30, and asserting a pristine preview — so a completed run leaves the gold master exactly as it found it. A failed run tears down the same way.

What to expect

Section titled “What to expect”
  • vet-p0 — PASS: engine $$DECRYP round-tripped the Go ciphertext and a real DUZ with a 0 ms fast-path RPC.
  • vet-p2 — a summary table; the p50 taxes are the stable statistic (≈ +48 µs names-only, similar full-payload p50), and throughput cost < ~4 %. The mean taxes are noisy (±~100 µs run to run) because the oracle contains real 40–50 ms RPCs — read p50.
  • vet-p3 journal — ^XTMP → TEMP|0 (non-journaled), ^DPT → DEFAULT|2 (journaled).
  • vet-p3 soak — ring grows then plateaus at the per-job depth cap; container memory stays well inside the 2 GiB budget; 0 failures.
  • vet-p4 — a two-column YDB/IRIS table of per-message model costs + 5000-ring sweep timings (all inside the 2 s reaper SLO); the suite’s 31 correctness assertions pass.

The one operator-run phase

Section titled “The one operator-run phase”

P1 (the CPRS fidelity anchor) is not scripted: a human drives a real Delphi CPRS client through the armed tap while the host arms/drains/extracts. The procedure and the resulting workload oracle are in cprs-workload-oracle.md. Its captured RPC sequence is what vet-p2.sh replays.

Scope note (honest limits)

Section titled “Scope note (honest limits)”

5000 real concurrent sessions is infeasible on this hardware (vehu ≈ 119 via Kernel MAX SIGNON, foia ≈ 8 via IRIS-CE serialization). vet-p4.sh is therefore a labelled model validated against the real curve — never a claim of 5000 real sockets. The full limitations statement is in the report §consolidated limitations and p4-extrapolation.md §5.
