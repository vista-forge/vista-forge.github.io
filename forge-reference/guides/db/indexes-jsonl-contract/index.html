The index-sweep artifact — JSONL input contract

Note

Hand-written, not generated — the words are v-db’s, from docs/guides/indexes-jsonl-contract.md. What this site guarantees about them is coverage, not correctness.

v db indexes --all --out <dir> writes two files: indexes.jsonl (one JSON object per line, one line per cross-reference) and manifest.json (what the run was and whether it finished).

One shape, two scopes. v db indexes <file> --key-sample N --out <dir> writes the same two files for ONE file, with the key columns measured (§5) — that artifact is what --explain’s licensing rule reads. A consumer reads both the same way; manifest.request.scope says which it holds (instance or file:<n>), and details carries the denominators for that scope.

This document is the contract for a downstream consumer. It exists so nobody has to read v-db’s source to know what a field means, or guess what a missing one implies. It is the sibling of the catalog contract, and deliberately the same shape: one manifest, one complete flag to branch on.

What this artifact is: every cross-reference declared by every top-level file of ONE VistA instance at ONE moment — where its entries are stored, whether anything is stored there, whether a seek is admitted, and how the stored keys are shaped.

What it is not: a query plan, a ranking, a judgement, or a claim that a key equals the value it indexes. That last question is not measured here — see §5.

Measured on the gold engines, 2026-08-14: vehu 9,739 cross-references across 2,879 files in 5 pages / ~4 s; foia 9,699 across 2,826.

1. Why this is not schema

Section titled “1. Why this is not schema”

v db schema <file> lists a file’s cross-references from the traditional ^DD(file,field,1,n,0) definition nodes. FileMan has a second register — the new-style INDEX file #.11 — and schema has never read it. On vehu, #2 PATIENT declares 485 cross-references across both registers where schema shows 384; #44 shows 19 against 14.

Every row here carries source, saying which register declared it.

2. indexes.jsonl — one line per cross-reference

Section titled “2. indexes.jsonl — one line per cross-reference”
field always? meaning
file yes FileMan file number, as a string (".11", "757.02"). A decimal-looking label, not a number — do not parse it into a float and back
name yes the cross-reference’s name. The row is keyed by (file, name), not by definition row: #2’s AR and BS5 are each defined on two fields and appear once
fields yes every field the name is keyed on, in the register’s own key order. An empty list is real — a record-level index is defined on the record, not a field
root when measured where the entries are stored, as measured — never assembled from the data root and the name
source yes dd-ix (traditional ^DD) · index-file (a #.11 registration) · both
kind yes the engine classifier’s own word — the same reading find dispatches on. The vocabulary is open (§4)
kindSource yes classifier on every sweep row. The per-file verb has a weaker second source and says so; this one never does
kindDocumented yes false when kind falls outside this catalog’s documented vocabulary. Nothing derives from an undocumented kind
walkable when measured whether a seek is admitted. Absent means unmeasured, never “no”
condition yes present · none · unmeasured. A conditional cross-reference holds a subset of the file (§6)
declaredTransform when true the #.11 registration declares a TRANSFORM FOR STORAGE — the key is proven not to be the field’s value, from the dictionary, with no sampling
declaredMaxLength when declared the registration’s declared key-length ceiling. Absent, never 0
subtree yes present · absent · foreign · unmeasured — whether a subtree named after this cross-reference exists under the file’s data root on this instance (§3)
foreignRoot when foreign the file whose root actually holds the entries
arity when sampled the subscript depths seen in the sample. More than one value means the entries are ragged
sampled, resolved yes how many stored entries were read, and how many resolved to a live record. 0 is a measurement and rides the stream
ienPositions when elected every below-name subscript position that addressed a live record in every sampled entry — an intersection, so one coincidence never elects a position
terminalIen yes unfalsified · refuted · unmeasured — whether the last subscript is the record id (§3)
refutedAt when refuted the entry that refuted it. A verdict carries its evidence
key yes unmeasured on every row of this artifact (§5)
unknownKeys only if present keys the engine sent that the writing build had no rendering for. Never dropped — they ride verbatim in the line and are counted in the manifest

Absence is meaningful and is never the same as zero or false. walkable absent means nothing measured it; declaredMaxLength absent means none is declared; foreignRoot absent means not foreign-rooted.

3. Three things this measures that a dictionary read cannot

Section titled “3. Three things this measures that a dictionary read cannot”

walkable and subtree are different properties, and on this database they disagree most of the time. A seek needs a mechanically-maintained cross-reference; storing entries needs nothing but a site routine that writes them. On vehu: 5,665 of 9,739 admit a seek, and 4,919 store nothing at all. subtree: present with walkable: false is the signal to reach for v db find <file> <name> --raw; subtree: absent is a measurement about this instance, not an error.

The record id is not reliably the last subscript. #100 AR carries the order number at position 3 of 4, with a trailing sequence number a walk assuming “last subscript = record id” would have read as a record. ienPositions is measured, terminalIen: refuted names it out loud, and refutedAt carries the witness.

sampled is a sample, never a walk. Every enumerability column (subtree/arity/ienPositions/terminalIen) is measured over at most details.sample stored entries per cross-reference (default 20, --sample N).

4. kind is an OPEN vocabulary

Section titled “4. kind is an OPEN vocabulary”

The documented kinds are regular, mumps, trigger, dangling, compound, record-level, computed-key, foreign-root, mnemonic, bulletin-message. Anything else rides through by name, is counted in manifest.details.undocumentedKinds, and nothing in v-db derives anything from it — neither should a consumer. Measured on vehu: kwic (45), soundex (3), unlisted (1).

5. The key columns — measured per file, never in a sweep

Section titled “5. The key columns — measured per file, never in a sweep”

In a --all artifact, key is unmeasured on every row, and says so rather than omitting the cell. Deciding whether a stored key IS the indexed field’s value costs one record read per sampled entry per cross-reference; across ~8,300 files that is a different order of cost from the whole sweep.

In a per-file artifact it is measured, and four more keys ride with it: keySampled (the n), minKeyBytes / maxKeyBytes (the measured key length range) and uniformLength, plus keyWitness when a transform was PROVEN and declaredTransform when the dictionary declares one. Ask one file:

…and read that answer asymmetrically: identity is unfalsified, never proven (300 entries agreed and every key stopped at exactly 30 bytes, because stock FileMan stores $E(X,1,30)), while transformed is proof and names its witness.

maxKeyBytes is the one to act on. An unfalsified identity means no sampled value was cut, so whatever length the index truncates at is at least the longest key seen — which makes a prefix inside that length safe, and makes the minimum (2 bytes on #44 B) a bound on nothing useful.

6. manifest.json — the run, and whether to trust it

Section titled “6. manifest.json — the run, and whether to trust it”

Check complete first. It is true only when nothing was absent, failed or incomplete. --one-page sets it false and says so in incomplete.

details.filesRepresented is not the number of files swept. It counts the files the rows came from — every top-level file declaring at least one cross-reference (2,879 on vehu). The sweep visits more than that; a file declaring none emits no row. Sub-files are outside the sweep entirely (the enumerability half needs a data root); ask one by number instead, where its subtree columns come back honestly unmeasured.

details.declared is the denominator, listed is what was written. A run filtered with --kind/--walkable is a deliberate subset — like export --files — so it stays complete: true, records the filter in request, and carries the number it was cut from in declared.

The roll-ups carry every value of each closed vocabulary, zeros included (sources, seek, stored): a value with no rows is a measured zero, not an absent key.

instance is the identity, and station is a STRING — foia’s is "050"; coercing it to a number silently merges it with "50".

sha256 covers indexes.jsonl exactly, so a consumer can verify the stream it holds is the stream the manifest describes.

7. Stability

Section titled “7. Stability”

The generator is gated: two recorded fixtures are replayed on every make check and the regenerated artifact must be byte-identical to the committed one, with writtenAt the only field allowed to move — and the allowance is narrow, not blanket, so a second varying field reds. The gate is red-proven by planting a renamed engine key and a changed page total.

The stream is also pacing-invariant: the same sweep run with --pace 500ms produced the identical sha256.

contract in the manifest is the shape version. It changes when this document does.
