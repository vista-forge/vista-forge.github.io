The catalog artifact — JSONL input contract

Note

Hand-written, not generated — the words are v-db’s, from docs/guides/catalog-jsonl-contract.md. What this site guarantees about them is coverage, not correctness.

v db census --out <dir> writes two files: census.jsonl (one JSON object per line, one line per file) and manifest.json (what the run was and whether it finished).

This document is the contract for a downstream consumer — the bundle analysis today, anything else tomorrow. It exists so nobody has to read v-db’s source to know what a field means, or guess what a missing one implies.

What this artifact is: a measurement of ONE VistA instance at ONE moment — which files exist, how many records each really holds, and which ones cannot be read normally.

What it is not: an analysis, a ranking, a judgement, or a comparison. v db browses, extracts, catalogs, scopes, queries and manages one instance; drawing conclusions from this artifact is the consumer’s job, deliberately.

1. census.jsonl — one line per file

Section titled “1. census.jsonl — one line per file”
field always? meaning
file yes FileMan file number, as a string (".11", "757.02"). It is a decimal-looking label, not a number — do not parse it into a float and back
name yes the file’s name. A raw JSON value, not always a string: an oversized or unreadable name is replaced by a typed object rather than truncated
state yes the closed vocabulary in §2. Always present, derived once
walked when state=walked the honest record count — obtained by walking the data, not by reading a stored counter
hollow when state=walked subscripts with no 0-node: they exist in the tree but hold no record
claimed when the header has one FileMan’s own stored count. Reported, never trusted — see §3
sampledAvgBytes, sampledN only with the size pass mean record size and how many records were sampled (≤20)
estimatedBytes only with the size pass sampledAvgBytes × walked. An estimate
perPatient only with --per-patient walked ÷ the patient file's walked count
unknownKeys only if present keys the engine sent that this host build did not know. Never dropped silently
detail, error only if present why a non-walked state happened

Absence is meaningful and is never the same as zero. Numeric fields are emitted only when measured: a missing walked means not measured, and "walked":0 means measured, and it is zero. This is deliberate — an earlier shape collapsed the two and it was a defect (VD-D67).

2. state — the closed vocabulary

Section titled “2. state — the closed vocabulary”

Every file gets exactly one. There is no “other”, and no file is omitted.

state meaning what a consumer should do
walked read normally; walked is the honest count use it
nodata registered in the dictionary, no data root it has no rows; not an error
nested-root its top-level subscripts are file numbers, not records — the data nests a level down (#.6, #1.1) do not treat top-level keys as rows
subfile-anomaly registered as a top-level file but shaped like a sub-file (#4.05, #2006.52) do not assume a flat record set
denied policy refused this file on this instance absence here is authorization, not emptiness
row-error the engine returned a row this host could not decode investigate — this is the one that means something is wrong
unclassified should never appear; present so it can never be silent treat as a defect and report it

On vehu today: 2,913 walked · 2 nested-root · 2 subfile-anomaly · 2 nodata · 0 denied · 0 row-error · 0 unclassified, over 2,919 files.

3. claimed vs walked — the reason this artifact exists

Section titled “3. claimed vs walked — the reason this artifact exists”

FileMan stores a record count in each file’s header. It is frequently wrong. Measured on vehu: 121 of 2,919 files disagree, and not by rounding —

file walked (real) claimed (header)
#81 CPT 2,351 26,877
#100.4 OE/RR ERRORS 55 10,055
#2006.96 IMAGE INDEX CONVERSION 754 0

Both numbers ship, side by side, always. Use walked. claimed is published as a free integrity signal — a large divergence is a finding about that file, not noise.

4. manifest.json — the run, and whether to trust it

Section titled “4. manifest.json — the run, and whether to trust it”

Check complete first. It is true only when nothing was absent, failed or incomplete. When it is false, exactly one of absent / failed / incomplete says why, in a sentence.

instance is the identity, and station is a STRING. foia’s is "050"; coercing it to a number silently merges it with "50". siteState is ok | unreadable | undeclared — undeclared means an engine older than VSL*1.0*52, which is not the same fact as a site that could not be read.

sha256 covers census.jsonl exactly, so a consumer can verify the stream it holds is the stream the manifest describes.

details.measured names every optional pass that did not run, and why — so an absent column is legible rather than mysterious.

5. What the numbers do and do not claim

Section titled “5. What the numbers do and do not claim”
  • walked is a measurement, cross-checked at M8 by three independent instruments agreeing on all 15 oracle files.
  • estimatedBytes is an estimate from ≤20 sampled records per file. A file with skewed record sizes is sized coarsely. It is not a disk-usage figure.
  • claimed is a claim, not a measurement (§3).
  • The catalog is one instance at one moment. Re-run it tomorrow and it will differ — measured: 6 of 2,919 rows moved on vehu in 8.5 hours, three of them because of activity the measuring session itself caused.
  • No labels, no classification, no ranking. v db carried an ndd label join until 2026-08-13 and it was removed: the national dictionary is incomplete and untrusted, and an untrusted source must not be joined into an artifact whose charter is that every cell is a fact or a named non-fact. A consumer wanting labels joins them itself, against its own copy, at whatever trust level it can defend.

6. Stability

Section titled “6. Stability”

The generator is gated: a recorded fixture is replayed on every make check and the regenerated artifact must be byte-identical to the committed one, with writtenAt the single excluded field — and that exclusion is itself checked, so a second varying field reds. A consumer can therefore rely on the shape not moving without a deliberate, reviewed change.

contract in the manifest is the shape version. It changes when this document does.
