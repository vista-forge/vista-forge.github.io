1. Introduction

Section titled “1. Introduction”

1.1 What v-db is

Section titled “1.1 What v-db is”

v-db is the FileMan domain of the v CLI — a modern, contract-governed command surface over VistA’s database engine. It has two halves separated by the vista-forge m/v waterline:

  • Host (Go, this repo): the command surface (dbcli/), the engine-neutral data-dictionary model, artifact writers, and the generated seam bindings (internal/vsldd). The host reaches an engine only through v-base over the m-driver-sdk client — one transport artifact, no hand-rolled engine access.
  • Engine (M, in v-stdlib): the VSLDD (dictionary) and VSLROW (data) dispatch modules — the only code that touches ^DD/^DIC and the data roots. Shipped to an instance as KIDS builds (VSL*1.0*nn).

The same binary runs standalone (dist/v-db <verb>) or mounted under the umbrella as v db <verb>; the surfaces are identical and the transcripts in the appendix print the mounted spelling.

The design stance, stated once and visible in every verb: measurements over claims. Record counts are walked, never read from the header; every paged read carries a completeness block; a refusal is typed and named, never an empty result; and anything the tool did not measure says unmeasured rather than guessing.

1.2 FileMan, in modern database terms

Section titled “1.2 FileMan, in modern database terms”

VA FileMan (the DI package, version 22.2) is VistA’s database management system. In mainstream vocabulary it is best described as a schema-driven, multi-model embedded DBMS built on an ordered key-value store, with the schema held in the store itself and all integrity enforced in the write path of its API rather than by the storage engine. Precisely:

The storage engine is the M global store. A global is a persistent, sparse, ordered tree: every node is addressed by a composite key of typed-less subscripts (^DIC(4,500,0)), stored in subscript collation order, supporting exact get/set, ordered traversal ($ORDER — the equivalent of a B-tree range scan), and nothing else — no schema, no types, no secondary access paths, no declarative queries. This layer is directly comparable to an ordered key-value engine such as LMDB or FoundationDB: everything above it is convention.

FileMan is the layer of convention, and its schema is data. The data dictionary (^DD) and the file catalog (^DIC) are themselves globals holding the metadata for every file — the exact analog of information_schema / pg_catalog, with the important difference that it is writable data, site-extensible at runtime, and the single source of truth the engine half of v-db walks. On the dictionary FileMan defines:

  • Files (numbered — #2 PATIENT, #200 NEW PERSON) — tables. Each file owns a global root (^DIC(4, for #4), and the root is measurably a unique key for the file (2,917/2,917 on vehu, 2,863/2,863 on foia, zero collisions).
  • Records keyed by IEN (internal entry number) — the row id, a decimal string subscript. .5 is a real IEN. Physical layout: the record is the subtree under <root>(<ien>,….
  • Fields — columns. Each field declares a physical storage address — node;piece: which node of the record subtree, and which ^-delimited piece of that node’s string. Storage is untyped bytes; several columns are packed into one delimited string per node. There is no NULL distinct from the empty string at the storage layer; “the node is absent”, “the piece is empty” and FileMan’s @ are states the API layer distinguishes.
  • Types as write-path code. A field’s “type” (free text, numeric, date, set of codes, pointer…) is realized by its input transform — a fragment of M executed when a value is filed, combining the roles of a type coercion, a CHECK constraint and a domain. Nothing re-validates data written by code that bypasses the API — a bare SET into the global is invisible to every constraint, which is why v-db treats stored claims as claims.
  • Multiples (sub-files) — nested tables, recursively: a field whose value is itself a file (#4’s field 4 CONTACT is sub-file #4.03), stored inline under the parent record’s subtree. This is the document-model half of FileMan: a record is a tree, and a faithful export of one record is a nested document, not a flat row.
  • Pointers — foreign keys: a field storing the IEN of a record in one declared target file. FileMan maintains a reverse catalog (the “pointed-to-by” register) which is a claim, not a constraint — v db refs --verify audits it. Variable pointers are polymorphic foreign keys: the stored value is ien;root — record number plus the target file’s global root — with a declared (but, measured, incomplete) target set. DINUM fields are identity foreign keys: the pointed-at IEN is the record’s own IEN.
  • Cross-references — secondary indexes, maintained by SET/KILL logic embedded in the write path (i.e., trigger-maintained indexes, not storage-engine indexes). They live in two registers: traditional definitions in ^DD, and the new-style INDEX file (#.11). A “regular” cross-reference stores <root>("<NAME>",<key>,<ien>). But the kind vocabulary is open: MUMPS-type cross-references execute arbitrary site-authored M and may store anything anywhere (or nothing — 70% of the non-walkable ones store nothing under the file’s root), and on real files they dominate: 354 of #2’s 386 cross-references are site-authored.
  • Word-processing fields — CLOBs, stored one line per node.
  • Computed fields — virtual columns: M expressions evaluated at read time, with no storage location.
  • Auditing and access control — field-level audit trails, and file/field access codes checked by the API (DUZ(0), $$CANDO^DIAC1) — GRANT-like, enforced only on the API path.

The same architecture, drawn — FileMan’s name for each part on the left of each label, the mainstream name v-db uses in parentheses:

Two properties the drawing should make obvious: everything — catalog, data, indexes — lives in the same ordered key-value store, distinguished only by convention; and every guarantee (types, indexes, counts) is maintained by the write path, so anything that bypasses the API leaves no trace in the guarantees — which is why v-db measures instead of trusting.

What FileMan does not have is as defining as what it has: no query language (reads are API calls — ^DIC lookup, DIQ retrieval, the DDR listers — and the caller is the query planner), no transactions in the API (each filing is an in-place global update; the engines’ transaction processing exists but FileMan does not use it), no cost model or EXPLAIN, no enforced referential integrity on delete, and no honest statistics (the record count in a file’s header is maintained by convention and measurably drifts). v-db’s verb set is shaped around exactly these absences.

1.4 What v-db adds that FileMan does not have

Section titled “1.4 What v-db adds that FileMan does not have”

Beyond wrapping the surfaces above, five capabilities have no FileMan counterpart at all (the effort’s coverage map dispositioned all 26 FileMan access surfaces): honest walked record counts (count, census), value/depth distributions (distribution), the one-walk per-column population profile (fields-profile), a read plan (--explain), and a read face for word-processing fields (text --show). A sixth is a different kind of addition: the raw index walk (find --raw), which reads the stored entries of the ~81% of cross-references a safe seek must refuse — the door to access paths FileMan maintains but never exposes.

2. Architecture

Section titled “2. Architecture”

2.1 Host and engine, and the driver seam

Section titled “2.1 Host and engine, and the driver seam”

Every command is one or more engine visits: the host sends a command string over the m-driver-sdk docker (or remote) transport, the engine-side dispatcher (VSLAPI → VSLDD/VSLROW) executes one bounded page of work, and the reply comes back as a single JSON envelope. Consequences that shape the surface:

  • Everything is paged. The envelope is one M string; the practical page payload ceiling is 786,432 bytes (derived from the smaller of the two engines’ string limits). Work that cannot fit a page is either paged with a cursor or refused typed (TOOBIG for one oversize value, TOOWIDE for a dictionary wider than a page, TREESIZE for a record subtree).
  • The command line is also bounded — vbase.MaxCommandLen (30 KB). A large --iens list is chunked host-side into a paged conversation.
  • Parameters are positional at the seam and the dispatcher binds at most 12; a numeric parameter has no “absent” distinct from 0 on the wire. Both are why capability checks are build floors (§2.8), not probes.

2.2 The contract and the JSON envelope

Section titled “2.2 The contract and the JSON envelope”

The machine-readable surface is generated, not documented by hand: dist/v-contract.json enumerates every command, flag, argument, default and help string, and a contract test (schema_contract_test.go) gates it against the live grammar. Every command emits one envelope shape:

On failure data is replaced by error (code, exit, message, hint). command is the stable grammar path, safe to switch on. Output selection: -o text (TTY-styled), -o json, or auto (default — text on a TTY, JSON when redirected). Executed example: appendix A.16.

2.3 The completeness discipline

Section titled “2.3 The completeness discipline”

No data page travels without an account of how it was produced. Every paged read carries a completeness block — population, examined, filtered, emitted, distinct, stopped — and a page block (more, next). The population field also fixes the emission order (§6.2). The point is epistemic: a page that stopped on a budget says which budget; a filter count never detaches from its denominator; an index walk’s emitted vs distinct shows duplication instead of hiding it. Artifacts (§2.7) carry the merged block in their manifest, so a truncated artifact says so.

2.4 Bounds, budgets and cursors

Section titled “2.4 Bounds, budgets and cursors”

Four per-page budgets bound every engine visit: rows (--max), bytes (--bytes), candidates examined (--examined), and engine time (--elapsed). Whichever trips first names itself in stopped. Continuation is an opaque token (--token, passed back verbatim); a token is bound to its request shape and refuses (U-VSL-ROW-STALE) if replayed against a different one. Fold verbs (count, census, distribution, fields-profile) run multi-page to completion by default; --one-page stops after one page and prints the token, and --pace inserts host-side spacing between visits for politeness against a live instance. --timeout bounds one visit (default 180 s) and aborts a hung page engine-side — it does not cap a multi-page command.

2.5 The run-lock

Section titled “2.5 The run-lock”

One v tool conversation holds the engine run-lock at a time (inherited from v-base; one bracket per verb). --lock-wait (default 30 s) says how long to queue for it; 0 refuses immediately when busy (exit 4). Long sweeps hold the lock for their duration — see §7.

2.6 Authorization — policy and the @mutates gate

Section titled “2.6 Authorization — policy and the @mutates gate”

Enforcement is engine-side, at every data verb’s door — never a host flag:

  • The instance declares a class (demo | real). An undeclared or unrecognized class refuses data verbs; a real instance additionally fail-closes reads if the read-audit write fails, and the Kernel PROD tripwire is checked.
  • Writes are default-deny per file (VD-D25): put/edit/delete/ reindex/text require an explicit write:<file>=allow declaration. Reads are allowed unless denied.
  • Every mutating verb is marked @mutates engine-side and refuses without confirmation (--yes) and attribution — the refusal is client-side and engine-side, so no transport shortcut bypasses it.
  • delete adds a third layer: it is a dry run by default, reporting the exact data nodes that would go; only --commit --yes actuates.

2.7 Artifacts and manifests

Section titled “2.7 Artifacts and manifests”

Verbs that can write to disk (export, census, refs --all, indexes --all, rows, find, distribution, fields-profile) write JSONL plus a manifest: which instance answered (station, domain, FileMan/Kernel versions), what was requested, what was not written (named incompleteness — --one-page, --max-pages, a refused fold), a sha256 of the data stream, and byte/record counts. Consumers verify before citing: --explain checks a supplied artifact’s manifest, verb, digest, instance and scope, and refuses (ARTIFACT_*) rather than quote a stale or foreign file. Formal contracts: indexes-jsonl-contract.md, refs-jsonl-contract.md, catalog-jsonl-contract.md.

The complete-schema bundle (VD-D83/VD-D84) is the assembly of these artifacts, not a new one. It is produced by bundle from a committed run set: each component lands in its own directory with its own manifest, and bundle.json records per component its argv, measured cost, projection tier and manifest digest, plus what was not run and both directions of the set↔artifact reconciliation. A busy run-lock refuses before the first sweep. (Until 2026-08-23 the assembler was scripts/dd-bundle.sh, 32 hand-written invocations in bash; VD-D95 retired it.) There is no merged super-artifact: every artifact stays verifiable through its own manifest, and the bundle is the record of how they were produced. Executed: A.18 — a whole-instance bundle on vehu, every pass timed, bundle.json shown.

2.8 Engine capability floors — and there are two kinds

Section titled “2.8 Engine capability floors — and there are two kinds”

The host checks the installed VSL build before sending a flag the dispatcher would silently ignore (an older engine does not refuse an unknown parameter — it answers the wider question with ok:true, which is worse than an error). A floor miss is the host-side AGG_SINCE/IENS_SINCE family, raised before any engine visit.

Kind 1 — an existence floor (@since): the label is not there. Below it the verb cannot be called at all.

capability floor

Kind 2 — an emission floor (@emits-since): the label is there and answers a POORER payload. This class exists because of a measured incident and it is the more dangerous of the two: an existence floor refuses, an emission floor succeeds and hands back less than the caller’s contract promises.

The 2026-08-18 regression is the case in point. VSL*1.0*66 ships the field description and screen reads; on an engine at *65 the same label still answers ok:true for every field — with the descriptions simply absent. Thirty- two export passes exited 0, reported complete:true, matched their own digests, and shipped a payload 8.6 MB lighter across 7,166 tables. Nothing in the existence-floor mechanism could see it, because the verb existed.

The fix (VSL*1.0*72) gave an emission contract a version of its own: a label declares @emits-since beside its @since, the generated binding gates on max(since, emits_since), and a review gate reds when a dispatched label’s payload description changes without an explicit re-record.

2.10 The verified channel — what runs on every dispatch

Section titled “2.10 The verified channel — what runs on every dispatch”

Two regimes run on every invocation of every verb, not as an audit somebody schedules. Together they close the band between “the engine’s stored data” and “the bytes this host decoded”, which no manifest signature can vouch for on its own — a writer’s own digest attests what the writer saw, not what the engine sent.

E1 — the source pin (VSL*1.0*68). Before its first dispatch, the client folds the installed source bytes of 62 engine routines (22 VSL* plus 40 STD*) and compares them against a generated pin table. A mismatch refuses SOURCE_DRIFT / SOURCE_PIN, fail-closed, naming the routine and both folds. The pin is exact source identity, not a version string, so it subsumes a build floor: an unregistered routine load, a partial install or a hand-patched routine is caught even when the reported version is right.

⚠️ One cross-engine fact rides in it, and it is not a quirk to work around: YottaDB folds bytes and IRIS folds code points. One source therefore has two legitimate expected values, and the host compares by family. A pin scheme that assumed one fold per source would refuse every IRIS instance.

The pin is why a SOURCE_DRIFT refusal is a good outcome and a common one after an engine ship: every deployed consumer is pinned below the new build until its pin table is regenerated. It names four suspects — engine, committed pin table, the composed module pin, and the built binary — and the built binary is gitignored, so a repo fully current in git can still refuse every read.

E2 — delivery digests (VSL*1.0*70). The engine stamps every ok envelope at the framing entry; the host recomputes at dispatch time and raises INTEGRITY_FAIL / INTEGRITY_MISSING, fail-closed at the pinned floor. This verifies the truncation, escape and transport band on every page of every verb. Measured overhead: ≈ 0.28 s per MB of page payload.

What this means for a consumer: an artifact’s sha256 says the file on disk matches what the writer wrote. E1 and E2 say the writer was reading the engine it claims, through code that is byte-identical to the code the host was generated against, over a transport that did not truncate or re-escape. Those are different guarantees and an artifact needs all three.

2.11 Independent oracles — how a read is checked against storage

Section titled “2.11 Independent oracles — how a read is checked against storage”

A read cannot vouch for itself. Two readings that share a code path are one oracle presented as two, which is the failure the per-pass dictionary fingerprint demonstrated: it was byte-identical across a regression that removed 8.6 MB of payload, because it fingerprints a narrower slice of the dictionary than the payload draws on. Fidelity is therefore only ever measured against a source that does not share the path under test.

Three instruments exist, and the third shares no code with the first two.

plane instrument what it compares
data the three-way join the interpreted value × the node;piece the dictionary declares for that field × the piece actually sitting at that position in the raw stored node
dictionary the raw ^DD subtree read (raw^VSLDD, VSL*1.0*71) the exported field surface against a $query walk of ^DD(file[,field]), run through two independent channels — an engine-exec fold and the product verb
both, out of band an engine-native dump no driver, no envelope, no JSON encoder, no VSL code at all — parsed offline and compared byte-wise in both directions

The storage grammar the join rests on is four shapes, not one, and a naive node;piece parse is silently wrong on 1,063 of 69,626 fields. Each shape is its own counted class with its own denominator:

shape fields what it means
node;<n> 66,866 (96.0 %) a ^-delimited piece — the only case a naive parse gets right
(empty) 1,013 a computed field: it has no storage, which is a fact and is reported as one
node;E<from>,<to> 764 an $EXTRACT character range, not a piece number
" " (no semicolon) 299 the .001 pseudo-field: the value is the record’s own subscript, so it is comparable against the node KEY and against no piece
node;0 (word-processing) 684 piece 0 names a subtree, not piece zero of a string

And a rendering transform is unverifiable by construction. About 5.6 % of fields carry an output transform, so the external tier renders — pointers as names, dates as human dates, sets as their meanings — and cannot be compared byte-wise against a raw piece. The comparison therefore runs at the internal tier, and the external tier gets its own decode-replay pass rather than being quietly excluded.

Building these instruments found defects every existing gate had passed, which is the argument for having them: a description read that dropped leading empty lines on 920 fields and collapsed 14 all-empty ones (fixed as VSL*1.0*69), and a row whose encoded form exceeded the engine frame being stored as "" and counted as emitted (fixed as VSL*1.0*67 — the file that exposed it now completes 470/470 with six uniform typed oversize stubs, four of which had previously been silent empties).

The instruments are not part of make check — they need live engines and, for the out-of-band leg, a sanctioned exception to the driver-only rule. They live at docs/design/read-fidelity-harness/ with a per-release runbook: run them per release and after any driver or JSON-encoder change.

5.2 census

Section titled “5.2 census”

Synopsis, arguments and flags: v db census in the command reference.

5.3 export

Section titled “5.3 export”

Synopsis, arguments and flags: v db export in the command reference.

Writes the data dictionary as dictionary.jsonl + manifest.json — one record per file, carrying the full field model: storageLocation (the node;piece physical decode map) and inputTransform (both VSL*1.0*65), description, screen and screenCode (VSL*1.0*66), types, pointer edges, DINUM, access codes, record-count claim and sampled size. The first two are empty on a computed field — a fact, not an absence: a computed field has no storage location, and its 0-node tail is the algorithm. The prose keys are always-on: measured growth 1.417× against the ruled 3× ceiling (the S4 measurement). The manifest records which instance answered, at what FileMan version, what was requested, what was requested and not written, and the stream’s sha256. This is the DD-half of the extraction pattern: every data artifact pairs with the dictionary that decodes it. The unit of the export is the table, and a sub-file is a table (VD-D80): every exported file rides with its whole sub-file tree — descent is recursive, applies under --files too, and de-duplicates by file number — so the artifact resolves its own subfileLink references, sub-file records are unmeasured with a non-empty parent (VD-D81), and the manifest counts them in details.subfiles. A named --files set costs one single-file census per named file (for the injected record counts) — never the instance sweep — so export --files 4 is seconds; a file the instance has no dictionary for lands in the manifest’s absent list (a malformed --files refuses BAD_FILES). Omitting --files exports the entire dictionary, which does sweep the instance census — measured 15 m 15 s on vehu for 8,171 tables (2,916 top-level + 5,255 sub-files), 19.61 MiB. Executed: A.3 (#4 + #4.1, 9 records — the two named files plus #4’s sub-file tree — digest and manifest shown; then the whole dictionary).

5.4 refs

Section titled “5.4 refs”

Synopsis, arguments and flags: v db refs in the command reference.

The reference (foreign-key) map around one file. Outbound: every pointer field this file’s dictionary declares, at every sub-file depth, with edge semantics — DINUM identity, required, LAYGO (“may add entries”), variable pointers. Inbound: FileMan’s pointed-to-by catalog. Because that catalog is a claim, --verify audits it against an independent field-level enumeration: every named file is checked for a field that really points here (confirmed / unconfirmed = over-report / unresolvable = a variable pointer declaring no targets). The under-report direction is unreachable per-file without a guess, so it is searched only where --scope names candidates — and the verdict says when it was not searched. --resolve names the far end of each edge for one extra round-trip per file. --depth follows edges transitively but is measurably unaffordable as a closure tool (1,294 dumps from a six-edge file); the instance sweep --all --out writes every edge once, and closures are computed offline (scripts/refs-closure.py; #2 reaches 651 files at depth 10, in 0.07 s). 5.5 indexes

Section titled “5.5 indexes”

Synopsis, arguments and flags: v db indexes in the command reference.

The cross-reference inventory — the measurements that say what may be looked up by key and what may not. Per row: name, field(s), source (which register declared it — dd-ix, index-file, or both), kind (open vocabulary — regular, mumps, trigger, compound, record-level, kwic, soundex…), seek (does a positioned lookup admit it), condition presence, stored (does a subtree by this name exist under the file’s root on this instance — absent is a measurement, not an error), shape (sampled subscript depth and the measured position(s) of the record id — which is not reliably the last subscript), and key — whether the stored key IS the indexed field’s value, measured by sampling --key-sample entries. The key verdict is epistemically careful: identity n=K is unfalsified, never proven, and the byte ceiling beside it is what catches truncation (vehu #44 B stores exactly 30 bytes). The per-license rendering spells out what each row admits: prefix seeks up to the measured ceiling; equality/range sample-supported only; conditional or condition-unproven populations named. --out works on both scopes: on one file it lands the --key-sample measurements as the indexes.jsonl that rows --explain --indexes cites; under --all it lands the instance sweep. --all inventories every top-level file in one engine-side pass (vehu: 9,739 cross-references across 2,879 files in ~2 s; the key column is not measured at that scale and every row says so). Executed: A.5 (#44: 19 cross-references, 6 of them seek-refusing MUMPS-kind; the sweep header with its open-vocabulary tally — kwic 45, soundex 3, unlisted 1).

5.6 estimate

Section titled “5.6 estimate”

5.7 rows

Section titled “5.7 rows”

Synopsis, arguments and flags: v db rows in the command reference.

One bounded page of records walked in IEN order from the data root — the population is the walk, never a stored list, so nothing is missed because an index was stale. Five population shapes, all carrying the same completeness discipline:

  • The file walk (default): row-id order, resumable by token.
  • A sub-file (rows 4.03…): file-wide at any depth — every parent’s instances, each row carrying its full iens; --parent '28,' scopes to one multiple instance (population sub:19.01@28,).
  • A supplied IEN set (--iens '.5,1,999' / --iens-file -): rows return in supplied order with a pos per row; a repeated IEN is served per request (visible as emitted over distinct); every IEN with no record is named in misses, never dropped. One paged conversation instead of a get loop — measured ~10× cheaper (253 ms → ~25 ms per record). This is how a pointer list from another read feeds straight back in.
  • The tree read (--with-multiples): every non-word-processing multiple projected inline under its field number, recursively, each sub-record with its own iens. A record whose subtree exceeds the bytes budget becomes a typed TREESIZE row naming the record, the multiple and the paged alternative — never a silent trim. Without the flag, a * read is flat and declares which multiples it left out.
  • The whole-file artifact (--out DIR): walks to exhaustion, JSONL + manifest with the merged completeness block; --max-pages is a named incompleteness, --pace spaces the walk’s engine visits. Both dials refuse without --out (BAD_OUT_DIAL).

--where filters on stored fields at the internal value (§6.4); rejected candidates stay charged to examined and appear in filtered. --ids attaches the reference map (§5.8). --explain reports what the read would do — population, which predicate each index can position (citing supplied artifacts, verified first), cost class, and the exact command to run — for two dictionary reads and zero data pages. Executed: A.7 (all six faces).

5.8 get

Section titled “5.8 get”

Synopsis, arguments and flags: v db get in the command reference.

One record by IEN, byte-exact — .5 is a real IEN, and 10000000247 and .5 are the same address space. --ref FILE-IEN reads the record a reference names — exactly the ref an --ids map emits, so a pointer’s value is followed without taking it apart (naming both spellings refuses). --with-multiples returns the record as a tree; --ids maps each pointer field to {file, ien, ref}. On the reference map generally (also on rows/find): a variable pointer resolves per record from its stored global root; a root the dictionary does not declare is resolved by asking the engine which file owns the root (resolvedBy:"root", fileOf^VSLDD, memoized per root), and named unresolved — never guessed — when no file claims it. --ids is free at --tier internal; at the default external tier it costs one extra internal projection of the reference fields per page. 5.10 find

Section titled “5.10 find”

Synopsis, arguments and flags: v db find in the command reference.

Lookup over a named cross-reference, in emission (key-collation) order — a declared index walk where seeks position and never degrade into scans. emitted vs distinct stays visible because an index walk never de-duplicates. Key bounds are in stored key space (what the index holds, not what the field renders). A seek admits only a mechanically-maintained cross-reference; the rest refuse U-VSL-ROW-IXTYPE naming their measured kind — and that refusal signposts the other face:

--raw reads a cross-reference’s stored entries instead of seeking it — the only way into MUMPS-type, compound, and definition-less cross-references, which are the majority of the database’s real access paths (354 of #2’s 386). It emits each entry’s whole subscript path; the record-id position is measured from a bounded sample and declared with its per-position evidence (a strict argmax that refuses on a tie — ambiguous is a measurement, not a missing answer), or pinned with --ien-at. --at constrains leading subscripts level by level, in stored key space — measured reality: “this patient” on #100 AR is the composite 100000;DPT(, a record id with its global root appended, not the bare id. A projection under --raw is opt-in; the coverage sentence on every page states what the walk is OF (the cross-reference’s stored entries, not the file’s records — the walk reads subscripts, it never interprets them). A declared cross-reference with no subtree refuses NOSUBTREE (a finding); an --at matching nothing is an empty page — different nothings, different shapes. --raw is not --tier raw (population vs projection). Executed: A.10 (#200 B prefix seek; the #44 AC typed refusal with its signpost; the raw walk of #44 AC with elected id-position and evidence line).

5.19 integrity

Section titled “5.19 integrity”

Synopsis, arguments and flags: v db integrity in the command reference.

The instance-integrity census: is the database self-consistent? The dispatched engine sweeps run in one pass — the header ledger (every file’s 0-node claim against the walked truth, plus hollow records), pointers, types, the index plane, hollow sub-records, the DD-side denominators, keys, and the full-depth sub-file descent. Engine floor VSL*1.0*73, with the key and descent sweeps at *75 (§2.8).

It is a census, never a verdict. Every class reports a count against its own denominator, and an absolute count never sets a failing exit — a stock release build is not self-consistent in any class, so “nonzero” is the normal state of a healthy instance. What a finding means is decided by comparison (§5.20 integrity-compare), not by this verb.

Three properties worth stating because they are unusual:

  • Population admission is declaration-driven in every plane. The two audit-class files that store per-FILE subtrees at the first subscript are excluded from every record walk and counted by name (excluded:audit-class), because a bare walk would read their subtree headers as records. An index subtree is checked only when its declared kind, fields, IEN positions and truncation are fully interpretable; everything else is a named unmeasurable count, and that count is about a quarter of the plane.
  • Direction is a declared property of every fed index row — both or entries — and the leg that did not run emits a named non-fact (index-records-not-run), never a zero.
  • --to is a dev bound, and it is recorded as a NAMED incompleteness: the artifact carries the reason, complete is false, and the run exits 3. It is not the instance audit and the artifact says so about itself.

Whole-instance cost, measured on the reference build: ≈ 8.3 min on vehu (descent 323.9 s · index plane 65.3 s · keys 9.0 s) and ≈ 2.5 min on foia. A bounded smoke run is seconds — --to 2 on vehu wrote 678 rows in 14.5 s. Artifact: integrity.jsonl + manifest.json (contract). Executed: A.19.

5.20 integrity-compare

Section titled “5.20 integrity-compare”

Synopsis, arguments and flags: v db integrity-compare in the command reference.

Offline. Compares one integrity artifact against a named expectation and answers in a pinned vocabulary of exactly four words, one meaning each:

outcome meaning exit
clean row-identical to the named base — the one meaning it has 0
delta any row difference against the named base, per (class, file, sub, value) row, with the expectation’s identity printed beside the verdict 3 — the audit’s only red
attention one-sided excess against the shipped-state ledger 0 — never red
stopped no verdict, because the input was incomplete or bounded 3

attention exists because the first baseline of an instance would otherwise swallow its pre-existing damage forever; excess against the cross-build floor is reported and never treated as a regression. stopped is distinct from clean because a run that ran out of scope is not a run that found nothing — that distinction is the whole reason the vocabulary is four words rather than two.

Both inputs are re-hashed against their manifests before any verdict (COMPARE_CHECKSUM); --assert is the labelled door for a deliberately edited expectation, and it turns the checksum check off and says so in the verdict. A cross-instance comparison refuses WRONG_INSTANCE. A build mismatch between subject and base is stated with its re-baseline sentence, never refused — the reader is told what to do, not stopped.

Red-proof: docs/design/instance-integrity-harness/instance-integrity-compare-redproof.py drives the shipped binary against planted copies of a real committed baseline and requires each outcome word to fire alone (3 plants + a control, both engines). Executed: A.20.

5.21 integrity-report

Section titled “5.21 integrity-report”

Synopsis, arguments and flags: v db integrity-report in the command reference.

Explains one integrity artifact’s pointer findings by TARGET. The census rows say which source files hold dangling pointers; this says what is wrong with the thing they point at, which is usually one fact about one target rather than N facts about N sources.

The mechanism split is the point. A target whose own header is divergent — or which holds no records at all — explains its own inbound dangling mass by construction, and is reported as ONE finding with its sources attached rather than as a defect in each source. Everything else is the worth-eyes class: residual dangling into a healthy target, source list attached.

Each target’s root is resolved to a file against the live engine (one dispatch per distinct root, memoized), so unclaimed and ambiguous roots are carried as named states rather than guessed. The artifact’s checksum is verified, and the live engine must declare the same instance the artifact measured or the report refuses — a join against another station is a different question wearing the same shape.

5.23 bundle

Section titled “5.23 bundle”

The run-set orchestrator (VD-D94/D95/D96). A run set is a committed TOML declaration of the components a bundle is made of — each a verb plus its argv, with a group and a sentence saying why it is in the bundle. sets/dd-bundle.toml is the committed one; its groups are structure, attribution, behavior, interop and ui-join, and the set itself is the denominator — bundle --explain prints the components rather than restating their count here.

Resolution precedes every engine visit. Each component is resolved against this binary’s OWN generated command contract — reflected from the live kong tree, not read from a committed file that could be older than the code running. Refused at resolve time, all problems at once rather than the first: an unknown verb; an unknown flag; a flag belonging to a different verb (the case the ruling was written for — a flat list of every known flag would pass it); a run-owned flag (--out, --engine, --lock-wait, --timeout); a verb whose declared engine class is write; a verb with no --out; a component naming bundle itself; a duplicate component name; a declared exclusion with no reason. The set is parsed strictly: a key this format does not know is named and refused, because a key read past is an operator’s written intent silently dropped.

Dispatch is IN PROCESS, re-entering this domain’s own grammar with the resolved argv. Nothing is shelled out: a subprocess would have to know whether it is the standalone v-db binary or the v umbrella that mounts this domain as v db, and would get it wrong on one of them. Each component’s own JSON envelope rides its own <name>.log; the run’s verdict is the only thing on stdout.

What lands. One directory per component, each carrying the artifact and manifest that verb writes on its own — bundle recomputes none of those numbers, because the artifact is the authority on itself. Beside them:

file what it is
bundle.json the run record: per component its argv, exit, duration, projection tier, both digests, the manifest’s own records/bytes/complete, and its declared instance; plus the set identity, what was not run, what failed, and the reconciliation
set.toml the set that produced the bundle, byte-identical and digested (VD-D94) — a bundle read a year later cannot be checked against a file that stayed behind on the machine that made it

bundle.json’s key names are the retired script’s, deliberately: it is a published machine interface with a live consumer, so the orchestration moved without renaming the artifact underneath it. New facts are added; nothing is renamed.

The reconciliation is VD-D94’s equality, both directions, published on every run whether or not it found anything: missing (a declared component with no complete artifact), unasked (a directory no component asked for — the direction nothing checked, and the one that catches a leftover from an earlier, larger set), and instances (more than one is a bundle assembled from two places). Any finding, or any failed component, exits 3 BUNDLE_INCOMPLETE.

Failure behaviour, today: a failed component is recorded with its typed refusal and the run continues; the bundle is marked incomplete. VD-D121 (per-component certification) changes that to stop-at-the-failing-component, and it lands whole rather than half.

The projection tier is derived, never declared twice. A component’s tier comes from its own argv (--tier <t>), from the engine default when the verb has a tier and the argv names none, and is absent — a named non-fact — when the verb has no projection tier at all. The one constant (the engine’s external default) carries an oracle: a test reds if the shipped --tier help stops saying so.

--explain reaches no engine and writes nothing: it reports every component, its group, its purpose, its verb and its resolved argv, the flags the run would add, and what the set declares it does not export. --explain with --out refuses (BAD_EXPLAIN) — a plan writes nothing.

The run-lock is probed before the first sweep. The set occupies the engine for the sum of its components (the export alone is ~15 min on vehu), so a busy lock refuses now rather than forty minutes in — and rather than as 32 consecutive component failures.

5.24 catalog

Section titled “5.24 catalog”

The catalog artifact (VD-D115 · D116 · D117 · D124 · D126). No engine. catalog build is a derivation over two inputs that certified themselves — a bundle (§5.23) and an integrity capture (§5.19) — and browse/search read only the artifact.

catalog build

Section titled “catalog build”

Inputs are re-verified, never trusted. The build decodes bundle.json through its own face and requires complete, no refused.json, a generatedAgainst pin, and every component the join needs (export, census, indexes, refs, rows-9.4, rows-9.44, rows-9.4014, rows-9.432, rows-1) certified; each component’s stream is re-hashed and line-counted against its manifest; every component and the integrity capture must declare one engine + station; and the bundle’s pin must equal the integrity manifest’s. Each failure is CATALOG_INPUT, before any output.

One entry per declared table. identity (number, name, header name, parent, depth, global root, DINUM, and the #1 description as present/absent/not-applicable — three states, three renderings; the test is whether a #1 row exists, never whether the table is a sub-file, because ^DIC registers some sub-files at top level and #1 describes them — #4.05 on vehu); structure (every ddmodel.Field, cross-references, the indexes rows and the refs edges the table carries or receives — an edge lives on the sub-file that carries the field — each naming its source component); volume (below); condition (the integrity rows naming this table, verbatim, class/sub/ value; instance-level -- rows ride in the manifest); classification (absent, with the reason); attribution (below); provenance (build id, built-at, engine identity, source pin, dictionary fingerprint = the export stream’s digest, input digests) — copied onto every entry.

The volume plane (VD-D115 as amended). A top-level table carries its census row: the walk as count (state: walked, value), the header’s claimed kept beside it so the two may disagree in the open, the sampled size with its derivation labeled derived; a census state other than walked renders the state word and no value. A sub-file carries exactly one of five words: walked-nonzero / emitted-zero (a sub-census row from the descent, VSL*1.0*76’s walked zero included), derived-zero (no row; the parent chain proves emptiness — a census-walked-empty top-level, an emitted zero, or a derived zero, transitively — and the rule names the table that proves it), wp-excluded (a declared exclusion: a line is not a row), or uncovered — no count from any source, value: null, and the reason. Malformed inputs (a parent chain leaving the dictionary, a cycle, a WP sub-file with declared children, a sub-census row for an undeclared table) refuse rather than classify around. The manifest’s tally sums exactly to the declared sub-file count and its headline keeps the two denominators apart.

Attribution (VD-D116). Longest-matching-prefix: the registry is #9.4 (.01 NAME, 1 PREFIX) plus #9.4014 ADDITIONAL PREFIXES minus #9.432 EXCLUDED NAME SPACE; the input is the global root’s namespace (^PS(53.5, → PS; ^%ZIS( → %ZIS); the longest matching prefix wins; a package whose excluded namespace is itself a prefix of the input does not claim it; ties are by distinct package NAME (two #9.4 entries with one name are one claimant) and are published whole with no owner. Every entry carries rule, namespace, confidence (single-valued · tied · unmatched · inherited), owner (single-valued only), via (prefix:DI / additional-prefix:DPT), claimants, and separately packageClaims — the many-valued #9.44 set as data. A sub-file inherits its top-level ancestor’s outcome and names it (inheritedFrom). The manifest tallies single/tied/unmatched over one denominator (top-level tables).

The index (VD-D117). One document per table and per field: id (<file> or <file>/<field>), name and description, with the tokens of each surface. Tokenizer: lowercase; a token is a maximal run of [a-z0-9] with one embedded . kept when digits sit on both sides; a table’s name surface additionally carries its file number. ranking.json version 1: a document scores only if every query term occurs in some surface; score = Σ_terms Σ_surfaces weight × min(tf, 3) with weights table.name 8 · field.name 4 · table.description 1 · field.description 1, plus 4 when the document’s tokenized name equals the tokenized query; order is score ↓, table before field, file number ↑ (numeric), field number ↑. Two fixtures gate conformance: the committed testdata/catalog-fixture/queries.json (hand-derived expectations over the synthetic fixture, consumed by the reader’s tests — a planted weight change must, and does, make them diverge) and the embedded ranking-fixture.json (the producer’s answers to fixed conformance queries over this artifact, replayed by the certifier).

Certification (VD-D126) — internal/catalogcert, independent of the joiner (own decoders, reads only disk). Layers, in order, first red refuses: artifact (every entry carries all seven planes, no stored staleness key, provenance equals the manifest) · components (re-read) · reconcile:components→entries (every dictionary, census, sub-census, integrity, index, ref and #9.44 row lands in the named entry with equal values, or is named in manifest.unaccounted) · reconcile:entries→components (every entry’s parent, description, volume word, condition row, attribution outcome and claim set trace to a component row or a named rule — a sub-file count with no sub-census row behind it is an inherited or invented count and reds) · index (no dangling document; no entry or field absent without a declared reason) · ranking-fixture (replays) · manifest (browse.defaultOrder is attribution-first) · density (per key path over the entries, recorded) · density-drift (against --previous; none is a named non-fact, and a previous that cannot be measured is a red). A refused build writes refused.json and exits 3 CATALOG_REFUSED; readers refuse the same directory.

catalog browse

Section titled “catalog browse”

Reads catalog.jsonl and lists one row per table: file, name, the attribution outcome (owner, or the contested set, or unmatched, or inherited), the volume word with its count when there is one, and the field count. --order defaults to attribution (single-valued owners A→Z, then inherited by the inherited outcome, then tied, then unmatched; file number breaks ties); number and size are explicit alternatives. A manifest whose browse.defaultOrder is anything but attribution-first is refused (BAD_DEFAULT_ORDER). --top bounds the listed rows on both faces; tables always carries the total.

catalog search

Section titled “catalog search”

Reads index.jsonl and ranking.json and ranks under the shipped spec. Every answer carries matches, denominator (tables, fields, and how many of each have a description) and the build block; a zero-hit answer without its denominator or build age is refused (CATALOG_DENOMINATOR); a missing or unreadable spec or index is CATALOG_RANKING. --top bounds the ranked hits on both faces; matches always carries the full count.

Staleness (VD-D123 as amended). Both readers compute staleAtPin at read time from manifest.generatedAgainst against this binary’s enginepin and render it with the build’s age on every answer; nothing is stored into entries.

5.25 selection

Section titled “5.25 selection”

The selection object (VD-D118). No engine for compile and explain; size reaches one, after an offline sizability decision. A run set (§5.23) says which VERBS to invoke; a selection says which TABLES to extract, at any depth, with a projection and a filter per table. Compiling is the seam, and it is the only place the two artifacts meet.

The grammar is the whole of it. [[table]] carries name, group, purpose, file (a file number at any depth), fields (a list, joined with ;), tier, where (a list, one --where each), with_multiples (--with-multiples) and ids (--ids), the two booleans omitted when false. [[passthrough]] carries name, group, purpose, verb and args, unchanged. [[excluded]] is the run set’s own declared-exclusion row, carried through. [catalog] carries build, rule and an optional dir. There is deliberately nowhere to put anything that would need engine behavior the rows verb does not have.

selection compile

Section titled “selection compile”

An unexpressed selector is OMITTED. A table entry with no fields and no tier compiles to rows <file> — never to the value the engine would have defaulted to. A compiler that fabricated one would make the run set say something the selection did not.

Values are argv ELEMENTS, never re-split, so tier = "internal --out /tmp" is one token the verb rejects rather than two the run set never declared.

Two refusals name the query-language creep the ruling forbids. NOT_A_TABLE — a file that is not a file number: a verb invocation is not a selection, and the whole-instance sweeps ride as passthrough entries. PASSTHROUGH_IS_A_SELECTION — a passthrough naming rows: it would parse, resolve and run, and the selection would no longer say which table it reads. The rest are the run set’s own: MISSING_FILE, MISSING_VERB, MISSING_NAME, DUPLICATE_NAME (across both kinds — names are the bundle’s artifact directories), EMPTY_SELECTION.

Every entry is contract-resolved, both kinds alike, by the same exportset.Resolve the bundle runs plus the record-schema registry check — so an unknown verb, an unknown flag, a run-owned flag, a mutating verb or a verb certification cannot grade refuses here. Nothing is written until the compiled set resolves: a refused compile leaves no half-valid run set on disk. This is SELECTION_UNRESOLVED (exit 2), with data.problems naming every problem rather than the first.

Lineage attaches at the compile step (VD-D118 as amended; VD-D122 reads it from here). The compiled set carries [lineage]: compiledBy, selection, selectionSha256, and either a [lineage.catalog] block (build, rule, dir, generatedAgainst, verified) or catalogAbsent stating that this selection was not chosen from a catalog. A --catalog <dir> reads that build’s manifest.json and marks the reference verified; without it the declared build travels as the claim it is, with the reason. A declared build that disagrees with the artifact is CATALOG_MISMATCH — publishing either version would be a lineage that lies. A --catalog pointing at something that is not a catalog build is NOT_A_CATALOG; supplying one when the selection declares no [catalog] is CATALOG_UNDECLARED, because the rule that chose the entries lives in the artifact.

The compiled set is deterministic and diffable. Passthrough entries first, then table selections, each in declaration order; no timestamp, no host path. The same selection compiles to the same bytes every time.

selection explain

Section titled “selection explain”

The same compile, reported and not written: every entry, the verb and argv it becomes, the lineage that would attach, and every problem if there are any. It takes --catalog for the same verification, and lands no file at all — so it is the safe way to read what a selection means before compiling it.

Tests and red-proofs. internal/selection/selection_test.go (the argv mapping, the omitted selector, the explicit *, sub-files at depth, the compiled order, determinism, both creep refusals, the duplicate and empty refusals, strict parsing, and the four lineage states), dbcli/selection_test.go (the committed selection compiling to the committed run set component for component — Proof 1 Leg A’s offline half — the 9 sub-file entries, contract resolution refusing a passthrough’s unknown flag and a mutating verb with nothing written, the injection control, and the three catalog states).

selection size

Section titled “selection size”

Adaptive spread sizing (VD-D119 / VD-D120, S6). internal/sizing is the package; the design and its two measured limits are in its header.

Order of operations is the ruling. (1) Read the committed artifacts — the certified catalog build (--catalog; a refused build is not read) and the integrity capture its manifest names under inputs.integrity, verified by sha256 (SIZING_INPUT on a mismatch: N and the row-id ceiling must describe one instance state); optionally a prior bundle run (--prior, its bundle.json). (2) Decide OFFLINE which components can be sized; if any cannot, refuse UNSIZED (exit 3) naming every one, report the rows the plan already holds, hold no verdict, and touch no engine. (3) Only then open the client and probe. (4) Validate the report against its own law before it renders (SIZING_INVALID is a defect in v-db, never in the selection).

N, per component kind. Table: the catalog entry’s volume.count — walked / walked-nonzero carry the value; emitted-zero / derived-zero size to zero with no visit; wp-excluded refuses WP_UNSIZED with the catalog’s reason plus the demand-trigger sentence; anything else (uncovered) is NO_COUNT; a file absent from the build is NOT_IN_CATALOG. A top-level file additionally needs the header-ledger max (NO_CEILING without it). Passthrough: a --prior pass with the same name, verb and args (run-owned --out/--engine/--lock-wait/--timeout stripped from the recorded argv), certified and complete — else NO_PRIOR_RUN.

The probe. A Prober seam (dataplane.Rows live; a fake in the tests). Spread (top-level): row-ids from the golden-ratio (Kronecker) sequence frac(i·φ + shift) scaled to [1, max], shift a per-file rotation — deterministic, low-discrepancy, order-scattered, and with no period to alias against (the first draft used base-2 van der Corput; over a range divisible by 2^m every point shares a residue class, and a periodic tail was sampled entirely off its period — measured in the suite, replaced before shipping). Each widening targets fresh HITS: 50, 100, 200, 400, 800 rows, asking n/density positions where density is the committed walk/max (measured 2026-08-24 on #757.01, 28 % dense: 50 asked was 14 hits, and 14 rows “converged” 9 % low), capped at 5,000 positions per widening. The list rides --iens, one page per visit; a page the engine cuts short on its byte budget is continued and every round trip is counted. Prefix (a sub-file, or a top-level file whose row ids are not integers — #1’s are file numbers, max=9999999.64): the file-wide walk from the front, --max per the same schedule, continued by token. Both at the component’s own --fields/--tier/--where. Bytes per row are what rows --out writes: the same json.Encoder (which HTML-escapes </>/& — json.Compact does not, a measured 3 % miss) over the row with the ien-list population’s own "pos":k member stripped (a walked row never carries it — measured as a symmetric 180 B on the 21 rows of #18.02). Six exhaustive components then match their S5 artifacts to the byte. A --where component derives N as committed count × probe pass-rate (emitted / (emitted + filtered)) and states the derivation on the row.

Band and stop. mean ± t(n−1)·s/√n over the cumulative sample (s the sample SD, t the two-sided 95 % Student-t quantile — z=1.96 read two hits of #2 over a 1.7 %-dense id space as a ±1.8 % band; t(1)=12.7 is what two rows know); relative half-width against the pinned ±10 %; a one-row sample has an UNDEFINED band, not a zero one. Decide returns converged (spread rows only), visit-budget (5), or exhausted (every row read — then the band is exact: exhaustive read, the strategy exhaustive). A prefix row never converges: its dispersion is the front of the walk’s, not a random sample’s (50 identical-width front rows of #63.04 gave ±0.0 % with the truth outside), so it spends the budget — the wider sample VD-D120 says the strategy earns — and its band’s method carries ; prefix-sampled (the biased case, VD-D120). Size = N × mean, interval N × (mean ∓ half).

Verdict. Only over a fully sized selection under --cap: fits when high ≤ cap, over when low > cap (OVER_CAP), otherwise undecided (CAP_UNDECIDED) — fits is a *bool, absent on the wire whenever no verdict was earned (VD-D85).

Measured limits, stated on the row. The sub-file index walk (VD-D125) is instance-major and key bounds filter within each instance (find 101.01 B --from 3000: 1,122 examined for 8 rows, all from the first two parents with a match), so no single-visit spread over a sub-file’s parent axis exists; the per-parent alternative costs one visit per parent and the parent-side tree read probes the wrong shape. A sub-file is therefore prefix-probed and declared so (PrefixDeclaration). The spread primitive for sub-files is an engine-side export request, recorded in the tracker.

Stop-rule validation (VD-D120 rev 4/5): scripts/sizing-validate.py record compares a sizing report against same-session rows --out sweeps (records, bytes, sha256 per shape) and writes truth.json + validation.json beside a copy of the report; check re-derives the verdict from the committed files. A shape is validated when its truth lies inside its interval AND its N agrees with the sweep’s record count; three shapes are required; a missing truth, an undeclared band or a tampered validation.json reds. make sizing-gate runs the self-test (ten plants) and re-checks every committed baselines/sizing/*/ for consistency with its committed validation.json; no baseline is a red, not a skip, and a committed not-validated verdict is evidence printed loudly on every run, never a permanent red. The verdict is also graded per strategy (byStrategy), because the constants govern the SPREAD probe and a prefix row is the declared biased fallback. The evidence of record: baselines/sizing/vehu-2026-08-24-s6/ (README.md names the three shapes, the verdict, and the same-day corroboration against S5’s 32-component run).

Tests and red-proofs. internal/sizing/sizing_test.go (the spread planner: both halves, deterministic, fresh on widening, exhausting a small range; the band and its label; the stop rule naming its outcome; offline sizability — WP names its reason, NO_COUNT, NOT_IN_CATALOG, NO_PRIOR_RUN incl. the different-args case, the prior-run row; the fake-prober loop — one-visit convergence, widening to band or budget on a heavy-tailed population with fresh points and a bracketing interval, a prefix-declared sub-file, an exhaustive small file and a zero costing no visit, a filtered component’s derived N; the validator’s three plants — a bandless point estimate, an undeclared prefix row, an unnamed stop; the verdict’s four states), dbcli/selection_size_test.go (the real command refusing UNSIZED offline — every component named, the WP reason, no verdict, no engine declaration — the integrity-mismatch refusal, a non-compiling selection).

5.26 packet

Section titled “5.26 packet”

The delivery packet (VD-D122), discharging VD-D72 through it. No engine. It binds five parts that already ship and adds one measurement — the fresh whole-instance audit’s rows, scoped to the tables the extraction actually read. Being offline is load-bearing rather than incidental: the condition is measured by integrity in the extraction session, so assembling the packet cannot contend for the run lock that audit just held, and the ruling’s promise of zero new engine code holds.

Inputs and how each is bound.

input read as bound by
--bundle bundle.json + the set that traveled inside it + per-component manifest.json and certification.json the set re-hashed against bundle.json:set.sha256; each manifest re-hashed against passes[].manifestSha256
--audit integrity.jsonl + manifest.json via internal/baseline the data file re-hashed against the manifest’s sha256
--ledger ledger.jsonl + its sibling manifest via internal/baseline checksum, source count ≥ 2, and every row a nonzero finding row
--sizing the sizing object of a selection size --out report computed and stated; absent is NAMED, never a silence

The certification part carries the LAYERS, not just the word. A component certified with its drift layer skipped (no --base was named on the run) and one certified with drift measured and clean render identically if only the verdict travels. Every layer rides, every skipped is collected into certification.skippedLayers, and a run with no base at all states certification.baseAbsent — drift unmeasured is not drift clean.

The grain table (internal/packet). Every audit class declares how its file field is keyed — file, parent/sub, file/qualifier or instance — because three different two-part spellings share one field and only the class tells them apart. TableOf reads the declaration, never the string shape. The table is graded in both directions against dataplane.RuledClasses, and a class it does not cover refuses PACKET_GRAIN: fail closed, because a slice that drops what it cannot read reports a cleaner instance than the audit measured.

The scoped comparison. Fresh finding rows with nonzero mass are read against the floor, sliced to the same tables by the same grain table. A row identical to a floor row is clean. Anything else is attention, carrying ledgerGrain: covered (the floor has rows at this (class, file) — they are named) or absent (it has none — the absence is stated in words). Measured zeros and context rows are counted, not compared. A floor row in scope the instance no longer carries is belowFloor. attention is never red; the packet exits 0.

The session bracket. Bracket(startedAt, finishedAt, writtenAt, window) refuses an audit before the extraction (PACKET_STALE_AUDIT) and one outside the window (PACKET_SESSION). --session-window defaults to 1h — a pinned default, stated in every packet it governs, sized against the ~8.3 min whole-instance audit measured on vehu. The artifact carries the order word, the measured gap, the applied window and the sentence naming what the bracket does not prove.

Refusals (all check-class, exit 3): PACKET_STOPPED (the extraction did not complete, or the audit is bounded — the packet still reports, with condition outcome stopped), PACKET_STALE_AUDIT, PACKET_SESSION, PACKET_REFERENT (a referent that does not hash or is absent, and a stream digest its three writers spell differently), PACKET_UNDECLARED (a component neither run nor named as not-run), PACKET_WRONG_INSTANCE, PACKET_PIN_MOVED, PACKET_GRAIN. PACKET_INPUT is usage-class.

Tests and red-proofs. internal/packet/packet_test.go (the grain table both directions; TableOf over the three spellings incl. a target root containing /; an undeclared class refusing by name; the slice’s kept/counted/named split; the scoped comparison’s four renderings — at-floor, covered excess, an excess at a grain the floor lacks with the absence named, below-floor; a measured zero counted rather than compared; the four-word vocabulary and the stated unreachability of delta; the bracket’s stale, out-of-window, adjacent and during cases). Three of its tests grade the declaration against oracles it did not compute: the two committed whole-instance captures (every grain declaration holds row by row; slicing to every table loses no row) and baseline.AgainstLedger (the scoped excess set equals the shipped ledger scan’s at full scope). dbcli/packet_test.go drives the real command struct over synthetic artifacts for every refusal above, for the verbatim channel evidence with a source named per field, for sizing carried-or-named, and for the packet holding no verdict of its own.

6.4 Filter operators

Section titled “6.4 Filter operators”

One closed grammar for every --where (rows, find, count, distribution) — no client M is ever executed: = '= > < >= <= contains starts, plus bound / 'bound (node-existence, the only operator admissible on a multiple; a two-token clause taking no value). Constraints: stored fields only (computed refuses), and predicates evaluate the internal value — a pointer filter takes an IEN, a date filter takes internal date form. A clause is ONE shell argument taken byte-for-byte: a comma in a value (--where '.01 = SMITH,JOHN') is data, never a list separator — repeat the flag for AND. Full discussion: user guide §11.7.

Section titled “6.5 Typed error codes”

7. Operational notes

Section titled “7. Operational notes”
  • Know the cost class before running. Single-file verbs are seconds — including export --files / estimate --files with a named set, which cost one single-file census per named file, never the instance sweep. Full-instance sweeps hold the run-lock throughout — measured on vehu: the full census 3 m 12 s (2,919 files, 15.1 M records walked, 2026-08-15), the whole-dictionary export 15 m 15 s (8,171 tables — 2,916 top-level + 5,255 sub-files by descent — 19.61 MiB, 2026-08-16); refs --all is the long one (tens of minutes — live pointer enumeration at every depth); indexes --all is ~2 s (one engine-side pass). --pace exists for background sweeps against an instance others are using; --lock-wait 0 makes a busy engine a fast refusal instead of a queue.
  • rows --explain before an expensive read. It costs two dictionary round-trips, cites only verified artifacts, and prints the command it would run. The licensing rule it applies: a measured-identity index licenses prefix seeks up to the measured byte ceiling; equality/range are sample-supported and may under-return on a truncating index — the P16-equivalence check is the verification.
  • The safe-write protocol (the one A.14/A.15 follow): declare write:<file>=allow on a class=demo instance · dry-run delete first · actuate with --commit --yes · delete fixtures · revoke the declaration. Write examples in this reference used #3.1 TITLE and a ZZVDB-named #19 OPTION fixture; both were deleted and the policy surface verified restored (A.15, final transcript).
  • Artifacts are citable objects. Keep the manifest beside the JSONL; every downstream citation (--census/--indexes/--profile) verifies manifest, verb, sha256, instance and scope before quoting a number.
  • Machine consumption: use -o json (or redirect — auto switches), switch on command and the typed error.code, and prefer --tier internal for anything that must survive an instance change. In JSON mode every envelope rides stdout — ok and error alike, one stream (since clikit v0.11.3, ruled 2026-08-15; a refusal after an engine visit additionally carries data.instance, which site refused). Text mode keeps the human Error: line on stderr. Exactly one ok:false envelope per failing invocation; the process exit code is authoritative regardless.
