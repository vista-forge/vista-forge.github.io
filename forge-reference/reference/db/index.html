v db

Analyze

Section titled “Analyze”

Sizing the database as it is — measured counts and sampled record sizes.

Command What it does
v db estimate Estimate export size for a set of files (record count × sampled record size) and fit it against a cap (exit 3 over cap).

Inspect

Section titled “Inspect”

Dictionary and catalog reads: schema, the walked census, explain.

Command What it does
v db export Write the data dictionary to disk as JSONL plus a manifest, for analysis away from the engine. The manifest records WHICH instance it came from, at what FileMan version, what was requested, and what was requested and not written.
v db census The WALKED catalog of every file (table): honest record (row) counts with the stored header claim beside as an integrity signal, and sampled record sizes.
v db refs The reference map (foreign keys) around one file: what it points at, and what points at it — with –verify auditing FileMan’s pointed-to-by catalog against the fields themselves.
v db indexes Inventory one file’s cross-references (indexes): both registers they are declared in, what each one stores, where the record id sits inside an entry, and whether its key IS the indexed column’s value — the measurements that say what may be looked up by key and what may not.
v db schema Describe one file (table): its fields (columns) and types, pointers (foreign keys) and cross-references (indexes) — the data dictionary, which is this database’s schema catalog.
v db integrity The instance-integrity census: the whole-instance sweeps — header claims vs walked truth, pointer resolution, declared-type grammar, the declaration-driven index audit (register + feed), hollow sub-records, the DD census, key uniqueness, and the full-depth sub-file descent — as counts with denominators per file (class, file, count, content-fold rows), never a pass/fail verdict.
v db integrity-compare Compare an integrity artifact against a named expectation, OFFLINE: a prior committed run of the same instance (any row difference is the red delta outcome) and/or the shipped-state ledger (one-sided excess is the attention outcome, never red). Speaks four pinned outcome words: clean, delta, attention, stopped.
v db integrity-report Explain one integrity artifact’s pointer findings by TARGET (VD-D109): dangling mass joined to each target file’s own header-ledger row — a header-divergent target is ONE finding with its mechanism shown, a healthy target is the class worth eyes, with the source list attached either way — plus the malformed split (type-history vs live-resolving), which has no target to attribute.
v db bundle Run a RUN SET — the committed declaration of the components a bundle is made of — writing each component to its own directory with its own manifest, and embedding the set that produced it. –explain reports what it WOULD export without reaching an engine.
v db selection The SELECTION object: which tables to extract, at any depth, with a projection and filter per table — compiled into the run set ‘v db bundle’ runs. Saved, diffable and re-runnable; not a query language.
v db catalog The VistA data catalog: build it without touching an engine, from a certified bundle plus an integrity capture (one entry per table — structure, volume and condition planes, derived package attribution with its rule, search index embedded), then browse and search the artifact without an engine.
v db packet The DELIVERY PACKET: the per-component manifest, the producer certification, the channel evidence stated verbatim, the selection’s lineage with every declared exclusion, the sized run, and the condition of the data — the same-session integrity audit’s rows scoped to exactly what was extracted, read against the shipped-state floor. Counts over denominators; the packet never scores or judges.

Data

Section titled “Data”

The data plane: bounded, resumable reads with a completeness block on every page.

Command What it does
v db rows One bounded page of a file’s records (rows) walked in row-id order — the population is the walk, never a stored list, so nothing is missed because an index was stale (completeness block on every page).
v db get One record (row) by its IEN (row id), byte-exact — .5 is a real IEN, not a typo.
v db count Honest record (row) count of one file (table) — counted by walking the rows, resumable, with a completeness block. The count the file header stores is a CLAIM; this is a measurement.
v db find Lookup over a named cross-reference (index) — a declared index walk in emission order. Emitted vs distinct stays visible because an index walk never de-duplicates; seeks position, never scans. –raw instead READS a cross-reference’s stored entries, which is the only way to reach the ones a seek refuses (most of them: 354 of #2’s 386 are site-authored).
v db distribution Bounded distinct-value/top-N distribution of ONE field (column), or the depth of a multiple (nested table) — what values are actually in this column, and how many of each.
v db fields-profile How many records hold a stored value in EACH field (column) of a file (table) — the whole dictionary tallied in ONE walk, so a wide sparse file says which of its columns actually carry data here.

Authorize

Section titled “Authorize”

The instance’s declared authorization surface (enforced engine-side at every verb door).

Command What it does
v db policy Show or declare the instance’s authorization surface (class, per-file policy, read enablement) — enforcement is engine-side at every data verb’s door.

Write

Section titled “Write”

Validated, audited mutations behind the engine-side @mutates gate.

Command What it does
v db put Create a record (row), or a sub-record in a multiple (nested table) — external values by default, validated whole-request.
v db edit Write values into an existing record (row) — one invalid value refuses the whole request; ‘@’ clears a field (column), which is distinct from deleting the row.
v db delete Delete a record (row) — DRY-RUN by default (reports what would go); –commit –yes actuates.
v db reindex Rebuild one record’s cross-references (its index entries). ADDS any entry that is missing; it does NOT remove one that is wrong — an index entry for a value the record no longer holds SURVIVES a reindex (measured, both engines). Whole-file reindex is deliberately not a verb.
v db text Write or read ONE word-processing field (a text blob) — replace/append/–clear; –show reads the field back, which the older interface could only write.

Commands

Section titled “Commands”
Command What it does
v db selection compile Compile a selection into the run set ‘v db bundle’ runs: each table entry becomes one ‘rows’ invocation with its projection and filter, each passthrough entry is carried unchanged, and the compiled set records which selection (and which catalog build, under which rule) produced it. Every entry is resolved against the generated command contract; a problem refuses and writes nothing.
v db selection size Size a selection BEFORE it is extracted (VD-D119/VD-D120): each table’s N from the committed catalog build at zero engine cost, its mean row bytes from one spread probe at the component’s own projection, tier and filter, widened until the sample-dispersion band is inside ±10 % or 5 visits are spent — an interval per component and for the whole, never a point; a selection with an unsizable component refuses before any engine visit and never holds a verdict.
v db selection explain Report what a selection WOULD compile to — every entry, its kind, the verb and arguments it becomes, and the lineage the compile step would attach — without writing anything. If the selection has problems, all of them rather than the first.
v db catalog build Build the catalog artifact OFFLINE from a certified bundle and an integrity capture of the same instance: one entry per table with structure, volume and condition planes, the derived package attribution with its rule, and the search index built in — then certify the derivation by both-direction reconciliation against the components (refused is not published).
v db catalog browse List the catalog’s tables from the artifact — attribution-first by default (owner, then the contested set, then unmatched); size is never the default. Every row states its volume as a count or a named non-fact.
v db catalog search Rank tables and fields by name and description over the artifact’s embedded index, under the ranking rule the artifact ships as data. A negative answer carries the corpus denominator and the build age.

Global flags

Section titled “Global flags”

Every command accepts these.

Flag Type Default Env Description
-o, --output text | json | auto auto — Output format: text (TTY-styled), json, or auto.
--no-color bool — NO_COLOR Disable ANSI styling even on a TTY.
-v, --verbose bool — — Verbose diagnostics to stderr.
--version bool — — Print version and build info.

Exit codes

Section titled “Exit codes”
Code Meaning
0 ok
1 runtime error
2 usage error
3 check / gate failed
4 refused / substrate unavailable
