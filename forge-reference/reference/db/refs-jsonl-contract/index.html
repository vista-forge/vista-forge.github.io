The pointer-graph artifact — JSONL input contract

Note

Hand-written, not generated — the words are v-db’s, from docs/guides/refs-jsonl-contract.md. What this site guarantees about them is coverage, not correctness.

v db refs --all --out <dir> writes two files: refs.jsonl (one JSON object per line, one line per edge) and manifest.json (what the pass was and whether it finished).

This is the contract for a downstream consumer, and the sibling of the catalog contract and the index-sweep contract: one manifest, one complete flag to branch on.

What this artifact is: every pointer FileMan’s dictionary declares on ONE VistA instance at ONE moment — from every field, at every depth, including the ones inside multiples — plus FileMan’s own pointed-to-by claims, reconciled against them.

What it is not: a data reading. No record is touched; a variable pointer’s actual target is chosen per record and this artifact says only which targets the dictionary declares.

1. THE GRAPH IS CYCLIC. Self-loops are legal.

Section titled “1. THE GRAPH IS CYCLIC. Self-loops are legal.”

No consumer may assume a DAG. Measured on vehu: 309 self-loops and 138 2-cycles across the whole dictionary. #2 alone has two self-loops (.082 PATIENT MERGED TO, .3601 COLLATERAL SPONSOR'S NAME), and 2-cycles exist (19↔200, 2↔405). Any traversal must carry a visited set; a recursion that assumes acyclicity will not terminate.

The manifest counts both shapes (reconciliation.selfLoops, .twoCycles) so this is a measurement you can check rather than a warning you have to trust.

3. The reconciliation — and when it is absent

Section titled “3. The reconciliation — and when it is absent”

The two sources are two independent readings of the same question, so each audits the other. A complete pass does both, for the whole instance:

  • verified:false on a catalog edge — no field edge backs the claim. It splits three ways, and the split matters: claimantAbsent (the file named is not in this dictionary at all — measured on vehu, 466 of 590, naming packages the instance never installed), unresolvable (the claimant reaches nothing declarable), and plain unconfirmed (the file is here and carries no such pointer — 124 on vehu). Reporting all three as over-reports inflated the catalog’s apparent error rate about fivefold.
  • catalogClaimed:false on a field edge — a real pointer the target’s catalog never lists. The catalog under-reports. This direction is unreachable one file at a time: refs <file> --verify has to be told where to look (--scope), and a sweep simply has every file’s fields in hand.

The flags are ABSENT on a partial pass, and manifest.incomplete says why. A run bounded by --max-files, resumed from --token, or one that met an unreadable dictionary entry cannot settle a claim about what it did not read — so it makes none. catalogClaimed is likewise absent when the target’s own catalog was never read (a pointer to a file the dictionary list does not offer).

4. to is always a string — a deliberate deviation

Section titled “4. to is always a string — a deliberate deviation”

The design sketch had a variable pointer’s to carry an array. It does not here: a key whose type changes between rows forces every consumer to type-switch before it can do anything, and a closure recipe would silently skip or crash on the rows it did not expect. to is a string or absent; targets carries the set.

Section titled “5. Computing a closure — the reason this artifact exists”

6. manifest.json

Section titled “6. manifest.json”

Measured on vehu 2026-08-14: 2,954 files + 5,308 sub-files, 19,187 edges, and a reconciliation of 8,088 confirmed / 124 unconfirmed / 466 claiming a file that is not installed here / 0 unresolvable, with 19 field edges the catalog never lists. So FileMan’s catalog is wrong about 1.4% of its claims in the ordinary sense, and names a missing file in another 5.4%.

Check complete first. details.files + details.subfiles is what the pass read; details.dumps is what it cost. failed names any dictionary entry that would not read — and its presence is why the reconciliation is absent.

7. Cost, and one operational fact

Section titled “7. Cost, and one operational fact”

The pass dumps every dictionary entry once — measured on vehu, 8,270 dumps over 8,262 entries in about seventeen minutes (the eight extra are sub-files numbered below their own parent, which the file list reaches first). It holds the engine’s run-lock for the whole pass (measured: a second command waiting on ydb.docker.vehu timed out while a sweep was running), so run it when the instance is free, and use --max-files + --token to take it in bounded bites if it must share.

8. Stability

Section titled “8. Stability”

The generator is gated: a recorded tape of the dictionary reads is replayed on every make check and the regenerated graph must be byte-identical to the committed one, with writtenAt the only field allowed to move. Red-proven by planting a removed pointer field and a changed catalog claim.
